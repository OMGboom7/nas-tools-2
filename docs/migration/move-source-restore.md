# 失败移动的原源恢复（2026-10-20）

Go／React 新增独立的原源恢复通道，供本地失败移动以及后续远程来源处置复用。只恢复有持久凭证的原文件／完整蓝光目录，并永久停止该任务的未完成项目；不继续整理、不覆盖或删除目标、不清理备份、不改写既有成功历史，不表示远程模式已接通。

## 范围与授权

仅当前管理员、纯 Go 模式、本地 `move` 任务开放，至少一项须有 `moving`／`quarantined` 的原源恢复凭证。无凭证 running、来源／隔离对象不完整或被替换、陌生同名对象均阻止恢复。已提交成功历史但清理尚未完成的项不允许反向恢复，仍走原明确清理流程；已完成且清理回执完整的项目保持原状。

未开始项目只停止，不声称核验过文件；尚未移除原源的 staging／prepared 项须核实原源完整，再停止并保留暂存。当前配置必须仍授权同一来源根和真实身份；不要求目标在线或旧命名设置不变，不从目标复制一个新对象冒充原件。移除来源配置或替换来源根不能靠旧任务继续获得权限。

恢复前须独立确认旧执行器、其他实例以及会写这些源／恢复路径的下载器或外部程序已实际停止，勾选不会代为停止它们。同组手动／旧未知记录／直接同步／下载完成任务共用此流程。

## 接口与页面

`GET /api/v1/organization/jobs/{id}/source-restore` 只读返回任务阶段、逐项条件、`canRestore` 和指纹，不建立文件锁或恢复意图。审核绑定原定义、状态／原因／凭证、当前原源和隔离对象版本；恢复意图建立后也参与新的指纹。完整 SHA 核验会读取原源字节，使用可取消的两小时上限，超时不表示可以重发。

`POST /api/v1/organization/jobs/{id}/restore-source` 要求 `confirm:true`、`confirmRestoreSource:true`、`confirmOldExecutorsStopped:true`、相同 `reviewFingerprint` 和非空、最多 512 字节的 `reason`。不借用源移除／暂存删除同意，也不从客户端接受源、目标或私有路径。持有原任务跨进程锁，下载任务还持原下载批次锁；锁内重新审核，写入各检查点再次核对当前管理员及来源授权。

React 整理任务页提供独立审核、原因、停止写入器和恢复确认，并展示回执。任务／会话变化、刷新及其他任务动作清除旧审核／确认；丢失响应不重发或改用正向移动。续办保持首次操作者与原因，不能覆盖原审计字段。

## 文件与账本

新增 `GO_ORGANIZATION_SOURCE_RESTORE`，私有保存定义摘要、原项目状态／原因／凭证摘要、首次审核、操作者、原因、时间及逐项结果。沿用 1,000 项任务上限，恢复文档最多 8 MiB。新增审核／恢复回执不含私有凭证、恢复目录名或额外节点身份；原任务的公开源文件快照保持原协议。

先在一个事务保存整个任务 `source_restoring` 意图，未完成项变为 `source_restore_pending`，阻止后续执行、发布、成功提交和移动清理。之后逐项恢复／提交；全部正向核验在位且回执完整后，最终事务保存 `source_restored`。事务回读核验，不在数据库写事务中读取影片。

普通文件要求原身份、大小、修改时间和完整 SHA-256，同时固定来源根、父目录、私有隔离目录及原 witness。原名为空时把原 payload 防覆盖改名回去；仅剩完整原节点见证时可防覆盖恢复原文件名。已在位的原节点只核验，不重复交换。新到同名文件／目录／链接一律保留，不能用相同字节接管另一 inode。

蓝光核验完整原目录身份、子目录／叶子清单及每文件原 SHA，整体防覆盖移回，不拼接片段、不从空隔离目录或来源名缺失推定成功。菜单、隐藏文件、证书和空目录保留。所有路径经固定描述符且不跟随链接，回调后、操作前后检查命名空间并同步目录。

目标、暂存、隔离目录、见证和未知对象全部保留，不释放目标／子树预留，也不自动过期清理。含未发布、已停止项目的预留仍在，占用磁盘；目标或未知证据的处置需要独立迁移，不能借原源恢复顺便删除。

## 中断与业务结果

意图事务失败不操作文件；文件恢复后单项或最终回执失败，保留 `source_restoring`。重启和刷新不自动续办，须取得新审核再明确核验原源已在位并补记回执，不再交换。成功请求以首次指纹、同操作者和原因重复提交，只返回原历史回执，不重新保证外部后来修改的现场。

不新增 `TRANSFER_HISTORY`／`SYNC_HISTORY` 或入库、字幕、成功通知事件，不改变既有成功行。最终事务仅将本任务的 pending 未识别关联关闭为 cancelled，旧记录保持原状、不标记整条已识别。下载批次不能据此宣称整理完成、改标签或移除下载任务；原监控允许另行明确忽略已关闭任务的事件，不隐式重启／停用周期。

## 验证与剩余范围

临时真实文件／目录、SQLite、模拟接口覆盖普通文件、仅剩见证、蓝光、晚到同名对象、节点及父目录替换、内部变更、事务／回执失败、重开数据库、取消和并发锁；覆盖离线目标、命名设置变化、既有成功项目、未识别／直接同步和 qBittorrent／Transmission／Aria2 批次不回写。前端覆盖独立同意、跨任务／错误响应和丢失响应不重发。

集中验证通过：后端全量（HTTP 116.527 秒、整理 17.793 秒）、整理竞态 29.474 秒、相关接口竞态 77.766 秒、`go vet ./...`、Linux amd64 无 CGO 静态构建；前端 160 项测试、类型检查及构建。主包约 563.26 kB，既有超过 500 kB 警告仍在。未操作真实 NAS、账户或生产目录；Docker daemon 仍不可用，容器运行和浏览器验收未完成。

下一批远程整理须为 Rclone／MinIO 分别建立目的端发布、完整性核对、失败处置与来源移除协议。旧 Rclone 直接调用 copyto／moveto；官方默认覆盖语义不能作为任意后端具备本地防覆盖原子发布的证据，`--immutable` 也不能直接证明这一点。参见 [Rclone copyto](https://rclone.org/commands/rclone_copyto/) 和 [immutable](https://rclone.org/docs/#immutable)。本接口未启用任何远程模式。

远程、未知／无凭证对象、已发布目标处置及其余保留业务仍待迁移。退出指标仍为 360 个 Python 文件、8 处 Go legacy 调用（含 helper）、74 处 proxy/runtime 引用和 45 处容器 Python 引用；整体仍粗估 50–60%，最终 Go-only 切换及 Python 删除目标不变。
