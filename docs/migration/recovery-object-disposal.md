# 恢复对象的独立永久处置

2026-10-23 后续范围：普通历史、原来源和已发布媒体由独立的 [历史及媒体删除](media-removal.md) 接管；旧目标／不确定占用由 [独立预留释放](reservation-release.md) 接管。本页仍只说明私有恢复单元，不混用这些授权。以下集中验证为本模块原批次证据，不替代后续模块的验证。

这是独立的新审核与处置，不把未知对象冒充旧整理凭证。它接管 Go 本地／Rclone／MinIO 整理及媒体库刮削留下的完整私有恢复单元，包括未入账目录、含未知成员的暂存、原源隔离副本和长期保留的元数据副本。不自动过期、不在启动时执行、不根据名称猜归属。

## 范围和授权

只能在当前配置的来源／媒体库根中只读浏览，显式选择本机、Rclone 或 MinIO。远程选择固定原账户、执行环境及信任绑定，不降级为同名本地目录。只能选择完整的 `.nastool-copy-*`、`.nastool-move-*`、`.nastool-library-*`、`.nastool-sidecar-*`、`.nastool-dispose-*` 单元，或固定远程私有范围中的完整操作目录；不能选择根、普通已发布媒体、整个远程私有容器或其中的成功子集。即使名字看起来是私有副本，与原整理来源／目标、元数据输出或旧转移历史文件重叠的范围也拒绝，不用命名前缀替代实际范围分类。

文件和目录清单、完整 SHA-256、本机链接字面值、根与目录身份、配置、操作者、原因和关联账本都绑定新审核。单单元最多 20,000 个对象，深度最多 64，总载荷沿用整理协议的 1 PiB 上限并在相加前检查，不误用缩略图的 1 TiB 单文件上限，也不允许公开字节数溢出。本机链接只读取并处置链接本身，不跟随到原件；特殊文件、非法／歧义名字和超限清单整批拒绝。远程仍拒绝危险链接清单。完整审核和删除前会重复读取，不能按一次读取估算流量或时长；普通两小时操作预算仍会中止长读取，协议数值边界不代表真实大盘吞吐已经验收。

公开审核提供完整计数和最多 100 项成员样例，不是只选择样例；确认范围始终是整个恢复单元。关联账本扫描目前每类最多 5,000 份 Go 任务定义，单次结果最多 50,000 行／64 MiB；超过任何预算整组拒绝，不省略旧关联后清理。更大存量账本的分页／索引化及真实数据规模仍须后续验收。

本机逐层检查挂载边界。Linux 须能提供正向 `statx` 挂载 ID，不能提供时拒绝这个破坏性流程，不退化成只比较设备号；同设备 bind mount 也不能作为普通恢复子目录进入。Darwin 检查设备边界。此约束不改变其他已实现整理方式，也不证明真实 NAS／跨挂载已验收。

完整读取须先确认。创建和每次执行又分别要求：本轮完整范围、永久删除、可能包含唯一原件的风险、已实际停止旧 Python／其他实例／下载器及全部外部写入器、关闭列出的关联任务；远程另需独占命名空间、非原子删除和重复完整读取费用确认。勾选不会代为停止外部程序，不继承原整理、原源清理或刮削授权。

## 持久流程

1. 只读浏览／审核，不改变旧记录或媒体。
2. 保存独立任务及完整私有清单，此步不删除任何对象，也没有自动 worker。
3. 按稳定任务 ID 新审核剩余内容，明确单次执行。现有入库补充、库刮削、远程命名空间和全部相关整理任务共用既有跨进程锁；忙时拒绝，不把进程死亡视为执行结束。
4. 在同一数据库事务保存首个意图并永久关闭列出的关联任务。旧记录多目标批次必须显示并关闭全部兄弟任务，不能只关闭一个目标。后续待发送刮削／字幕阻止派发；旧成功历史、原来源、已发布目标、未识别行、目标／不确定占用保持，不伪造成功。
5. 本机先将整个所选对象防覆盖捕获到同目录的独立名称，再核验完整内容。捕获不符时不删除，可在尚未删任何成员、原位置仍空且新审核通过时独立归还整个捕获对象；归还不重开旧任务、不覆盖后来到达的对象。
6. 每个叶子先保存独立删除意图，再核验其身份／完整内容并仅删除它。目录仅在空时移除，不递归删除一个新发现的目录，不扩大到源、目标或父目录。已选硬链接的移除可能改变同 inode 的链接数，但不重写其他名字的内容。
7. 完整核验所选范围已不在原位置后保存最终处置回执，不写整理成功历史、不释放旧目标预留。保留的旧预留不是清理失败，也不能靠切换入口解除。

只关闭列出的旧任务。已决库刮削副本的处置按原批次的部分关闭记账，不顺便撤销用户已授权的未来 cron 周期；未来周期重新建立工作清单，不复用旧凭证。若旧输出仍不确定，原有暂停／占用规则照常生效，不借清理放行。

Rclone 只调用单路径 `deletefile`／空目录 `rmdir`。原生 MinIO 的通用客户端继续禁止对象和桶删除；只有本次精确对象的私有请求能力能执行单次条件删除，禁止桶、递归前缀、版本清除及保留策略绕过。条件头是额外约束，不宣称跨服务商的原子比较删除。分版本存储可能保留旧版本或删除标记，不保证物理容量立即回收。

MinIO 沿用既有 SDK 的路径式、DNS 式及区域地址路由，能力校验仍固定当前端点／桶／对象、端口、TLS 方式和 AWS 分区，不因支持 DNS 式而开放任意地址。路径／DNS 请求由隔离 TLS 夹具和映射传输验证，区域路由另有离线约束断言，不宣称真实 DNS、AWS 或 MinIO 服务已经验收。未完成分片上传不是可读对象，本入口不列举或中止未知上传 ID，也不把它们当作已核验／已回收的副本。

网络失败、取消或回执丢失立即停止本轮，不自动重发。后续必须重新读取剩余完整范围并单独确认；已有删除意图对应的确切缺失可只补数据库回执，不再次发送删除。迟到对象、内容变化、账户／配置撤销都阻止旧范围继续；不能把缺失当旧整理归属证明。重复提交同一个已用审核键只返回现有回执。

停止请求不等待长读取或工作锁，阻止后续工作并取消在途读取；已经送到服务端的单次删除可能仍完成，不能声称它已撤回。停止保留全部剩余对象及捕获，不释放旧任务占用。关闭的处置任务可只读查看，即使账户后来不可用；若要在新配置下另行处置遗留捕获，必须作为完整独立范围重新审核，不能重开旧任务。

## 集中验证

实现与整模块用例齐备后集中验证。最终不缓存后端全量通过：32 个含测试包、2,563 个测试／子测试通过事件，HTTP 包 1,424.339 秒；另 5 个包没有测试文件。唯一跳过的是仅供子进程调用的 `TestJobGuardSubprocess`，真实 Rclone CLI 用例没有跳过。相关 HTTP 竞态 118 个测试／子测试通过事件、223.859 秒；整理／远程存储整包竞态分别 134.649／19.826 秒。静态检查、Linux 无 CGO 静态构建、模块缓存校验通过，生产依赖不含测试夹具。前端 211 项测试、类型检查及构建通过；611.57 kB 的现有主包体积警告仍保留，没有调高阈值。

覆盖三种存储、普通与完整目录载荷、未知成员、链接、空目录、源／目标保持、无凭证任务关闭、整个旧记录批次、元数据副本／旧恢复权限、内容／配置变化、回执丢失和重启不重放，以及 React 独立授权与单次请求。集中回归中修正了旧批次父状态／已关闭子任务的关闭兼容性、载荷预算继承、MinIO DNS 式端点约束和已决副本关闭后未来 cron 的保留；上述最终结果均来自相应修正后的源码。1 PiB 边界仅作整数运算与拒绝路径验证，不声称已读写该规模数据。

使用临时本机目录、空账户环境的隔离 Rclone 别名、虚构账户／临时 CA 的内存 S3 夹具；不访问真实云账户或 NAS，不在用户已有容器中执行删除。Docker 由用户自行启动，实际候选镜像、真实服务器、NAS 和浏览器验收仍未完成。

## 不等于整个 Python 退出

这个入口不是旧 `delete_history` 或任意媒体 `delete_files` 的替代声明；旧历史删除涉及原记录、黑名单、媒体文件及业务事件，仍需完整迁移。已发布目标的修复／处置、旧目标占用的独立释放、其他保留业务和最终生产切换继续保留在目标内。独立删除隐藏恢复副本不发送“来源／媒体库媒体已删除”的假事件。
