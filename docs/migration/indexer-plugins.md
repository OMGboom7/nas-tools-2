# Jackett / Prowlarr 插件管理与后台列表读取

2026-10-19，补齐已由 Go 执行搜索的两类索引器插件：原生安装/卸载、配置保存与只写凭据、一次读取、五段 cron 周期、状态和列表页面。React 复用现有插件配置/只读表格组件，不加载 Python 或动态插件脚本。仅这两个插件的旧 form 安装/卸载/配置/状态/页面入口由 Go 接管；包含未迁移插件的旧聚合列表仍可能走旧服务，不能据此宣布所有插件已迁移。

## 配置与执行边界

继续使用 `UserInstalledPlugins` 和 `plugin.Jackett` / `plugin.Prowlarr`，保留未知安装 ID、未知配置字段和卸载后的全部原配置。API Key、管理密码、服务地址和 cron 文本为只写字段；React 留空保留原值，不回显凭据和私有缓存。安装不会伪造“连接成功”，初始未配置是已知未运行，未读取/过期/失败状态明确未知。现代读取与原生旧聚合结果均不返回原密钥、密码和私有缓存。

修改仅限当前管理员、纯 Go 模式；混合运行时不启动原生周期读取，也不把两类插件修改转发给 Python。保存只登记配置及一次读取意图，不在请求中阻塞等待远端。实际原生运行时在后台读取已安装且配置完整的插件列表；首次配置变更后读取一次，默认不擅自启用长期周期。旧 `onlyonce=true` 或界面的“一次读取并启用周期”会同时开启 `refresh_enabled`，由后台原子消费 `onlyonce` 后按周期运行。可单独关闭周期，不影响搜索时已有的实时发现。

使用现有 APScheduler 兼容的 Go 五段 cron：星期一为 0，日与星期为 AND；时区沿用 `TZ`（未设置时为 Asia/Shanghai）。保留旧默认 `0 0 */24 * *` 的实际日字段语义，它并不等于“每隔 24 小时”；界面明确提示，管理员可主动配置 `0 0 * * *` 表达每天午夜。错过周期只合并读取一次，下一次从当前时刻计算，重启使用持久检查点而非重放所有错过记录。

列表读取只调用已迁移的 `externalindexer.Discover`：Jackett 可使用其原管理密码建立会话，密码不进入 URL；Prowlarr 调用索引统计。不会执行资源搜索、下载、订阅、暂停、删种或文件操作。原有搜索仍实时发现索引器，不依赖展示快照，也不把列表连接成功当成检索或下种成功。

## 并发、持久状态与页面

系统设置增加多键事务读写，安装范围、配置和 `GoIndexerPlugin.<ID>` 检查点原子更新。网络前先持久声明；其他进程在一分钟读取租期内不重复发出请求。网络在事务之外进行，配置变更/卸载无需等远端返回，旧声明无法发布；卸载再安装同配置也会换声明，防止 ABA 旧结果写回。中断租期过后允许重试的是幂等列表读取，不是下载任务；请求超时和停止使用上下文取消，生产停止等待真实 worker 退出。

检查点只包含配置摘要、声明、时间和 ID/名称/域名/公开性，不保存密码、API Key、原始响应或错误正文。失败保留同配置旧快照并明确警告，配置变化不显示旧范围快照；超过 30 分钟的成功快照不再对外报告确定运行状态。页面只读，不提供删除索引器或外部管理操作。状态和字段标签本身不能证明真实服务已经验收。

其余插件执行器、全项目旧接口/代理、Python 生产镜像与最终删除旧实现仍待继续。未对真实服务启用插件、未读取真实账户、未部署生产容器。整体迁移暂维持粗估 50–60%。
