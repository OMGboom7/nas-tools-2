# Rclone 旧记录与手动识别（2026-10-21）

在 [手动远程入库](rclone-manual-intake.md) 和 [同步／下载完成](rclone-automatic-intake.md) 基础上，本批接通旧未知／历史来源的原生重新规划、沿用旧方式重新识别、关联记录改名及自定义识别。Go 直接复用同一 Rclone 执行、完整内容凭证和明确恢复链路，不调用 Python、不另建空数据库、不静默将远程目标替换为同名本地路径。

## 原记录不等于任意路径权限

- 未知记录继续绑定精确 ID、原 `PATH`／`DEST`／`MODE`／`STATE`、当前启用来源与目的根、完整来源快照。历史只从原 `SOURCE_PATH`／`SOURCE_FILENAME` 扫描，原历史和已发布媒体保持原状；来源丢失不会改用原目标。
- Rclone 目标只按明确的逻辑根字面匹配。不得使用本机同名目录或其符号链接别名扩展远程权限；本地来源的已配置根别名仍可使用，子路径链接仍拒绝。
- 普通原生规划及旧重新识别沿用记录中的字面方式，不把远程改为本地复制。旧 `MODE` 未指定时，重新识别使用当前默认方式；关联改名／自定义识别可明确选择本次新方式，但不改旧记录的方式或目的。
- 旧接口的空自定义目的按核验媒体类型选择配置媒体库；省略方式时使用当前默认方式。未知 provider 或 MinIO 仍明确拒绝，不降级。
- 所有来源仍须在启用配置内，不能把旧记录、已发布媒体或任意绝对路径当额外目录权限。原目标冲突不覆盖，未完成任务及永久远程预留继续阻止重复接管。

## 只读审核与独立执行

旧 REST 执行入口继续保留：`/api/v1/organization/unknown/redo`、`rename` 和 `renameudf`。对应只读审核为各自路径追加 `/plan`；`rename` 的审核入口是已有能力，另两项本批补齐。

远程执行必须先取得匹配本次来源、原行、规则、目标、账户／执行文件／环境的审核指纹，再独立确认停止外部写入器、独占远程命名空间／接受非原子可见性，以及持续保留完整恢复副本和元数据暂存的费用。移动另需源移除授权；审核、保存、列表、刷新和独立数据库回执都不是新转移授权。

重新识别审核逐条返回可用计划或错误，不返回私有 Rclone Binding、配置文件路径或账户内容；执行前再次重新规划核对。远程或提交了审核指纹的调用须匹配整批审核；所有确认在任何任务预留前检查。原生本地旧客户端仍保留既有直接明确 POST 的行为，不自动获得远程权限。

记录 ID 使用完整十进制字符串，可到有符号 64 位上限；禁止前导零、重复 ID、浮点转换和跨记录替换。逐记录回执区分未开始、已保存但待核对及完整完成，部分成功不是整批完成。丢失响应或不确定文件阶段不自动重发、不重传；管理员须读取原任务并重新独立授权恢复。

## 完成、兼容状态及原源恢复

远程普通文件／附件与蓝光整盘复用私有完整副本、全量 SHA-256、发布意图、最终核验、源隔离／清理、历史和入库事件。蓝光保留完整目录，不将内部片段当独立影片。复制保持原来源；移动使用已有 PT／做种保护及持久清理通道。

未知记录只有全部保存项及移动清理完成、完整原范围仍可核验时才提交兼容状态。远程还须使用原绑定重新完整读取目标内容；不能用本机同名目标、缺失来源或单个成功条目代替。兼容回执丢失时只核对并补数据库回执，不重传、不再写历史；账户或内容不符保持待审核。

关联改名的父目录模板扩展仍须独立确认。扩大或只筛选部分内容时保存 `preserved` 回执，旧未知行不标整条成功；已处理行不重置为 `N`。历史重识别只追加新成功历史，原身份、旧目标及原历史行不被重写。自定义识别不隐式关联任何旧记录。

失败任务继续使用明确发布／移动续办、远程停止留证或离线原源恢复入口。原源恢复不依赖云端在线，不能将它记作整理成功；停止留证不删除云端对象或释放目标预留。完成凭证的独立解除关联也继续保留原行与所有文件，不放行未完成任务。

## React

原生旧未知／历史列表现可定位受支持的远程来源；执行方式仍保持原字面值，账户配置未开放对应执行模式时禁用入口。超出 JavaScript 安全整数的行不通过近似数字选择，可使用完整字符串 ID 的独立表单。

新增“沿用旧方式重新识别”的逐记录只读审核／明确执行／结果与任务入口；关联改名表单增加远程两方式和不关联旧记录的自定义识别。每个入口各自审核、各自确认，账户授权、源移除与父目录扩大不能互相替代。切换范围、会话、重新审核和请求完成／失败都清空远程勾选；失败只刷新账本，不重放请求。

## 集中验证与剩余工作

模块整体实现后集中验证：后端全量通过（HTTP 848.816 秒），相关 HTTP 竞态通过（275.688 秒）；整理／远程存储另以 `-count=1` 不使用缓存通过竞态检查（85.641／15.248 秒）。静态检查及 Linux amd64 静态构建通过。前端 183 项、类型检查和构建通过；主包 583.17 kB（gzip 160.71 kB），原有的超过 500 kB 提示保留，不调高阈值隐藏。

初轮仅一处新测试夹具失败：macOS 临时路径的 `/var` 与规范 `/private/var` 不同，错误地让本地别名测试要求接管第二个非规范历史别名。改为真实的规范历史路径后通过相关竞态；远程仍只按逻辑路径字面匹配，没有放宽实现。

真实 CLI 回归显式设置 `NASTOOL_TEST_RCLONE_BINARY`，使用 Rclone v1.68.2、临时 `[NASTOOL] type=alias`、空子进程环境与模拟元数据服务，不读取工作站账户。未设置变量而跳过用例不算远程验收。覆盖原生未知／历史及旧 redo、rename、renameudf 的复制／移动；普通／蓝光、父目录扩展／部分保留、原历史不改、精确大 ID／已处理行／默认方式、独立确认与 JSON／旧表单、账户／原行变化、不确定阶段拒绝以及目标被改后的兼容回执。

本批最初保留的单一完整目标边界，现已由后续 [旧记录多目标协调](legacy-multi-target.md) 补齐：默认混合媒体按核验类型分库，原子预留所有子任务与唯一旧行关联，完整目标／来源核验后才提交整条兼容回执；整批停止、重新授权、关闭不依赖某个成功子集。后续继续 MinIO 原配置 provider、远程已有库刮削／FFmpeg、未知无凭证对象与保留副本的独立清理、其他保留业务和最终运行时切换。没有删除未知云对象，也没有取消未确认的业务。真实账户／NAS／浏览器及生产容器升级、健康、权限和回滚尚未验收，不能提前删除 Python。

退出指标仍为 360 个 Python 文件、8 处 Go legacy 调用（含 helper）、74 处旧代理／运行时引用、45 处容器 Python 引用。整体仍粗估 50–60%；子模块完成不能折算为全项目完成或通过强制退出门禁。
