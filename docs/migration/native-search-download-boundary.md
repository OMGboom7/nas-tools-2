# 现代搜索与下载请求退出 Python 回退

2026-10-19，本模块收尾 React 正在使用的 `/api/v1/search/resources`、`/api/v1/downloads`、`/api/v1/downloads/resource` 及现代任务控制入口。原生索引器、缓存、下载客户端和回执已经存在；本批删除这些控制器中的四处 `postLegacy` 调用及仅用于转换旧结果的代码，不新增另一套搜索或下载执行器。

## 实际请求行为

- 搜索仍使用当前用户权限、所选内置/外部索引器、真实资源解析和媒体分组，结果只包含 Go 生成的不透明资源 ID。无索引器配置时返回真正的空结果；配置或远端失败明确报错，不以旧服务结果掩盖失败。没有原生配置的运行时返回 503，不再转发查询或账户 token。
- 搜索 JSON 必须是完整的单个对象，拒绝未知字段、尾随 JSON、尾随垃圾和超限正文；错误请求不开始远端搜索。
- 活动任务和历史仍并行由 Go 客户端/原数据库读取。一侧不可用时展示另一侧并明确警告，不伪造完整列表，也不向旧服务请求补全。
- qBittorrent、Transmission、Aria2、115 与 PikPak 使用现有原生客户端；客户端尚不支持的动作依旧明确拒绝，不伪报成功。本批没有改变各协议的控制能力或授权安全约束。
- 原 Python 数字/旧式搜索 ID 不能移植到新内存缓存，也不猜测对应 torrent/hash，现代下种入口返回 409 和“重新搜索”的说明。Go ID 仍受当前用户、有效期和当前缓存约束，失效返回 404，不向 Python 重放。
- 搜索下种补齐 PikPak 入口白名单，使用同一原生磁力提交和持久手动回执。新的搜索 ID 或进程重启不能绕过原 hash 的成功/待核查范围；响应不确定时保持待核查，云端任务 ID 保留大小写。不将缓存过期、响应丢失或换一个搜索 ID 当作重新下种的许可。

## 明确保留的缺口

这里只证明所列现代请求不再有代码层的 Python 回退，不代表全项目请求链、旧外部 form 搜索 API、插件执行、定时任务、容器与生产验收均已完成。`legacyProxy`、其余插件 `postLegacy` 调用和旧生产镜像仍在。未删除原 Python 业务实现、用户配置、下载任务、历史或媒体文件。

PikPak 的实际账户验收、交互验证、云端控制/转移及按 hash 的不确定提交核对仍未完成，见 [原生下载器说明](pikpak-native.md)。搜索相关真实站点/浏览器验收和存量配置完整升级仍须继续；本模块不以 503/409 等防误执行响应作为未迁移业务已经实现的证明。
