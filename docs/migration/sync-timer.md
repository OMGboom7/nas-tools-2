# 定时目录同步

Go 接管 SyncTimer 的安装状态和 `plugin.SyncTimer`。在插件配置中保存原五段 cron 后，到整理页的自动同步区域选择定时触发并审核同步范围。原周期配置单独存在时保持未授权。定时与十秒轮询使用同一个授权和执行锁，重新选择触发方式会替换原授权。

定时扫描包含所选配置中已经存在的文件。每次可审核最多 16 条启用的同步配置，界面会在此上限内预选当前启用项。后端沿用已有原结构同步、识别整理、稳定快照、历史去重和目标保护。移动与远程范围继续要求独立确认。cron 使用服务的 `TZ`，星期一为 0。原 APScheduler 3.10.2 会忽略命名范围末尾的数字步长，Go 保留该行为。数字范围仍按步长执行。 [旧版源码包](https://pypi.org/project/APScheduler/3.10.2/#files)

到期后 Go 在同一数据库事务中领取周期、保存当时的候选并推进下次时间。候选至少间隔 30 秒再核对。新到文件等待下一周期，变动文件等待新的稳定快照。已完成或需审核的任务沿用原文件账本和回执。服务停机错过多个周期时合并为一次扫描。

保存周期、卸载插件或停止监控会撤销相应授权。旧授权中断时保留已产生的文件和回执。定时授权使用独立状态，旧 Go 版本的十秒轮询不会领取它。插件页和整理页最多展示最近 30 条扫描记录，完成后释放该周期的候选快照。扫描记录与每个文件的实际结果分别记录。

集中 Go 竞态回归通过 162 项。最初跳过的 6 项 rclone 子测试使用本机临时别名补跑通过。前端 353 项、生产构建、Go 静态检查和本机及 Linux 无 CGO 构建通过。隔离 Go 进程等待真实 cron，到期后切换到旧 Go 版本，确认期间没有写入。恢复当前版本后，原编号只复制了当时冻结的文件并记一条历史。真实 NAS 和浏览器交互仍待验收。
