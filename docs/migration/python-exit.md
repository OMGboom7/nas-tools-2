# Python 完全退出计划

目标不是只把界面换成 React，也不是让 Go 包一层 Flask，而是让生产系统最终只运行 React 静态资源和 Go 服务。

后续实施先按 [剩余功能迁移/删除决策清单](module-decisions.md) 核对模块用途与用户需要；可选功能未确认不删除，核心闭环继续迁移，旧技术实现待替代验收后删除。

## 完成标准

只有同时满足以下条件，才能宣布 Python 迁移完成：

1. 仓库中不再保留 `.py` 源文件，包括 `app/`、`web/`、`scripts/`、`tests/`、`third_party/` 和根目录启动文件。
2. Go 中不存在 `postLegacy`、`legacyProxy`、`LegacyBackendURL` 或任何 Flask 反向代理。
3. 生产镜像不包含 Python、pip、`requirements.txt`、`run.py` 或 Python s6 服务。
4. 现有 `config.yaml`、`user.db`、`media.db` 和插件数据可以原地升级，不要求用户重新配置。
5. React 当前使用的所有请求均由 Go 原生处理；外部 API、Webhook 和后台任务也不再调用 Python。
6. Go 单元测试、前端构建、生产镜像健康检查和关键用户流程回归全部通过。

可随时运行以下命令查看退出指标：

```bash
make python-exit-status
```

最终 CI 门禁使用：

```bash
./scripts/check-python-exit.sh --enforce
```

## 无 Python 候选运行时

`docker/go-only.Dockerfile` 仅复制 Go 二进制、React 构建产物和内置站点目录，不安装或启动 Python。`NASTOOL_DISABLE_LEGACY=true` 使 Go 对未迁移的 `/api/` 路由返回 `501`，显式旧接口调用也不会访问 Flask；它暴露功能缺口，不是完成迁移的证据。可用 `make go-only-build` 构建候选镜像，并以 `docker/compose.go-only.yml` 启动。现有 `config.yaml` 与数据库需挂载到 `/config`，且须可由容器内 UID 911 读取及写入；首次迁移会创建数据库备份。不要直接用候选镜像替换生产服务，直到完整退出门禁、镜像健康检查和关键流程回归通过。

目前只完成 Compose 配置校验、本地 Go/前端构建及“无旧服务请求”测试；当前环境 Docker daemon 未运行，候选镜像实际构建、启动和健康检查尚未验证。

## 分阶段删除门槛

### 1. 认证、配置与数据库

- Go 原生读取 `config.yaml`，且保存时不丢失未知字段。
- Go 原生兼容 Werkzeug PBKDF2 和 Scrypt 密码。
- Go 原生读取并迁移 `user.db`、`media.db`。
- 登录、令牌校验、退出和权限检查不依赖 Flask。
- 建立数据库迁移版本与备份/恢复策略。

当前进度：Go 已能读取认证配置、校验两类存量密码、读写 `CONFIG_USERS`，并原生签发兼容 JWT。用户查询、列表、新增、删除和权限认证接口均已由 Go 接管；旧 PBKDF2 用户成功登录后会自动升级为 Scrypt。迁移期间 Flask 仅保留一个验证 Go JWT 的兼容分支；所有旧接口替换后删除。

### 2. 配置型业务

识别词配置补充：启用原生配置后，`POST /api/v1/words/list|item/info|item/update|item/delete|item/status|group/delete` 已由 Go 直接操作 `CUSTOM_WORDS` 和 `CUSTOM_WORD_GROUPS`，保留通用组、媒体组、词条字段和显示顺序。编辑沿用原 ID 并保留 NOTE；重复项检查、批量启停和整组删除使用事务。写操作只允许管理员；单条删除按 REST 声明的 `id` 执行，状态接受声明的 `0/1` 及旧页面的 `enable/disable`。`words/group/add` 也已由 Go 直连 TMDB 获取电影/剧集标题、年份及季数后创建，按媒体 ID 和类型事务化拒绝重复项；上游失败、身份不匹配或跳转均不写库。词组查询与季列表复用同一受限详情请求实现。测试覆盖禁止访问 Flask 的接口流程、冲突编辑保留原词条、批量更新与整组删除失败回滚、普通用户写入拒绝、词组创建及重复/跳转处理。名称识别时的词条执行仍待迁移；过渡期间 Python 的识别词缓存尚不能随 Go 写入自动刷新。

- 用户、站点、下载器、通知、过滤规则、词表和同步目录的增删改查由 Go 直接访问数据层。
- 配置更新由 Go 原子写入 YAML，并保留注释或提供一次性规范化迁移说明。
- React 请求不再通过 Go 调用旧配置 API。

当前进度：Go 已提供保留 YAML 注释的原子配置更新、修改前备份、目录列表维护和认证配置热重载；`SYSTEM_DICT` 系统设置以及 `DOWNLOADER` 下载器配置已可直接读写 SQLite。下载器列表、新增、修改、删除、状态切换和默认下载器设置已有原生接口。Go 首次接管已有 `user.db` 前会通过 SQLite 一致性快照生成只读回退副本 `user.db.pre-go.bak`，验证成功后才打开写入连接。qBittorrent、Transmission 与 Aria2 的连接测试及活动任务控制已经迁移；115 网盘的连接测试、活动任务读取和单任务删除也已迁移，PikPak 及其他云下载器任务操作仍待迁移。

RSS 手动下载补充：旧版 `POST /api/v1/rss/item/download` 现由 Go 接管，读取任务及默认下载设置，可选择下载器并传递任务级目录、暂停状态等支持的设置。磁力链接直接提交；HTTP(S) 种子链接按站点地址匹配现有 Cookie 和 User-Agent，拒绝跳转并限制报文为 8 MiB。每条提交成功后才把处理状态和任务下载历史原子写入 `RSS_TORRENTS`、`USERRSS_TASK_HISTORY`；没有原生存储时不会转发 Python。目标下载器不支持的设置会在批量提交前返回 `501`。当前不执行旧版 TMDB 媒体识别，因此不能等同于完整下载链路：没有媒体 ID 的条目不补写 `DOWNLOAD_HISTORY`，自动目录分类、站点特殊下载 API、字幕抓取和通知事件也尚未迁移。批量操作可能已有部分条目提交成功后才遇到后续条目错误，与旧版一样不能跨下载器操作回滚；调用方可查看 RSS 下载历史确认已成功条目。

这些进展不代表站点和过滤领域全部完成：旧版 `/site/*` 的其余接口、插件索引器与实际过滤执行仍待迁移；搜索、RSS 等旧进程仍可能缓存配置，过渡期间不能据此保证 Go 修改后其缓存立即刷新。最终切换必须移除这些旧执行链路，而不是保留代理作为完成状态。

### 4. 后台任务与插件

自定义 RSS 下载型任务执行接管：纯 Go 模式新增管理员 POST /api/v1/rss/run（表单 id），读取实时任务与解析器，支持多源 JSON/XML、参数/代理、include/exclude、自定义词和过滤规则，以及 N 离线识别/Y TMDB 识别和真实媒体库存核验。报文声明的 movie/tv 类型显式约束识别；未知库存不触发下载，自动执行严格过滤不会因未知大小/单集数量/促销而绕过对应约束。资源经受限私有取种与 Go 下载器提交，成功后把 RSS 去重、任务历史、成功计数/时间及电视剧 MEDIAINFOS 放入同一事务；计数改为确认成功而非旧实现的匹配数，响应分别报告 downloaded/skipped/uncertain。单任务同时执行返回 409；数据库哈希资源预留跨任务/重启保留，外部结果不明或提交后本地持久化失败不自动重试。手工 RSS 下载共用预留与历史事务，重复操作不重复提交且保持旧手工操作不增加任务计数的行为；显式 set_unfinish 可按 enclosure 清除已确认记录/预留，不能清除结果不明的预留。Go-only 模拟测试覆盖过滤/重复/重启、未知提交、电影库存、TV 身份保存、库存失败、错误条件、权限/过渡模式拒绝、任务重入和事务故障回滚。按媒体自动选目录、完整下载历史/通知及不明预留的管理员核验恢复界面尚待迁移。过渡模式不启用此执行器，避免与 Python 调度器同时执行；真实站点/下载器及生产镜像未联调，Python 仍不能删除。

自定义 RSS 下载型调度接管：Go 生产入口使用带生命周期的 `NewWithContext`，仅 `NASTOOL_DISABLE_LEGACY=true` 且有原生配置时启动 RSS worker；过渡模式保持不启动，避免双调度。每 5 秒读取当前任务，`STATE=Y/1` 启用，空周期/停用/删除不执行；任务目录、过滤等由执行器再次实时读取。正整数周期单位为分钟，启动或周期变化后从当前时刻计时；五段 cron 支持通配符、列表、数字/命名范围与步长、月名/星期名和月末 `last`。沿用 APScheduler 的日期与星期 AND、星期一=0（不是 Unix cron 的 OR/星期日=0），时区读取 `TZ`，缺省 `Asia/Shanghai`，静态 Go 二进制内置时区数据；无效时区阻止纯 Go worker 启动。cron 严格寻找下一未来触发点，不在启动时补跑，夏令时不存在的墙上时刻跳过，重复时刻只选择 `time.Date` 的一个实例。日期字段的第几个星期等其他 APScheduler 扩展目前明确报不支持，不解释成其他日期。每次错过的周期合并为至多一次运行，不建立故障期间的执行积压；最多 4 个并行定时任务，饱和时跳过当次并记录不含来源/凭据的告警。定时执行与 HTTP 手动执行共用单任务防重入及数据库资源预留，提交不明仍不重试。执行前核对最新启停/类型/周期，服务关闭取消外部请求并等待 worker 退出。模拟时钟/出站请求测试覆盖周期和 cron、日期/星期交集、闰日/月末/时区、停用/删除/周期修改、错过周期合并、真实 Go 下载历史/去重、手动冲突和运行中取消；未验证真实站点或生产容器。自定义 D/R/S 类型 RSS 已接入此调度器，系统订阅刷新/搜索、目录监控与其他后台任务仍需迁移，不满足 Python 删除条件。

已安装识别插件读取接管：旧 `POST /api/v1/plugin/status` 对两个原生插件现由 Go 读取实时安装与配置状态；未安装返回 null，安装但无有效识别配置为 false，不凭安装状态伪造运行状态。旧 `POST /api/v1/plugin/list` 在安装名单为空或仅含两个原生插件时，由 Go 输出旧编辑器的字段、声明配置、版本/前缀/图标和状态，不执行 Python；未知持久化缓存字段不返回。坏配置或损坏名单明确失败。名单含其他尚未迁移的插件时仍使用原过渡处理器，保留其完整列表及原请求体，不隐藏已有插件。测试覆盖空/已安装/活跃/未安装状态、配置热读取、旧编辑器字段、未知缓存不泄露、未登录及混合名单保真。React 全插件市场聚合与其他插件列表/状态仍待接管；不能以只展示两个插件代替最终全域迁移。

旧版识别插件路由接管：`POST /api/v1/plugin/install|uninstall|config` 对两个原生识别插件现直接调用 Go，不再转发 Flask。沿用旧表单及 `code/msg` 响应，重复卸载成功；旧配置端点保存完整 JSON 对象，所以空字符串/省略字段会清除旧值，与 React 的敏感文本合并策略明确区分。允许先保存配置再安装，验证失败不写库。新增旧插件路径的 Go 登录认证；其他插件请求仍进入原过渡处理器，保留原表单字节、内容类型和多值字段，不把解析过的空请求交给 Python。测试覆盖完整替换、空值、坏 JSON/表达式回滚、安装识别生效、重复卸载、未登录以及其他插件原请求保真。旧版插件列表、市场、页面和其他插件业务仍未迁移；这不是移除过渡处理器的最终状态。

识别插件生命周期接管：React 安装/卸载 `CustomReleaseGroups` 与 `Customization` 现由 Go 管理 `UserInstalledPlugins`，不读取 Python 插件目录、不下载 Python 模块、不调用 Flask。它们没有后台工作线程，原生匹配器每次读取安装状态，所以安装/卸载会实际启用/停用其识别效果；卸载保留原配置，重装恢复，重复安装不增加重复项。安装前验证存量配置，坏配置不激活；事务内合并当前安装名单，保留其他插件及顺序，卸载清理目标插件的所有重复项。管理员权限、并发安装不丢项、保存配置不被卸载删除、匹配器真实启停、损坏名单不覆盖均经模拟环境接口测试验证。未安装插件的重复卸载仍按 React 既有接口返回 409。这里只接管两个已原生实现的插件；插件市场列表、旧 `/plugin/install|uninstall` 路由和其他插件生命周期仍需迁移，不能标记整个插件体系完成。

制作组/占位符插件配置接管：已迁移识别逻辑的 `CustomReleaseGroups` 与 `Customization`，其 React `GET/PUT /api/v1/plugins/{id}` 现可由 Go 读取 `UserInstalledPlugins` 和 `plugin.{id}`，直接验证并保存配置，不调用 Flask。读取仍按既有策略隐藏文本配置，只提供字段与已配置标记；保存要求管理员，保留未知持久化字段，空的敏感文本保持原值，显式 `clearConfig` 才清空。写入前以真实 Go 匹配器验证表达式和长度；事务内读取最新配置再合并，失败回滚，避免同一 Go 存储实例并发更新丢失字段。端到端测试确认保存后的识别立即使用新制作组/占位符，无旧进程缓存刷新依赖；覆盖权限、未安装、非法表达式、超限、清空和存量未知字段。插件市场、安装/卸载、旧版配置路由及其他插件配置仍依赖 Python，不能视为插件体系迁移完成。

- 定时任务、目录监控、文件整理、刷流和自动删种迁移到 Go worker。
- 插件协议改为 Go 接口或独立进程协议；不在 Go 进程内嵌 Python。
- 对无法兼容的 Python 插件提供明确迁移说明，不把 Python 解释器保留为隐藏依赖。

### 5. 生产切换与删除

- 删除兜底代理与 Flask 进程，先用无 Python 的候选镜像完成回归。
- 删除 Python 源码、依赖清单、镜像安装步骤和旧服务定义。
- 启用 `check-python-exit.sh --enforce`，防止 Python 代码重新进入生产分支。

自定义 RSS 订阅型执行接管：原生执行器和纯 Go worker 现支持 R 以及旧持久化别名 S，两者均从 RSS 创建媒体订阅，不把 S 当成直接资源搜索/下载任务。复用多源受限抓取、自定义词和名称解析，include/exclude 在识别前执行；当前 RSS 条目不应用任务过滤组，组号与质量/分辨率/制作组配置保存到创建的订阅，沿用旧实现。任务 recognition=N 也不绕过订阅所需的 TMDB 身份核验；不要求 enclosure，不连接下载器。强制 movie/tv 类型保留，TV 有季标记时选该季，没有季标记时复用原生订阅的最新有效季规则。保留 RSS/search 站点列表、选版、下载设置和目录（直接字段优先 NOTE），不套用自动订阅默认值。先核对已完成订阅历史，TMDB 搜索和详情核验成功后，再在同一数据库事务核对共享已处理键、最新任务类型/存在性和识别后的历史，创建 RSS_MOVIES/RSS_TVS、写 RSS_TORRENTS 标记并增加成功计数。已有同 TMDB/季身份或同名称/年份/季的订阅不会被覆盖；该条仅登记处理标记，不增加新建计数。元数据失败、未识别和事务失败不提前标记完成，下一次可以继续处理；事务触发器测试确认标记或计数写入失败时订阅也回滚。响应新增 subscribed，后台日志也区分下载与订阅成功数。预览和处理查询现统一识别 S 别名。模拟测试覆盖电影/指定季/无季、规则与参数保留、历史阻止重建、重启/别名去重、已有配置不覆盖、识别失败、安全错误、跨连接并发、事务回滚和真实 worker 派发；没有真实 TMDB 服务联调。这里只完成从自定义 RSS 创建订阅；订阅加入事件/通知、订阅后台搜索/刷新/后续下载和其他 worker 尚未全部迁移，旧手动 /do 命令仍未全面接管，不能据此删除 Python。

订阅元数据刷新接管：纯 Go 模式新增管理员 `POST /api/v1/subscriptions/refresh`，并在生产 worker 中沿用旧服务每 6 小时的周期，启动不补跑；HTTP 和后台共用防重入，服务退出取消并等待刷新结束。只刷新 STATE=R 的非模糊订阅，既有数字 TMDB ID 查询核验后的详情，其他受支持身份/名称复用原生解析流程；保留任务状态、筛选、站点和下载目录等用户设置。更新标题、年份、图片、简介和 NOTE 元数据时合并 NOTE 的未知字段，旧 DESC 中的 JSON 订阅配置保持原样，其指定总集数仍优先。`name_follow_tmdb_changed=false` 现在实际保留用户标题（修复旧实现 `or True` 导致 false 无效的行为），仍刷新其他信息。TV 总数变化时，有具体缺集记录则保留原有非连续缺集并增加新集、移除超出缩减总数的集；只有计数而无记录时沿用旧连续缺集范围，具体记录和旧缺集计数冲突则明确失败，不伪造进度。总数、缺集数和 RSS_TV_EPISODES 在同一事务写入，失败全部回滚；查询期间的用户编辑、删行、状态/身份/进度变化通过源字段比较拒绝旧结果覆盖。响应和安全日志区分 updated/skipped/failed，不返回上游凭据或原始错误，部分完成/取消不冒充全量成功。模拟出站和时钟测试覆盖电影/TV、用户配置与旧字段保留、非连续缺集增减、固定总数、缺集冲突、回滚、并发编辑、权限、过渡模式拒绝、共享防重入和 worker 取消。真实 TMDB/生产容器未联调；订阅搜索、媒体完成判断及后续自动下载、事件通知、其他后台任务和旧 /do 路由仍未全部接管，Python 退出条件仍不满足。

订阅搜索抓取层准备：原生搜索现拆出私有 fetchResources，按当前全局启用的索引器及可选严格子集抓取内置/Jackett/Prowlarr 资源，不依赖 HTTP 用户令牌、浏览器资源缓存或逐条展示识别，供后续订阅执行器直接复用；私有取种地址仅在后端资源结构中保留。现有交互式搜索复用该层，认证、搜索权限、识别/库存分组及用户隔离缓存仍在原有 HTTP 链路。POST /api/v1/search/resources 新增可选 indexers（原生索引器 ID 数组），空/省略沿用全局启用范围，非空必须全部为启用项；重复项去重，未知/未启用项返回 400，不静默扩大为全部站点。未请求的不可用内置站点不会影响显式有效子集，但默认全局搜索仍真实报告该不可用项；被选择的插件未安装、源不可用及任一源抓取失败仍明确失败，不返回部分列表冒充全部完成。没有原生配置的过渡链路对显式子集返回 501，不丢掉范围后转交全局搜索。测试覆盖范围/去重、全局默认、无效项预检、权限、部分失败、取消、插件缺失、范围隔离和私有链接不向浏览器泄露；既有内置/外部搜索与下载回归保持通过。本批是后台执行前所需的可复用抓取层和范围支持，尚未接入订阅队列、旧站点名称映射、媒体匹配/过滤排序、缺集规划与自动下载事务；不能视为订阅搜索全部完成，Python 尚不能删除。

订阅候选与缺集规划接管：纯 Go 新增管理员只读 POST /api/v1/subscriptions/search/plan（表单 type=MOV/TV、id），直接读取当前订阅、自定义词、过滤和启用索引器，核验目标及搜索资源的 TMDB 身份；同名但不同媒体身份的资源不会成为候选。先核对真实媒体库存，失败不伪装为缺失，也不发起后续索引器搜索；TV 将当前持久化缺集与实际库存缺集取交集，尊重指定季和总集数覆盖。按旧质量/分辨率选择器、制作组与 include/exclude 表达式、原生过滤组筛选；大小/单集数/促销未知时不会绕过相应限制。候选依次按过滤组优先级、缺集覆盖数、已知做种数及稳定标题排序；电影只规划一个候选，TV 去重取种地址并规划非重叠的所需集数，显式 E02E04 链保留非连续集合，不虚构 E03，名称与副标题的自定义词结果用于匹配。指定季的季包按完整季范围规划，但未知真实集数仍不绕过单集大小限制；跨季包当前不进入指定单季计划，后续仍需完整支持。响应只含安全标题/站点/优先级/拟覆盖集数、计划尚未覆盖集数与已核验库存状态，不输出取种链接，不进入浏览器下载缓存，不提交下载、不占资源预留、不改状态/缺集/历史；计划剩余集数不是已经下载后的进度。存量 search_sites 报文损坏会明确失败，不被标准化为空列表后扩大到全站；目前使用原生索引器 ID，旧名称别名映射仍待接入。模糊匹配和洗版明确 501，不能当作最终兼容完成。测试覆盖电影与 TV 的身份核验、规则/质量/制作组、缺集与非连续链、排序/去重、未知促销、私有字段隐藏、坏范围、库存失败及只读无进度消费；真实站点/生产镜像未联调。下一步必须将该计划连接持久下载预留、真实提交、订阅完成/进度事务和生产调度，且补齐洗版、跨季包、旧名称映射、通知与其他后台任务，Python 仍不能删除。

## 数据兼容原则

- 不直接重建用户数据库；先只读验证，再以事务执行版本化迁移。
- 每次写结构前创建可恢复备份，并用真实旧版本数据库夹具测试升级。
- 密码只做兼容校验，不降级为明文；用户成功登录后可升级到新的 Go 哈希参数。
- 配置中的密钥、Cookie、Token 和密码不得写入日志或返回浏览器。
