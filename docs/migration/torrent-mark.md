# 种子标记（TorrentMark）

Go 原生接管原 `plugin.TorrentMark` 配置、安装状态、下载器选择、五段 cron 和一次运行。React 插件页提供范围核对、手动运行、启用、停止与未知结果只读核对；原插件配置、状态和扩展页入口也进入同一实现。混合运行模式只读，执行需独立 Go 模式和当前主管理员。

原 `enable`、`onlyonce`、`cron`、`downloaders` 沿用，下载器编号以精确字符串传递，兼容旧数字编号。保存配置保留未知 JSON 字段和大整数，并撤销原后台授权；安装、卸载及原始配置写入口不会绕过该边界。原配置中已勾选一次运行时，需在 React 核对后启用；启用事务消耗该开关并保存单独时刻。

## 下载器协议与范围

只对所选、已启用的 qBittorrent／Transmission 查询完成任务。列举最多每下载器 1,000 条，列举之后逐条重新读取进度、剩余量、状态、加入时间、标签和 Tracker；不下载或发送种子内容。最多 16 个下载器，每轮最长八分钟。

qBittorrent 使用单标签 addTags／removeTags，添加后重新核对同一任务及分类再删除相反标记。Transmission 使用原 RPC 和 4.1 JSON-RPC 2.0，通过原会话协商选择协议，不在未知写入后改用另一协议重发；完整替换标签前需独立确认外部标签写入器已停止，并与本应用下载整理共用跨进程任务锁。两者保留 PT／BT 之外的标签。协议依据为 [qBittorrent WebUI API](https://github.com/qbittorrent/qBittorrent/wiki/WebUI-API-%28qBittorrent-5.0%29) 和 [Transmission RPC](https://github.com/transmission/transmission/blob/main/docs/rpc-spec.md)。

Transmission 沿用原 Python `get_completed_torrents` 的做种／等待做种范围（状态 5／6），停止的完成任务不自动纳入。qBittorrent 的完成上传与已完成暂停状态仍可核对。新分类优先使用可用的私有属性，兼容单 Tracker 中 passkey／secure／totheglory 的旧线索；线索冲突、地址无效、无有效 Tracker 或证据缺失均跳过。旧 qBittorrent 未提供私有属性且已有 PT 标记、没有明确公开证据时保留原标记，不将证据缺失当 BT。该分类仅用于显示标签，不作为 PT 准入或做种限制的许可。

标签读取上限 64 个；计算后的标签集合也先核验该上限，超过时跳过，不先写再生成无法核对的结果。超过 500 条未知意图时停止新增写入。Tracker 私密查询参数和下载器凭据不进入回执或 React。

## 回执、停止与重启

执行前将编号和记录保存到原数据库的独立 Go 设置键。手动编号有永久受保护的已接收标记，最近 30 轮展示完整计数；原记录退出最近列表后，同一编号返回“已归档”，仍不会重新执行。一次／cron 在发请求前事务领取并前移时刻；重启不重新消费旧时刻。

每次真实网络请求都重新核对当前主管理员、完整插件配置、安装状态、下载器配置和执行状态。每条标签写入前保存精确任务／加入时间、下载器配置摘要和预期标签摘要。应答丢失、超时或核对失败保留原意图，后续轮次跳过它；只读核对仅在原任务、配置及目标标签证据完整匹配时结束意图，不重发标签。停止会阻止后续请求，已发出的请求可能已到达下载器，需通过原记录核对。运行中的 React 操作不阻止另发停止请求。

进程启动检查持有执行锁后，才将失去执行器的旧运行记录标为未知，不接管或重放原写入。停止和保存配置也会关闭本地运行状态。未发送写入的任务可以在新的明确执行中重新审核。
