## 实际覆盖决定进度

整季包即使整季全部缺失，也先读取实际种子文件清单，不能凭 S01 标题和配置总集数登记完整季。声明集数与当前缺集不一致、候选之间重叠时同样进入本流程。明确带集且完整落在目标内的普通资源保持既有整资源提交语义；电影和模糊 RSS 不借本模块改变其业务范围。

完整清单支持 v1 单文件／多文件、BEP 52 v2 文件树及两套非填充文件完全一致的 hybrid。身份 hash 保留原始 info 编码语义，不重新编码后猜 hash。拒绝重复索引／路径、大小写别名、文件作为父目录、越界／负长度／溢出、绝对或穿越路径、控制字符及符号链接条目。最多 10,000 文件、单路径 4,096 字节、全部路径 4 MiB、元信息 8 MiB；超限不截断冒充完整。

固定原媒体和单季后，按文件真实集号选择。E01E03 不扩成连续三集；不可拆多集文件只有全部集均在目标内才选择。最近目录的季号不能继承跨季目录为单季，未知裸文件名不猜集号，样片／预告和非媒体文件不选择。只附带已选媒体的同名字幕／NFO；程序等额外文件保持不下载。最终进度只计实际选择覆盖的集，种子少一集时保留缺集，不把标题补成接收事实。

## 下载器执行与持久意图

- qBittorrent 4／5 使用相应暂停／停止添加参数，保留原目录布局且关闭自动管理，核对原 hash、独有任务标记、明确指定的目录和完整路径／长度。文件请求使用下载器返回的显式 index，不把列表位置当文件编号；通过 torrents/filePrio 取消非目标再选择目标，每个阶段都完整回读。
- 两代 Transmission RPC 使用相应字段／方法名，要求元信息完整、原 hash／目录／标签和 files／fileStats 对应。files-wanted／files-unwanted 永不发送空数组代表“全选／全不选”，只发送精确索引；会话令牌协商不等于失败后重放业务请求。
- 原每任务下载预设和 PT 设置仍先于文件选择／启动。文件钩子只插入原预设的已配置到启动之间，不更改全局设置，不以另一个“暂停预设”掩盖原启动意图，也不放宽做种义务。
- 先在原提交事务保存完整私有定义、唯一 hash 占用和 V4 原来源证明，再发一次暂停添加。原 SQL 类型／辅助缺集账本、过滤／识别／站点／索引器／下载器配置、原洗版质量轮次及选文件范围共同绑定。
- adding → added → unwanting／unwanted → wanting → selected → starting → ready 分别保留已发意图与正向回执。仅 ready 不代表订阅接收已经登记；原来源、共享提交证明和实际选择再次核验后，接收事实／RSS_TORRENTS／业务事件／缺集或洗版进度及私有 committed 才在同一事务提交。静默忽略写入也使事务失败。
- 未知添加、设置、选择或启动不自动重发，不因重启／超时释放预留。不采用原先已存在或缺少独有标记的其他任务；普通添加／启动／旧预设恢复不能绕过待核实文件流程。明确添加前认证／配置拒绝可释放自己的占用，但原拒绝尝试和事实保留。

私有定义保存在 GO_TORRENT_FILE_SELECTIONS，唯一范围在 GO_TORRENT_FILE_SELECTION_SCOPES，人工阶段留痕在 GO_TORRENT_FILE_SELECTION_ACTIONS。公开响应只有稳定编号、原来源／下载器、标题、hash、季集、完整文件和阶段，不包含下载 URL、凭据、原配置、私有 Proof 或 Options。文件长度以十进制字符串传递，前端不以浮点数丢失精度。

## 磁力元信息不再依赖 Python

需核验文件的 v1 btih 磁力通过独立 aria2c 元信息进程解析，不调用旧 Python／libtorrent，也不调用下载器创建整包任务。NASTOOL_ARIA2_BINARY 可指定二进制，否则从 PATH 查找。进程明确禁用配置文件与 RPC，只取并保存元信息，不跟随 torrent 载荷；只使用自行创建的私有临时目录，45 秒超时。磁力从标准输入传入，不进入进程参数或捕获日志，子进程不继承账户环境变量。

返回的固定 hash.torrent 必须是有界普通文件，并再次核验完整清单和 hash；失败明确阻止本次提交，不退回整包下载或 Python。NASTOOL_METADATA_DISABLE_DHT=true 可用于仅允许已知 tracker 的环境与隔离测试，不改变默认线上发现策略。候选 Go-only 镜像增加 Alpine aria2 软件包，仍不安装 Python；没有新增 Go 模块依赖。

本机验证的 aria2 1.37.0 从官方发布源在 /private/tmp/nastool-aria2-cli.wJfvsc 独立构建，没有全局安装。归档 SHA-256 为 60a420ad7085eb616cb6e2bdf0a7206d68ff3d37fb5a956dc44242eb2f79b66b；真实 CLI 测试使用自建 tracker 和 BEP 9 元信息对端，明确拒绝载荷块请求。这只验证本机 CLI，不等于 Alpine 候选镜像或真实站点兼容性验收。

## 管理员恢复与 React

所有接口要求当前管理员及纯 Go 模式，本命名空间未知路径／方法明确拒绝，不回退 Python：

- GET /api/v1/subscription-file-selections?page=1：每页最多 30 条，页码 1–10,000。
- GET /api/v1/subscription-file-selections/{id}：32 位原编号只读查回，来源已收尾仍可使用。
- POST .../{id}/review：只读重核原来源和下载器完整实际状态，生成新指纹与唯一下一阶段，不发变更请求。
- POST .../{id}/recover：新审核、原指纹与总确认；文件／下载设置／启动／登记还分别要求独立确认。只核实已发未知阶段，或单次执行从未发出的下一动作，不重发原添加。

已发取消选择／选择只有全部实际状态匹配才可采用；缺少证据继续拦截，而不是提供“忽略错误继续”。已登记或明确拒绝的记录只有只读结果。React 展示完整原文件、实际目标集、阶段和接收登记状态，分开说明“已选文件”“已启动”“已接收”和“下载／入库完成”。错误／卸载／换会话废弃旧审核，不自动轮询或重试；先保留原编号，查回／恢复同时更新已加载列表，避免旁边还显示旧阶段。
