# Transmission 下载预设：实际应用与恢复

## 已迁移范围与语义

旧 `app/downloader/client/transmission.py::change_torrent` 在添加后实际设置限速、分享率停种上限及**空闲做种停种上限**。最后一项不是 PT 最低做种时长，也不是 qBittorrent 的总做种时间上限。本批迁移此既有能力，不解除原生搜索/订阅对已知正值 PT 最低要求的拒绝，不把有限停种上限当作最低保种保障。

Transmission 的旧 RPC 与 6.x JSON-RPC 分别使用 camelCase 和 snake_case 字段，使用稳定 hash 而非重启后可能变化的数值任务 ID。限速数值沿用下载器 KB/s 字段，不乘 1024；正分享率/空闲分钟启用每任务模式，0 关闭相应每任务种子停种限制，而不是继承全局种子停种上限。全局速度限制仍可被下载器遵守，本模块不改 session 配置。协议依据：[官方 RPC 规格](https://github.com/transmission/transmission/blob/main/docs/rpc-spec.md)、旧 Python 上述实现；不将客户端推测当成可执行范围。

实际搜索、订阅及自定义 RSS 的显式下载预设（包括全零）走同一分阶段执行链；非零的内部选项也走此链。没有显式预设/限制的原始磁力、上传和站点链接仍沿用原直加分支，不暗中重写全局继承行为。Transmission 不支持 qB 分类，非空 category 仍在发送前拒绝，不默默忽略。原标签最多 31 个，给任务身份标记保留一个位置；保留用户标签，不在设置阶段整表替换标签。

## 分阶段真实执行

1. `GO_TRANSMISSION_PROFILES` 及 scope 保存原下载器整行摘要、准确 hash、原目录/标签/暂停选择和全部预设值；不保存凭据或种子/磁力原文。RPC 前提交 add_pending，并生成本次唯一 `NASTOOL-PROFILE-<id>` 标签。
2. 先以暂停状态添加，原标签与专用标记随本次 add 一起发送。返回必须是准确 hash；然后回读任务，核对目录（若原选择明确）、原标签及专用标记、真实停止状态。原来已经存在但没有该标记的对象，不因重复 add 的成功响应被接管。
3. 持久化 configuring 意图及审计后，对准确 hash 发一次设置请求，只含上传/下载限速开关和数值、分享率/空闲模式和值。不发送目录、文件、位置或标签变更。回读必要字段，全部语义匹配且仍停止，才提交 configured。
4. 原选择保持暂停时直接确认 ready；原选择运行时先持久化 starting，发一次启动请求，再回读限速/停种设置、任务身份及非停止状态，才确认 ready。ready 是当时的设置执行回执，不是下载完成/入库或永久设置不变的保证。

需要服务器支持标签及所核对的设置字段。缺字段、null、错误 hash、重复/非法标签、未知模式或无效数值不以默认零代替。接口应答后仍回读，不凭“success”推断设置生效。CSRF 409 按现有客户端协商会话/协议；设置/启动响应丢失后不换接口重发。

## 中断与独立恢复

Go 提交、普通任务控制、恢复及完成整理的暂停/移除按原下载器/hash 共用设置操作锁。设置尚未 ready 时，普通 start 不绕过预设，下载完成移动/自动暂停/移除也不能接管其未完成设置；明确的普通 stop 仍可用。普通控制也由一次读取的原配置直接构造客户端，不在核验后另读新默认/新地址。

只有确定发生在 add 接收前的配置/认证拒绝可记录 rejected 并释放本设置 scope；所有后续错误保持原意图和 scope，不借认证错误释放已经添加的任务。配置变动、标记丢失、重复对象和目录变化保留现场，不能自动重下或启动。设置/启动没有正向结果时保留 configuring/starting；其当前状态仍无法证明原动作成功时，只读审核也拒绝重新发送该动作，不以超时推断未执行。

纯 Go 管理员可用：

- `GET /api/v1/downloads/transmission-profiles?page=1`：只读分页，每页最多 100 条，优先未完成；空读取不建表或请求下载器。
- `POST /{id}/review`：只读核对原任务/配置/全部设置与当前状态，审核指纹绑定操作者、原账本和远程证据；返回下一步 configure/start/acknowledge。
- `POST /{id}/recover`：再次审核同一指纹，主确认与设置写入/启动确认分开；每次只做一个已审核步骤，先存意图与操作者，再发请求并回读。恢复设置不顺带启动；必须新审核及独立启动许可。acknowledge 只凭当前正向证据补齐本设置回执，不重发 RPC。

恢复请求只接受指纹/确认，不接受客户端新 hash、地址、设置或路径。新增用户标签会使旧审核指纹过期，重新审核后保留标签；专用标记/原标签被移除则拒绝。响应丢失后 React 只读刷新，编辑/换会话/卸载失效旧结果。设置回执本身不伪造原订阅/RSS/手动提交成功。

## 源业务回执

手动下种与订阅的持久证明增加可选设置摘要；已有旧证明继续兼容，不把无证明的旧对象推断成已完成。带新摘要的手动/订阅/RSS 成功记账事务均核对相同设置 scope 已 ready 且原配置仍匹配，未应用的设置不能只凭 HasTorrent 变成成功历史/通知。

明确恢复设置后，原手动/订阅来源仍走各自只读核实，实际回读设置后才提交原账本；不重新下种。自定义 RSS 不确定来源的通用正向恢复本来尚未齐全，仍保留其 pending；修好远端设置不等于补写 RSS 成功计数。设置业务事件仍由原来源的成功事务触发，不由设置审核/意图冒充下载成功。
