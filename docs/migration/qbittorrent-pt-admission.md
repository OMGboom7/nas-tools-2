# qBittorrent Go PT 提交与设置回执

本批接通 qBittorrent 带正值最低做种要求资源的搜索、订阅搜索和订阅 RSS 提交。仍需管理员按准确下载器配置启用 PT 接管授权并分别确认范围、旧执行器停止、未知义务持续拦截和禁用自动做种上限；默认关闭，未改动真实下载器或生产服务。没有最低要求元数据的其他来源不因此获得此类能力。

## 协议与证据

支持经过严格版本读取的 qBittorrent 4.6+（4.x）及 5.x 正式三段版本号。4.x 使用暂停添加/恢复，5.x 使用停止添加/启动；未知版本、预发布字符串、字段缺失和重定向等不能授权写入。请求失败不切换另一个写接口重试。

先确认准确 hash 尚无外部既有任务，再保存提交意图、设置意图与来源约束，以唯一身份标签和暂停状态添加。禁用自动管理，避免分类/全局覆盖。添加时就显式禁用分享率、累计做种时间和空闲时间三项上限；随后只对已拥有任务设置并回读三项上限，要求原始与有效值均为无限制。`-2` 继承不是无限制，缺失值不能补零。5.2+ 保留回读的做种上限动作参数，不更改其动作；4.6、5.0/5.1 不要求该版本未提供的字段。原目录、分类、标签、限速不匹配时不自动重写接管。最后按原选择保持暂停或启动，并回读核实。

只有当前源码明确支持的证据与参数才能完成流程；未来版本新增必填参数或变更语义造成错误时保留暂停和待核实回执，不猜测默认值、伪造成功或重试变更接口。排队、磁盘、错误和其他客户端仍可能停止任务，不宣称下载器永远不停。

## 持久化与恢复

`GO_QB_PROFILES`、`GO_QB_PROFILE_SCOPES`、`GO_QB_PROFILE_ACTIONS` 保存冻结设置、准确作用域和操作审计；对外只显示公开范围，不包含下载器口令、站点 Cookie、私有下载地址和原始配置。来源约束在任何 Add 之前已持久保存，设置定义必须引用对应的 `seedingPolicyId`。

qB 设置证明使用 `qb:` 前缀，沿用来源提交记录的 `profileDigest` 字段；原 Transmission 指纹编码不变。统一事务核验器按类型分派，手动、订阅和 RSS 成功历史不能绕过缺失/未就绪设置或缺失的来源约束。通用启动、下载整理及其恢复也检查相同来源；共享的每任务锁覆盖首次接管，避免暂停添加窗口被普通启动请求穿过。

React 下载页提供独立 qB 只读列表和审核。响应丢失不重新添加；只根据原任务当前的正向证据，分别确认“仅设置”“仅启动”或“仅核实已正确状态”。对已经处于不确定配置/启动状态、又缺乏已完成证据的请求，不再次发相同写入。缺少身份标签、错误 hash、设置漂移或配置变化都不能自动接管。恢复设置不会顺便启动，恢复设置回执后仍需另行核实原来源提交记录。

## 尚未完成

HR 标记拒绝下种；没有标记不等于账户义务已解除，未知仍会持续拦截停止、删除和移动。账户级 HR 验证/解除、其他尚未迁移的媒体/订阅/云端业务，以及最终 Python 运行时、镜像和代码清理仍须继续。整体迁移保守粗估仍为 50–60%，不是本模块或模拟测试通过就达到完整退出。

## 集中验证

已通过 Go 全量测试（HTTP 约 76 秒）、相关下载器/持久化/来源事务包及 HTTP 回归的 race 检测（约 92 秒）、`go vet ./...`、CGO 禁用的 Linux amd64 静态构建；前端 123 项测试和 TypeScript/Vite 构建。入口包约 522 kB，仍有非阻塞体积提示，没有提高阈值隐藏。

临时 SQLite 和模拟网络覆盖 4.6、5.0、5.1、5.2 的协议及字段差异、磁力/种子文件、来源在 Add 前持久化、每任务与有效上限双重核实、原暂停选择、来源历史事务、订阅/RSS 真实提交流程、丢失响应后的独立恢复、未知字段/版本、错误身份、外部既有任务、配置变化、旧审核及普通启动不能穿过接管窗口。首轮虽通过，进一步发布源码审计发现 5.0/5.1 不提供 5.2 的动作字段，已修正模拟与实现并整批重跑通过，没有把不存在的版本字段当成已验证证据。

Python 退出门禁仍未通过：360 个源码文件、13 处 Go 旧接口调用、75 处旧代理/运行时引用、45 处容器 Python 引用。不以模拟网络验证冒充真实下载器、浏览器或生产镜像验收。
