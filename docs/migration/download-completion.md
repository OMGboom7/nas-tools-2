# 下载完成 → 整理迁移

最终要求是下载器完成状态、任务文件范围、配置内路径映射、持久整理任务、真实文件/历史回执、下载器结果回写及后台调度形成闭环，不能用“提交成功”或下载中列表替代完成证明，也不能只加只读接口就宣布完成迁移。

## 2026-10-15：完成证据与来源核验模块

Go 的原下载列表有意过滤正在下载的任务，不能复用于完成监控。新增独立 Completion 读取，按精确 hash/GID 查询并归一化有界的任务文件清单，最多 1000 文件；未选中文件不要求本地存在，也不能混入转移范围。任务显示名不参与路径拼接，响应不包含下载源 URI、密码、Cookie、原始错误或访问令牌。

- qBittorrent：核对真实完成状态、明确的进度、剩余量和完成时间，并读取各文件的选择优先级及进度；检查/移动/错误状态不因 100% 变成完成。文件相对真实 save_path，兼容 pausedUP/stoppedUP。
- Transmission：兼容旧 RPC 和新 JSON-RPC 的字段命名；读取实际文件长度、完成字节、wanted、元数据完成度、剩余量、错误及状态，正在检查/下载不判完成。files/fileStats 不一致、缺少必要字段或错误报文不能默认成零并判成功。
- Aria2：读取精确 GID 的实际文件绝对路径、选择标志及逐文件完成字节，不使用下载中列表；完整任务仍须每个已选择文件真实完成，元数据派生任务不作为已完成媒体。没有原生标签能力，only_nastool 额外要求准确 DOWNLOADER + DOWNLOAD_ID 的持久历史行，不能拿空展示对象或其他下载器的记录代替归属。

协议依据：[qBittorrent 官方 API](https://github.com/qbittorrent/qBittorrent/wiki/WebUI-API-%28qBittorrent-4.1%29#get-torrent-contents)、[Transmission 官方 RPC](https://github.com/transmission/transmission/blob/main/docs/rpc-spec.md)、[Aria2 官方 RPC](https://aria2.github.io/manual/en/html/aria2c.html#aria2.tellStatus)。与旧 `app/downloader/downloader.py`、`app/downloader/client/` 的任务筛选和目录替换逐项核对，旧实现仍保留，未部署新执行链路。

`POST /api/v1/organization/downloads/completion/review` 仅纯 Go 管理员可用，输入 `{downloaderId,taskId}`，ID 为精确字符串，支持 int64 大 ID；要求下载器启用完成转移及受支持的本地方式。远程、未迁移下载器或混合运行时明确拒绝，不转回 Flask。未知私有路径/执行字段拒绝。

映射使用目录组件边界和最长配置前缀，不进行全字符串 replace；同等具体程度却目的不同会失败，不依赖配置顺序。MATCH_PATH 要求真实匹配下载目录；未开启也只能落在该下载器明确配置的本地来源根，不能访问下载器返回的任意路径。源根允许配置别名，但根内链接、父级逃逸、隐藏/系统/下载临时路径和目录伪装成文件不接管；当前要求非根目录的规范 POSIX 绝对路径，不把 Windows 路径猜成 Linux 路径。

审核逐条核对任务明确选中的本地普通文件，绑定根身份、文件身份/大小/修改时间，并检查静默区间。内部两次读取下载器证据且复核本地快照及配置未变化，任何变化失效审核。精确 NASTOOL 标签与“已整理”状态参与筛选，子串不算归属；已整理标签只抑制候选，不证明媒体库仍完整。凭据仅进入服务端配置摘要，不返回原值。`eligible` 只代表本次完成证据和本地检查可用，不是执行授权、媒体身份、入库成功或跨观察周期的稳定证明。

React 的“下载完成证据审核”提供只读入口，编辑、换会话和卸载失效旧结果，错误不重试、不改标签、不删种、不建任务或搬文件。普通下载任务列表和人工转移任务均保留原有语义，不借新接口暗中开始后台执行。

## 2026-10-15：持久批次、实际整理与结果回写

管理员通过 `POST /api/v1/organization/downloads/plan` 将完成证据和本地快照接入真实命名/分类与分库规划。仅按任务选中文件逐项核对，不扫描共享下载根；电影/TV/动漫依实际身份选库，附件只继承同目录唯一主媒体。冲突、未识别、蓝光或无唯一附件不降级为普通复制。普通附属文件及明确规则筛除项列为 omitted，单独确认保留范围后才能保存；没有可执行媒体不标成功。

`POST /downloads/batches` 重新规划并核对指纹，明确确认旧执行器实际停止，先持久化任务键唯一预留及完整预期计划，再保存关联任务。批次绑定下载器/任务、配置摘要（不保存凭据原文）、操作者、原选中清单、本地身份及每个实际计划；创建事务、逐步骤核验与历史事务继续核对来源配置和归属。不允许 JSON 注入内部下载来源权限。重复原请求只读取原批次，不重复建任务；同任务的新范围不冒充原范围重用，不会因响应丢失或重启自动补齐部分预留。GET `/downloads/batches?downloaderId=&taskId=` 和 `/{id}` 只读找回账本，含尚未绑定响应的实际关联任务。

`POST /downloads/batches/{id}/execute` 另行确认执行，支持四种本地方式，复用已有持久凭证与非覆盖执行。移动另需源移除授权及实际暂停该种子的确认，服务端核对真实停止状态，不替用户停种。新增用户标签允许保留，但移除原标签、改变文件选择/路径、任务不完整或配置变化会阻止后续步骤。成功只追加来源“下载完成整理”的兼容媒体历史；普通/未选择文件不作为成功媒体，也不被删掉。

批次与单任务操作共用批次锁，和原逐任务文件锁按同一顺序获取；中断后不整体重跑，使用原单任务明确核对/恢复，再经 `reconcile` 验证全部已完成凭证。完成目标检查只用于已提交且无待清理项的回执，在合法暂存清理后核对原目标 inode/父目录/内容摘要；链接另核对原源与链接关系。它不能接管 prepared/running 等不确定状态，也不靠源名不存在推断移动成功。

文件全部正向核验后状态为 files_done，此时不改下载器。`result-review` 只读审核回写；`finalize` 再核对同一结果指纹并独立确认，将完整操作/标签前后值/操作者/审核指纹先保存为 result_pending，再发送一次请求。qBittorrent 原子添加“已整理”而非替换其他标签；Transmission 只有整体替换标签，必须另行确认已停止其他标签写入者，并按最新审核列表替换。移动仅移除种子记录，明确 `deleteFiles=false` / `delete-local-data=false`，不让下载器删除未知或未选择文件；Aria2 只移除完成结果记录。记录移除另需授权。

响应不确定保持 result_pending；`reconcile-result` 仅通过成功读取现状、原清单兼容及全部预期标签/可信任务缺席来完成本地回执，不重发回写、不搬文件。Aria2 通过全部三类队列的有界完整读取核对缺席，错误或达到上限不当成不存在。回写前后仍核对已发布文件；老 completed 只表示当时的审计回执，不保证未来文件一直存在。React 将审核、保存、执行、逐任务恢复、文件核验与结果回写分开呈现，独立确认，编辑/换会话失效预览，错误后只读找回原批次。

回写客户端从同一条已核验的配置快照直接构造，不在检查旧摘要后另读一条可能已经换过地址的配置；即便进行中的配置切换也不会把旧任务操作发送到未经审核的新地址。result_pending 意图和 completed 回执的状态事务内部重新核对下载器配置与必要归属，过期配置不能提交成功回执。

人工操作请求目前有界（执行/结果操作 20 分钟），大量或超大媒体的转移及重复目标摘要核验可能中断，回执仍保留且不自动重放；真实 NAS 的吞吐、长任务调度和浏览器体验尚须验收，不能将临时小文件测试当作性能验收。

## 后续必须完成

1. 接入默认关闭、显式授权的下载完成后台调度，不把独立人工执行入口当作后台闭环已完成。
2. 补齐部分预留的明确恢复/关闭、同 hash 重新添加的新范围审核、任务被外部删除后的受控处置，以及迟到附件、未识别目录、蓝光/远程和其余实际整理缺口；保留不确定对象，不猜测重跑。
3. 接入通知及生产验收，连同其余保留业务一起通过 Python 退出门禁，才删除旧实现。Transmission 必须满足单一标签写入者的真实部署条件，不能将人工确认当作协议具备 CAS。

本模块不是整个下载完成闭环完成，整体进度仍粗估 50–60%；未使用真实 NAS/下载器，也未部署生产或删除 Python。
