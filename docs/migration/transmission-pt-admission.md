# Transmission 带最低要求资源的 Go 提交链路

接续 PT 约束执行保护，本批把带正值最低做种时间/分享率资源接入 Transmission 的持久化提交及设置流程，覆盖原生搜索下种、订阅搜索和订阅 RSS。默认不启用；qBittorrent、Aria2、115 及不携带该元数据的通用 RSS 等其他来源不因此自动开放。未宣称完整 PT 或 Python 退出完成。

## 配置级明确授权

管理员在下载页填写准确下载器 ID，只读审核当前配置，分别确认范围、旧 Go/Python 执行器已停止、未知要求/HR 持续拦截、对这类新任务禁用分享率和空闲自动停种上限。授权指纹绑定当前操作者、下载器整行配置、旧授权快照和本次启用/撤销目标。只有当前启用的 Transmission 配置可被激活；修改服务器、凭据、目录配置甚至名称，旧授权均不能自动适配。

`GO_PT_ADMISSIONS` 保存当前配置授权，`GO_PT_ADMISSION_EVENTS` 保留启用/撤销审计。只读查询与审核不建表、不联系下载器。对外不返回原始配置、私有链接、Cookie 或口令，仅提供授权 ID、操作者、时间与有效状态。撤销仅阻止后续接管，不撤回已记录的约束、不停止任务，也不取消已经接管中的请求。响应不确定只读查询，不自动重放授权。

## 来源与远端设置成为同一提交证明

源资源从服务端搜索缓存/订阅规划/订阅 RSS 解析结果取得，客户端不能上传阈值覆盖。正值要求生成不可变来源摘要，包含当时授权身份，私有下载地址只参与摘要而不进入做种记录。未知阈值不补零。HR 标记直接拒绝下种；详情页没有 HR 标记只是一项页面观察，不等于账户级解除证明，所以本批仍保留未知 HR hold，时间和分享率达标也不自动解除。

Transmission 流程：

1. 核对配置授权和原选择；若原选择的分享率/空闲停种上限不是 0，拒绝而不是静默覆盖。
2. 解析真实 infohash，在与停止/删除/移动共享的跨进程锁内，先确认没有未受本流程所有权标记保护的既有任务；不自动接管外部任务。
3. 保存来源端提交意图和 Transmission 设置意图，把 `seedingPolicyId` 冻结到设置定义与指纹。
4. 在任何 Add 之前追加持久化源约束，核对引用，再以暂停状态和独立身份标签添加准确任务。
5. 回读标签、hash 和目录确认所有权，应用并回读 `seedRatioMode=2`、`seedIdleMode=2`（新协议为 snake_case）及原有上传/下载限速，明确禁用这两个继承的自动停种上限。
6. 按原“保持暂停/启动”选择执行，回读验证，再提交来源历史和进度。

每次设置状态推进，以及手动下载、订阅和 RSS 的成功事务，均验证冻结的源约束引用。不能用缺失/损坏的策略把任务记为成功；重启恢复、通用启动及整理也核对源引用。原始磁力、其他来源或不带源策略的 Add 不能绕过一个已登记 hash 的约束。

Add、Set 或 Start 的响应丢失后不自动重发。已有显式设置回执恢复只对准确的已拥有原任务进行只读审核、独立确认下一步；源提交回执随后另行只读核实/提交本地进度。只读找不到原任务不是重新下种的授权。任何已登记未知约束继续保护停止、删除和移动，不因撤销新接管授权而放行。

## 边界与后续

禁用的是本批拥有的 Transmission 任务的分享率/空闲停种上限，不是承诺下载器永不因错误、磁盘、排队策略、用户或其他客户端停止。未修改真实下载器、NAS 或生产容器。源记录、配置级授权和远端设置均使用 Go，无 Python 回退。

后续仍需迁移 qBittorrent 等对应的持久化提交/设置流程、站点账户级 HR 和义务解除验证，以及其他尚未迁移的订阅/媒体/云端能力；最后验收生产镜像和完整请求链路，再删除旧 Python。整体保守粗估仍为 50–60%，不按新增文件数或单个通过的测试计算。

## 集中验证

已通过 Go 全量测试（HTTP 约 70 秒）、`go vet ./...`、CGO 禁用的 Linux amd64 静态构建；策略、下载器、搜索缓存及持久化包的 race 测试，HTTP PT 接管、旧设置回执、手动提交、订阅/RSS、恢复及下载监控相关 race 回归（约 73 秒）；前端 119 项测试与 TypeScript/Vite 构建。入口包约 517 kB，仍有非阻塞体积提示，没有提高阈值隐藏。

使用临时 SQLite、模拟两种 RPC 协议验证默认关闭、四项独立授权、配置/授权快照 CAS、撤销、隐私、精确身份、Add 前来源持久化、禁用且回读自动停种上限、原暂停选择、已有任务拒绝、标记 HR 拒绝、丢失响应显式恢复、缺失来源禁止回执成功，以及搜索/订阅/订阅 RSS 的实际 Go 提交事务。首轮发现的旧拒绝提示兼容检查和 RSS 测试重建目录配置问题已修复后重跑整批，未放宽原约束。没有操作真实服务或进行生产部署。

Python 退出检查仍是 360 个源码文件、13 处 Go 旧接口调用、75 处旧代理/运行时引用、45 处容器 Python 引用，门禁仍未通过。协议依据为仓库既有 Transmission 双协议设置客户端及 [Transmission 官方 RPC 规范](https://github.com/transmission/transmission/blob/main/docs/rpc-spec.md)，模拟验证不冒充真实站点或生产验收。
