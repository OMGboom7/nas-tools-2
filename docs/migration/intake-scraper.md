# 入库刮削：NFO 与图片

2026-10-19，继续迁移 `app/media/scraper.py` 实际能力。此前 Go 整理只转移媒体和已有附件，不会生成 NFO/海报。本批接入新原生入库任务的自动刮削主链路；不把它宣称为旧脚本全部替代，媒体库遍历/强制覆盖、蓝光与远程、豆瓣/中文演职员及 FFmpeg 回退继续在完整退出目标内。

## 来源、配置与调度

保留 `media.nfo_poster` 和原 SQLite `UserScraperConf` 的独立 NFO/图片开关。新任务的审核定义固定是否启用入库刮削；旧已保存任务不会在升级后被悄悄接管。完整媒体/附件组、历史和移动清理全部完成后，在同一事务为每个媒体文件登记 `GO_SCRAPE_JOBS`。普通文件直同步、未完成组和重复执行不派生新的写入。

React 整理页面可只读核对配置、选项和最多 100 条回执（未完成优先），明确保存选项与启用/停用是两个独立操作，不假装跨 YAML/SQLite 原子提交。选项按最新指纹合并，保留未修改/未知字段；页面、回执和错误不暴露密钥、上游原始正文或绝对媒体路径。管理员、纯 Go 模式才能使用，不回退 Python。

纯 Go 运行时每 15 秒检查队列。原定义、目标 proof、当前 YAML 全快照和刮削选项摘要都须匹配；开始前先持久化 running 意图。读取元数据不扫描/猜测其他文件，使用原已核验 TMDB 类型、ID 与完整季集范围。配置改变或目标被替换则阻止旧任务。running、partial 和 blocked 不自动重跑；崩溃或回执失败不重做入库，也不为补 NFO 重新下种。

## 元数据与图像

实现电影、剧集、季及集 NFO 的独立基础/演职员开关、TMDB/IMDb/TVDB 唯一 ID、评分/年份/简介/导演/演员与原季集字段。XML 通过标准编码器转义，不能把简介中的标记变成额外元素；多集文件保留范围中每个已核验集，而非只写第一集。NFO 与图片遵循原目录布局；不向目标根之外扩展。

沿用 [TMDB 详情与追加响应](https://developer.themoviedb.org/docs/append-to-response)、[季详情](https://developer.themoviedb.org/reference/tv-season-details) 和 [图像路径规范](https://developer.themoviedb.org/docs/image-basics)。图片读取配置中的原 TMDB 图像地址；Fanart 使用原内置项目凭据和 [官方 v3 协议](https://api.fanart.tv/)，电影/剧集分别使用 TMDB/TVDB 身份。海报、背景、logo、disc、clearart、banner、thumb、季海报/横幅/缩略图及集缩略图按各自开关处理，缺失来源明确记录，不制造图片。

图片下载不附带 TMDB 或用户凭据；仅允许配置的 TMDB 原图范围和官方 Fanart 图片域，拒绝重定向/路径穿越/查询凭据。响应有体积上限，JPEG/PNG 内容、扩展名、尺寸与像素总量均须校验；不把 HTML、JSON 或 SVG 当图片写入。

2026-10-20 补充：中文演职员匹配（豆瓣唯一匹配、TMDB 人员别名、纯 Go 繁简转换）及缺图时的只读 FFmpeg 第 181 秒截帧已经接入，见 [刮削增强](scraper-enhancements.md)。歧义或缺失姓名保留原名并标 partial，视频回退失败不改媒体或撤销入库。只有缺少 still 路径才可回退，畸形图片路径及已有图下载失败不会扩大成本地解码。

## 落盘与字幕顺序

落盘使用固定目标根、父目录描述符和媒体凭证，不跟随路径组件中的符号链接。每份新 sidecar 放在当前执行用户所有的 0700 私有目录，空载荷身份、目录身份、摘要和写入意图先保存，再写入并同步内容，最终以防覆盖改名发布。完整媒体摘要核验前后和发布窗口核对 inode、大小、mtime、ctime 与链接数，不能仅恢复修改时间来接管内容已变的媒体；发布前再核对私有载荷节点、单链接及内容摘要。成功 sidecar 使用 0644 供媒体服务读取。

根/父目录/媒体绑定复核失败不当成成功。已有媒体、NFO、图片、外来链接和目录都不覆盖；电影目录已有 `movie.nfo` 时也保留原文件，不生成第二份文件 NFO。“保留”不等于验证旧 NFO 的身份正确。私有目录/空载荷创建与首次入账并非同一原子操作，崩溃可留下未入账对象；不按名称自动接管或批量清除未知暂存。正常返回时只清理本次创建且身份仍匹配的私有载荷和空目录，已发布 sidecar 保留。

刮削与 ChineseSubFinder 共用跨进程入库扩展锁。字幕派发等待 pending 刮削被处理；执行中的刮削持锁，不能让字幕请求先于写入。刮削失败仍保留原字幕事件；进程中断留下 running 回执时不自动恢复写入，后续字幕也不会借此重做媒体入库。
