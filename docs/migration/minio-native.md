## 原账户和路径

仅在 `NASTOOL_DISABLE_LEGACY=true` 下，通过绝对路径 `NASTOOL_MINIO_CONFIG` 显式选择原 `mc` JSON 配置。支持 version 10 的 `aliases.NASTOOL` 及 version 9 的 `hosts.NASTOOL`；只读，不添加、升级或修改原账户。未配置时不扫描宿主机默认账户，不开放 MinIO 执行。

沿用 `url`、`accessKey`、`secretKey`、`sessionToken`、S3v4／S3v2 和原 path／dns／auto 桶寻址。明确存在的 `MC_HOST_NASTOOL` 按原环境别名覆盖账户；它及代理配置参与审核摘要，不混用 Rclone 账户或通用 AWS 自动凭据链。自签证书可通过绝对路径 `NASTOOL_MINIO_CA` 显式提供 PEM 信任，不关闭证书核验。配置、环境覆盖和额外信任内容改变后，旧计划、任务及后台授权均不能继续写入。

部署示例：把原 `mc` 配置和所需 CA 挂载到容器可读位置，设置 `NASTOOL_MINIO_CONFIG=/config/mc/config.json`，可选 `NASTOOL_MINIO_CA=/config/mc/ca.pem`；不要把真实访问密钥写进仓库、React 请求或公开任务回执。此文档没有启用真实账户或部署服务。

原 `miniocopy`／`minio` 及 `Minio复制`／`Minio移动` 保持字面语义。配置根 `/bucket/library` 表示 `NASTOOL` 账户下的桶 `bucket` 和对象前缀 `library`，不是同名本机目录。桶须已存在且允许所需列举／读取／写入；预览不创建桶、目录标记或对象，不借旧记录扩大到任意路径。

## 完整执行与恢复

手动整理、原结构直接同步、识别监控、四种本地下载协议适配（qB、两代 Transmission RPC、Aria2）的完成批次与独立调度、原生未知／历史重新规划、旧 redo／rename／renameudf 及默认混合多库批次接入同一 Go 持久流程。原历史不改，部分范围不将旧未知行标整条成功。

先冻结来源与完整 SHA-256，持久记录私有操作命名空间和意图，上传完整私有副本及清单，再另行发布、全量读取核验最终目标。SDK 请求不自动重试；单次上传支持流式分片，超过单次复制上限的对象使用原生多段复制。ETag 用作来源条件，不能替代 SHA-256 内容凭证。分页清单有完整性、大小、深度、重复／大小写／Unicode 歧义和取消预算；普通目录只列当前层，不把整个已有媒体库递归吸收入库。

普通文件、唯一附件与蓝光整盘共用上述流程。蓝光保留原目录层级、全部载荷和零字节目录标记，包含空目录，不把内部片段当独立影片。入库 NFO／图片、字幕事件复用原远程内容核验及队列顺序，不重跑整理。

复制保留原来源。移动在目标完整核验后才隔离／清理已审核来源，继续遵守停止状态、做种／PT、源移除和结果回写的独立授权。下载器只移除明确授权的任务记录，不删除未知或未选择的本地数据。

发布仍遵守非原子、命名空间独占和外部写入器停止约定，不承诺跨服务商的本地原子防覆盖等价行为。执行前核验不存在，支持条件写入时附带 no-replace 条件；已经存在的最终对象不覆盖。完整私有恢复对象和元数据暂存长期保留，空间与读取流量费用须独立确认。SDK 仅可中止本次已知上传 ID 的未完成分片，不删除对象、桶或发现的未知上传。

响应丢失、半写或未入账状态不自动重发；根据原账本明确核验／继续发布／继续移动。已存在且完整匹配的发布对象不再次复制。仅停止远程工作保留对象和预留，不冒充成功。已隔离的本地原源可在目标及账户离线时通过原凭证恢复，不从远程重复制。多库批次须整批停止／审核／处置，不因单个子任务完成或取消释放兄弟任务的旧行占用。

原永久目标预留继续保留：相同字面目标跨 provider／账户也不会因切换模式而自动解除占用或接管旧对象。这一保守边界及无凭证对象、保留副本的重新接管／清理须由后续独立处置补齐，不把账户切换当作目标已安全释放的证据。

MinIO 的后台授权按 provider 与目标分别绑定；原 Rclone 授权摘要和键保持兼容，但不能获得 MinIO 权限。保存配置或旧 ENABLED 不启动新后台。React 提供两种 MinIO 方式、完整审核与远程独立确认，错误后只刷新，不重放写请求。
