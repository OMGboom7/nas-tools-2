## 安装、配置与提交范围

继续使用 `UserInstalledPlugins` 与 `plugin.ChineseSubFinder`，保留未知安装 ID、配置字段和卸载后的原配置。原地址、API Key 与三组路径映射使用只写字段；留空保留原值，显式清除须成对且满足校验。原生安装/卸载、配置、状态及旧 form 对应入口不回退 Python。修改要求当前管理员和纯 Go 模式；保存本身不向字幕服务发送请求，只影响以后完成入库的事件。无变化的保存不使旧待处理事件失效。

路径映射保持三组依次处理，但只替换一次完整目录前缀，避免 `/media` 误匹配 `/media2` 或替换后缀中的重复目录。支持 POSIX、Windows 盘符和 UNC 表示，拒绝不完整映射、相对路径、控制字符及 `..` 穿越。地址不得带 URL 用户名、查询凭据或 fragment；密钥只放 Bearer 请求头，不返回旧聚合配置、页面、错误正文或日志。

协议依据 [ChineseSubFinder 官方 API 设计](https://github.com/ChineseSubFinder/ChineseSubFinder/blob/docs/DesignFile/ApiKey%E8%AE%BE%E8%AE%A1/ApiKey%E8%AE%BE%E8%AE%A1.md)：单次 POST `/api/v1/add-job`，电影/剧集类型分别为 0/1，优先级 3，媒体服务器 ID 留空。收到合法 `job_id` 只证明任务已被接收，不能报告字幕已下载。客户端也实现规范中的蓝光电影虚拟 `.mp4` 请求形状；当前 Go 普通文件整理不推断蓝光证据，不会借此声称原盘整理已迁移。完整刮削/NFO 仍需后续工作；远端字幕检索依赖实际媒体命名、元数据和服务能力，不以模拟响应保证能找到字幕。

## 持久事件及不确定响应

后续入库刮削主链路已接通，见 [入库 NFO 与图片](intake-scraper.md)。字幕与刮削共用跨进程入库扩展锁，pending 刮削未处理前不提交字幕；执行中的刮削持锁，不能在其写入前抢先派发。刮削的独立失败/中断回执不重做媒体入库，也不自动重发字幕。

同一个 SQLite 事务在整组全部完成、移动清理完成后，为每个媒体文件登记 `GO_SUBTITLE_JOBS`。来源摘要绑定原定义、文件序号与关键目标 proof，不把未完成整理、普通文件直同步或仅收到下载任务当成入库事件。原事件重复经过提交、重启或重新执行不会再次登记。未安装插件时不生成请求；插件配置错误登记 blocked 本地回执，不撤销已完成媒体入库，也不伪造远端调用。

发送前重新核对原任务、当前入库配置、目标根/父目录身份、文件身份/摘要及符号链接绑定；源对象被替换、proof 改动或原范围不再有效则阻止提交。配置、映射与原生安装世代冻结在事件范围，后续配置变化及原生卸载再安装不能把旧事件发给新接收方。开始前持久 sending 意图，实际请求使用此事务核实的同一份配置，不重新读取另一个接收地址。

网络错误、超时、重定向、空响应或没有有效任务编号都保留 uncertain；崩溃遗留的 sending 也不自动重发。修复配置不重放原 blocked/uncertain 任务，更不重复移动、复制或下种；需在原字幕服务人工核查和处理。不取消或回滚已开始的远端请求。字幕服务可以按自身策略重试下载，这与 NAS Tools 重发提交是两件事。

React 复用插件只读页面展示最多 100 条回执，未解决记录优先，隐藏地址、密钥和完整媒体路径。回执页面仅管理员可读；它不是远端任务控制界面，不提供删除媒体、删除字幕或自动重发按钮。

混合运行模式下，已接管的修改入口明确返回 501，不回退旧服务；没有原生入库账本时回执页返回 503，不伪造空队列。安装该插件不影响原生索引器搜索与下种。
