# 入库与单文件字幕触发

2026-10-30。本批接通旧 `SubtitleDownload` 的实际入库生产者，以及原 `/api/v1/media/subtitle/download`、`/do download_subtitle` 的单文件操作。沿用原 ChineseSubFinder 协议与配置，不把收到任务编号说成字幕已经下载；OpenSubtitles 的独立检索／下载实现仍在整体迁移目标内。

## 实际事件与元数据前置条件

完整原生入库的全部媒体、附件与移动清理核实后，在原成功事务中冻结每个媒体的字幕来源，保存原 ChineseSubFinder 待办及独立 Webhook 的 `subtitle.download`。不以规划、部分成功或普通不识别同步冒充入库。原事件包含实际目标文件、源后缀、已证明的蓝光标志和实际可用的媒体字段；不凭空补造 IMDb、英文标题或完整旧 `to_dict`。新事件不补领旧历史。

来源凭据绑定原完整任务定义、该媒体发布凭证、原序号与原 NFO／图片配置。每个文件只等待自己的原元数据账本：pending／running 保持等待，终结后须无 writing／uncertain 等未决输出；来源、配置或凭据损坏不能换一份新证明接管。原未启用元数据或当时尚未配置原生刮削时，明确冻结“无原刮削待办”，不因后来配置而扩大原范围。

原生字幕发送与独立事件发送在各自保存发送意图的实际事务中再次核验该前置条件，避免检查后字段变化仍发出请求。等待项保留 pending，按独立下次检查时间让出队列；元数据正常收尾会唤醒同一原来源，不修改发送意图或重放远端操作。

新原生字幕待办使用可识别的第二代编号，必须存在同事务冻结的原来源。较早原生队列继续沿用自己的原入库与元数据凭证，不因为升级生成新外发、采用另一任务或重新登记成功。新来源表、事件、字幕待办与入库成功同事务；静默忽略、替换原字段或最终提交失败不能留下假成功。

## 单个现有视频

React 整理页提供原配置目录选择、单个相对视频路径、可选识别名称及明确媒体身份纠正。初始无选择或确认，不自动发请求。现代接口和两种旧入口共用同一审核／提交实现；旧直接发送方式须先取得原审核和独立确认，不回退 Python。所有操作要求纯 Go 模式及当前主管理员，未知动作明确拒绝。

只读审核绑定原目录及文件身份、完整内容 SHA-256、原管理员、完整应用配置、原字幕服务配置／原生代次与路径映射。普通文件和已配置目录内的已知链接使用固定目录描述符读取；库外链接、私有暂存／恢复路径、文件夹和蓝光片段不当作普通视频采用。Rclone 与 MinIO 使用所选原账户和命名空间，读取完整对象内容与元数据；需要单独的远程读取确认，不以本机同名文件代替。

保留原三组映射及 ChineseSubFinder 请求形状。审核不向字幕服务提交，保存后有效十分钟；提交须分别确认原身份、原文件／映射、服务可能下载／更新字幕，以及原重复执行器实际停止。明文 HTTP 凭据与远程完整内容读取分别确认。文件、配置或账户变化须重新审核，不自动沿用新设置。

单文件请求有独立原编号和私有定义，不伪造一个已完成入库任务，不新增或改写整理／下载／删除历史。排队事务同时保存独立请求、原服务待办及当时授权的原字幕事件；后启用的外发不补收。后台发送意图之后再次读取完整原内容，按当前原配置核验后仅进行一次原服务提交。应答丢失、sending 中断或本地结果回执丢失均不自动重发。

只读回执区分审核、排队、服务接收、应答不明与阻止，并单独显示服务回执更新时间。原编号可在目录／配置变化或页面刷新后查询，每页三十条。未知修改结果仅查回，不自动再次提交。仅尚未发送的 ChineseSubFinder 项可明确注明原因后停止；独立事件外发和服务已接收的任务保留，不将停止本地请求冒充取消远端任务。

安装列表及未知配置继续保留；原配置的大整数变化按原始文本区分。若另有已启用、尚未迁移的 OpenSubtitles，单文件入口明确返回未迁移，不默默执行部分消费者或删除其配置。未启用的原 OpenSubtitles 不阻止 ChineseSubFinder。

## 接口与验证范围

- `GET /api/v1/organization/subtitles`：只读原字幕服务、目录与存储方式。
- `POST /api/v1/organization/subtitles/review`：原单文件只读审核。
- `POST /api/v1/organization/subtitles/requests`：仅原审核的这次排队。
- `GET /api/v1/organization/subtitles/requests?page=1`、`GET .../requests/{完整编号}`：原回执。
- `POST .../requests/{完整编号}/cancel`：明确原因后仅停止原尚未发送项。
- `POST /api/v1/media/subtitle/download` 与 `POST /do`：保留原参数／命令，使用同一审核与原编号。
