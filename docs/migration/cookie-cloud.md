# CookieCloud 同步

Go 独立运行模式接管 CookieCloud 的插件配置、手动同步、一次运行、周期、停止和记录。React 入口在插件页。原安装名单和 `plugin.CookieCloud` 中的配置继续使用，保存时保留未知字段。标识和解密密码为只写字段。

连接测试向已确认的服务发送原协议 `POST /get/<标识>` 和解密密码。Go 支持配置在子路径下的服务，拒绝跳转。测试只读取模拟或实际配置的 CookieCloud 接收方，且无需访问站点或更新站点表。同步时 Go 用原 Cookie 检查已有站点，保留可用或相同的 Cookie，更新适用记录的 Cookie 字段，也可新增目录中唯一匹配的站点。协议见 [CookieCloud 官方说明](https://github.com/easychen/CookieCloud#api-interface)。

Go 沿用全部、黑名单和白名单三种模式。由于站点表共用一个 Cookie 字段，登录、RSS 或内置索引的接收地址不同会跳过该站点。M-Team 派生 API 站点、目标不明确的 Cookie、非根路径、过期、分区和不符合 HTTPS 范围的 Cookie 也会跳过。

原有周期和一次运行设置需要在页面单独确认后才会执行。变更设置、停止或卸载会撤销旧授权。停止绑定当前记录和授权。执行时使用数据库所在目录的跨进程锁，站点更新、完成记录和可选的成功通知在同一事务提交。中断中的记录可查，服务重启不会重做已领取的一次运行。旧 Python 进程内存中的历史没有可导入的记录。

集中验收通过 208 项相关 Go 竞态测试，另有 3 项既有环境相关测试跳过。前端 353 项测试和生产构建通过，本机与 Linux 的无 CGO 服务构建及 Go 静态检查通过。浏览器用本机模拟服务验证编辑设置、连接测试、更新和新增站点、一次运行、撤销授权与重启回查。真实服务、实际站点、生产镜像和通知送达仍待验收。
