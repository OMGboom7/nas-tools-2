发布后再次核对目标身份、完整内容摘要和当前目录绑定，媒体成功状态与 Python 兼容的 `TRANSFER_HISTORY` 在同一数据库事务提交；附件不重复生成媒体历史。移动还必须有已保存且核验的源隔离凭证，不能只凭目标存在或源名空缺提交成功。历史字段保留实际“复制/硬链接/软链接/移动”模式、“手动整理”、核验的媒体类型、标题、年份、分类、季集及源/目标完整位置。事务失败时保留对象和发布凭证，不假装转移失败后重新执行。不清理源目录或任意未知文件。现有本地库存查询能够统计普通文件硬链接和有效媒体文件软链接，软链接失效时明确失败；并未开放链接目录遍历。

| 单项状态 | 含义与允许动作 |
| --- | --- |
| `planned` | 尚未执行。整个任务均为此状态时可明确取消，保留任务记录并释放目标预留 |
| `running` | 已开始，可能仍执行或已中断。不能凭时间判断停止，不能自动重跑/取消释放 |
| `staging` | 原源完整摘要和私有对象/见证已在内容写入前保存；对象可能为空、半写或内容完整但尚未提交准备回执。不能发布、认作成功、接续复制或自动重跑；符合核验条件时可明确放弃 |
| `prepared` | 完整转移凭证已保存，未必已经发布。可正向核对/明确续办发布；全任务符合条件时可另行确认放弃未发布暂存，不自动重新转移 |
| `moving` | 移动专用：目标已核验，源恢复目录/见证与源移除意图已保存；源名可能仍在或已转入恢复目录，不自动判断或重跑 |
| `quarantined` | 移动专用：原源文件已转入恢复目录并核验；历史尚未提交，保留源恢复对象与独立目标副本 |
| `completed` | 成功状态及媒体历史已提交。移动可能仍有持久清理待办；只要 `reason` 非空，整体任务为 `needs_review`，不把“历史已提交”显示成“清理已完成”。重复执行跳过该项 |
| `cancelled` | 未执行任务已取消，不再执行 |
| `discarding` | 整个任务的放弃意图已持久保存，正在清理已核验未发布暂存；所有普通执行/发布/移动均被阻止，目标预留仍保留 |
| `abandoned` | 此项已明确放弃，不记成功历史；全任务清理回执与目标预留释放提交后，任务也为 `abandoned` |

`POST /api/v1/organization/jobs/{id}/reconcile`（`{"confirm":true}`）只核验已保存发布凭证：私有暂存引用、设备/节点、对象类型、根/父目录身份和 SHA-256 必须相符，软链接还核对指向及源文件快照，才补交状态和历史。仅存在同名、同大小甚至同内容/同指向的其他对象不是成功证据。未发布、缺少完整凭证、损坏、替换或配置变化均保持占用/待核对，不自动删除暂存文件，也不返回“从未执行”的猜测。已核对完成的部分不会重新复制/链接；剩余 `planned` 项可由管理员再次明确确认执行。`cancel` 只适用于全未执行任务。旧复制任务/凭证缺少新增对象类型时仍按普通文件恢复，保留原账本和历史。

完整 `prepared` 暂存对象可由管理员另行确认 `POST /api/v1/organization/jobs/{id}/resume-publication`，非移动 JSON 为 `{"confirm":true}`，移动仍须增加 `"confirmSourceRemoval":true`。它从账本取得原对象的模式、身份、私有目录、父目录和摘要，不重新复制、不重建链接、不创建新的暂存目录、不接管未入账对象。重新核对配置、来源/目标根、原源身份/大小/修改时间与完整摘要、30 秒静默间隔、暂存目录身份/0700/当前运行用户归属及对象类型/身份/完整摘要；发布前再次核对账本仍为 `prepared`、源/暂存内容和当前目录绑定。仅通过防覆盖硬链接发布原暂存对象。目标已存在时，只有同一私有引用证明其为本任务原对象才可继续；同内容的外来目标也不覆盖或认领。正常执行与显式恢复并发时仍受原子防覆盖和一次性历史事务约束，不使用超时租约或自动释放。

继续发布完成后，复制/链接按实际原模式提交兼容历史；移动按已单独授权的原流程核验源隔离、提交历史及续办清理。跳过已完成/尚未执行项，不开始新文件；遇到运行中、缺完整凭证或其他不适用状态仍停止。普通核对和刷新不会代为调用。React 提供单独勾选/按钮，沿用任务保存的路径，错误只刷新。该入口是完整对象的正向续办，**不是负向取消、回滚或删除暂存**：未完成/未入账/受损对象和无法证明原对象的情况继续保留；源恢复目录已保存的移动应使用 `resume-move`。

2026-10-09 开放独立的 `POST /api/v1/organization/jobs/{id}/abandon-unpublished`，JSON 必须为 `{"confirm":true,"confirmDiscardStaging":true,"confirmOldExecutorsStopped":true}`。后两项分别授权删除本任务未发布暂存、确认管理员已实际停止旧执行器和其他路径写入任务；它们不复用 `confirmSourceRemoval`，不代为停止服务，也不是证明旧进程停止的自动检查。仍需遵守上述部署互斥前提。

首次处置只接受整个任务均为 `planned/prepared/staging` 且至少一个有凭证项，全部有凭证项都必须通过核验后才保存意图。核验配置、原源身份/快照/完整 SHA-256 和 30 秒静默、目标确实不存在（包括不能有软链接）、准确账本暂存名、私有目录及父目录身份/归属/0700、对象类型/身份，目录只能包含账本声明的 `payload` 和可选 `anchor`。完整凭证核验完整对象摘要；半写复制/移动副本必须为原独立节点、长度不超过原源、字节严格等于原源对应长度的前缀，见证与载荷均指向保存的节点且无额外硬链接，原源完整摘要在此前后仍需重新核验。链接仍核对字面类型、身份和完整源内容。损坏、不匹配、缺见证、未知对象均拒绝，不用“长度较小”代替归属证明。已发布目标即便属于本任务也不在该入口删除；无凭证的运行中、已完成、移动隔离阶段、源恢复凭证或未入账对象均拒绝，保留全部原占用。

先在事务中将整个任务保存为 `abandoning`、有凭证项为 `discarding`、未执行项为 `abandoned`，保留原凭证与处置原因；所有媒体/附件都不再执行。之后先移除凭证匹配的暂存 `payload`，见证仍固定原节点，再移除已核验的 `anchor` 和空私有目录，不动源文件、目标媒体、其他文件或父目录，不递归删除。每次删除前重新核对源/目标/目录绑定、内容证据和账本，逐步同步目录后保存单项回执；所有回执及再次核验完成后，事务关闭全任务并释放目标预留，不写成功历史、不重置为待执行。清理/回执失败时仍为 `abandoning`，必须用相同明确授权续办；已有持久放弃意图才允许仅剩原见证、空暂存或已移除暂存的回执恢复，且仍须正向证明原源完整、目标未出现。新凭证只剩载荷、见证缺失时拒绝，不接管可能替换/复用的对象；历史旧凭证没有见证标记仍按旧协议核验。新到目标或未知目录不会清理，也不释放预留。React 的两个独立勾选在刷新、任务/会话切换、请求结束时清空，失败只刷新。

对移动任务，普通 `reconcile` 仅返回当前账本，不改名、不清理、不补交移动历史。移动续办必须使用独立动作 `POST /api/v1/organization/jobs/{id}/resume-move`，JSON 为 `{"confirm":true,"confirmSourceRemoval":true}`。它只处理 `prepared/moving/quarantined` 的正向凭证和已提交项的清理待办，不复制目标、不启动 `planned` 项；运行中但无完整凭证、未发布目标、未知源恢复目录及配置变化仍拒绝续办。源改名竞态捕获其他对象时，仅尝试把本次捕获的对象恢复到空源名，不覆盖新文件；恢复失败则保留该对象，不删除。未经账本保存的同名恢复目录不能自动接管。

移动提交事务同时写入“源恢复清理待办”。源清理前重新核对目标私有引用和完整摘要，原源节点若恢复到源名则不清理；只处理原身份/快照/摘要匹配的 `payload/witness`，空目录才可移除。未知对象原样保留，清理失败仍为待办且目标引用不清理。源清理完成后持久保存“目标恢复清理待办”，才清理目标引用；引用仍存在时再次核对已发布目标，空暂存/已移除暂存只续办目录清理或待办提交，不重新处理源。两个阶段的数据库回执失败都可在重启后通过明确授权续办。成功历史只记录已验证的提交，不保证用户随后不会自行删除媒体文件。

React 展示任务账本保存的实际源/目标路径，执行与续办移动均需独立勾选源移除授权和相应执行/恢复确认。缺少路径时不开放授权按钮。选择任务、刷新、请求完成或登录会话变化会清空勾选，错误处理只刷新状态，不自动重试、恢复或切换转移模式。
