# Go 原生整理：本地复制、链接与移动任务

这是整理迁移的执行批次，不代表完整整理、同步和自动入库已经完成。保留旧 Python 实现，待所有保留能力和生产切换验收后再删除。

## 已实现范围

- 管理员在 React“整理预览”页扫描现有配置目录，核验媒体命名、大小门槛和目标冲突。
- `POST /api/v1/organization/jobs` 使用来源/目标 ID、相对路径、`mode=copy|link|softlink|move` 和已审核预览的 `fingerprint`，重新生成预览并核对指纹（包括转移模式）；变化时返回 409，不保存旧计划。只保存可规划项，先媒体后附件。不同模式不能同时预留同一目标。
- 创建任务只写当前 `user.db` 的新增账本，不创建媒体目录、不复制文件。`GET /api/v1/organization/jobs` 返回最近 30 个任务，`GET /api/v1/organization/jobs/{id}` 可读取任意已知任务 ID。
- 管理员另行确认文件已下载完成，调用 `POST /api/v1/organization/jobs/{id}/execute`，非移动任务 JSON 为 `{"confirm":true}`；移动必须同时提供 `"confirmSourceRemoval":true`，缺少任一确认时在抢占、文件写入前拒绝。任务创建、页面加载、刷新和错误处理都不会自动执行。
- 执行重新核对完整配置摘要、启用来源/目标、物理根身份以及每个源文件的设备/节点身份、大小和纳秒修改时间；源文件至少 30 秒未修改。目录选择沿用默认 150 MiB 或 `media.min_filesize` 门槛，明确单文件选择沿用旧行为不受该大小门槛约束。
- 只在 Linux/macOS 且关闭旧后端的模式开放执行；其他模式仍可预览，不回退 Python 转移。部署时必须另行停止旧 Python 整理/同步执行器：`NASTOOL_DISABLE_LEGACY=true` 本身不能停止独立 Python 进程。不要因此把尚未验收的候选运行时直接替换生产环境。

## 写入、去重与恢复

账本为 `GO_ORGANIZATION_JOBS`、`GO_ORGANIZATION_ITEMS` 和 `GO_ORGANIZATION_TARGETS`，位于既有 `user.db`。使用原应用的迁移前备份，不另起空库绕过旧数据。目标身份与相对路径的持久唯一预留跨 handler/重启保留；没有超时租约，也不因断线自动释放。单项用数据库状态比较更新抢占，只有一名执行者可开始。

2026-10-09 增加同任务跨进程执行互斥。所有生产任务动作（执行、两种恢复、核对、取消）在确认/权限检查之后，持有基于实际数据库目录的非阻塞文件锁，并在锁内重新读取账本；独立 handler/数据库连接/进程共用同一任务锁，不因数据库文件路径别名分裂。锁忙时返回 409 并说明已有操作在运行，不等待、不猜测超时、不自动重试；读取任务/列表和只读预览仍可进行，不同任务不共用全局执行锁。

锁位于实际数据库父目录的 `.nastool-organization-locks`（0700、当前运行用户），每任务锁文件为 0600 普通空文件。拒绝链接、非普通对象、权限/用户不符、额外硬链接、非空锁文件和路径身份变化，不自动跟随、接管内容或修复权限。正常/失败请求结束及进程终止由内核释放互斥，**不删除锁文件**，避免重新创建另一 inode 让两名执行者各持一把锁。锁文件持久存在不是“进程仍运行”的证据；只有实际锁操作判断互斥。持久任务状态/目标预留独立于此锁，进程死亡仍保留 `running/prepared/moving` 等不确定状态，不能据此释放目标或清理媒体。

这是后续人工处置的前置条件，不是已开放负向取消/清理。只约束使用此版本协议、共用实际数据库目录的 Go 执行器；不能约束 Python、未升级 Go 或其他媒体写入进程，不能证明它们已停止。仍必须停用旧执行器，不要运行混合版本、删除/更换锁目录、替换/恢复活动数据库目录或用新空库绕过原占用。数据库所在文件系统还必须实际支持跨进程文件锁，失败时明确拒绝，不回退内存锁或 Python；真实 NAS/NFS/跨容器挂载的锁语义仍待验收。

文件操作从已核验根目录的固定描述符逐层打开目录，拒绝链接祖先、链接源文件和非普通文件，不把客户端任意路径用于写入。先在目标目录下创建专属 0700 暂存目录，生成对应模式的对象，再保存设备/节点、对象类型、私有暂存目录和父目录身份及 SHA-256 凭证。发布前还重新打开配置根及源相对位置，拒绝源文件/根目录在准备期间被替换。通过目标侧硬链接原子发布该对象，目标已存在时失败，绝不覆盖。暂存引用保留到账本提交后，避免节点复用被误认作本任务的发布；提交后才清理本任务经过身份核验的私有暂存对象。当前要求目标文件系统支持对象硬链接和文件/目录同步，不支持时明确失败，不退化为覆盖式复制或其他转移模式。

| 模式 | 对象与限制 |
| --- | --- |
| `copy` 复制 | 先复制源内容，保留普通权限位和修改时间；源/目标有独立内容副本，不把源文件硬链接进库 |
| `link` 硬链接 | 不复制数据，将核验的源普通文件链接到暂存位置，再核对对象确为原源文件；源与实际目标祖先必须同一文件系统。预览可只读核对设备，执行重新核对；权限/文件系统不支持或跨设备时明确失败，不退化成复制。不会修改源权限、修改时间或删除源名；链接完成后源名被用户删除不影响目标内容 |
| `softlink` 软链接 | 建立指向已保存配置根下源文件的绝对链接。发布/恢复只检查链接自身，不顺着其文本访问任意位置；另从核验源根的描述符打开源普通文件，核对身份、大小、修改时间及摘要。源码路径须长期保持可用，失效或替换不能认作成功。当前发布要求目标系统支持对链接对象本身保留私有硬链接引用 |
| `move` 移动 | 先发布独立目标副本，再于源父目录建立专属 0700 恢复目录和原节点硬链接见证；持久保存源移除意图后通过平台原子防覆盖重命名将源名转入恢复目录，并核对捕获文件确为原身份/快照/摘要。历史提交后才清理核验的源恢复对象，最后清理目标私有引用。源文件系统须支持见证硬链接和防覆盖重命名，不支持时明确失败，不降级成覆盖式改名。不会删除源目录、新到的同名文件或任何未知文件 |

发布后再次核对目标身份、完整内容摘要和当前目录绑定，媒体成功状态与 Python 兼容的 `TRANSFER_HISTORY` 在同一数据库事务提交；附件不重复生成媒体历史。移动还必须有已保存且核验的源隔离凭证，不能只凭目标存在或源名空缺提交成功。历史字段保留实际“复制/硬链接/软链接/移动”模式、“手动整理”、核验的媒体类型、标题、年份、分类、季集及源/目标完整位置。事务失败时保留对象和发布凭证，不假装转移失败后重新执行。不清理源目录或任意未知文件。现有本地库存查询能够统计普通文件硬链接和有效媒体文件软链接，软链接失效时明确失败；并未开放链接目录遍历。

| 单项状态 | 含义与允许动作 |
| --- | --- |
| `planned` | 尚未执行。整个任务均为此状态时可明确取消，保留任务记录并释放目标预留 |
| `running` | 已开始，可能仍执行或已中断。不能凭时间判断停止，不能自动重跑/取消释放 |
| `prepared` | 完整转移凭证已保存，未必已经发布。只允许基于正向证据核对结果，不自动重新转移 |
| `moving` | 移动专用：目标已核验，源恢复目录/见证与源移除意图已保存；源名可能仍在或已转入恢复目录，不自动判断或重跑 |
| `quarantined` | 移动专用：原源文件已转入恢复目录并核验；历史尚未提交，保留源恢复对象与独立目标副本 |
| `completed` | 成功状态及媒体历史已提交。移动可能仍有持久清理待办；只要 `reason` 非空，整体任务为 `needs_review`，不把“历史已提交”显示成“清理已完成”。重复执行跳过该项 |
| `cancelled` | 未执行任务已取消，不再执行 |

`POST /api/v1/organization/jobs/{id}/reconcile`（`{"confirm":true}`）只核验已保存发布凭证：私有暂存引用、设备/节点、对象类型、根/父目录身份和 SHA-256 必须相符，软链接还核对指向及源文件快照，才补交状态和历史。仅存在同名、同大小甚至同内容/同指向的其他对象不是成功证据。未发布、缺少完整凭证、损坏、替换或配置变化均保持占用/待核对，不自动删除暂存文件，也不返回“从未执行”的猜测。已核对完成的部分不会重新复制/链接；剩余 `planned` 项可由管理员再次明确确认执行。`cancel` 只适用于全未执行任务。旧复制任务/凭证缺少新增对象类型时仍按普通文件恢复，保留原账本和历史。

完整 `prepared` 暂存对象可由管理员另行确认 `POST /api/v1/organization/jobs/{id}/resume-publication`，非移动 JSON 为 `{"confirm":true}`，移动仍须增加 `"confirmSourceRemoval":true`。它从账本取得原对象的模式、身份、私有目录、父目录和摘要，不重新复制、不重建链接、不创建新的暂存目录、不接管未入账对象。重新核对配置、来源/目标根、原源身份/大小/修改时间与完整摘要、30 秒静默间隔、暂存目录身份/0700/当前运行用户归属及对象类型/身份/完整摘要；发布前再次核对账本仍为 `prepared`、源/暂存内容和当前目录绑定。仅通过防覆盖硬链接发布原暂存对象。目标已存在时，只有同一私有引用证明其为本任务原对象才可继续；同内容的外来目标也不覆盖或认领。正常执行与显式恢复并发时仍受原子防覆盖和一次性历史事务约束，不使用超时租约或自动释放。

继续发布完成后，复制/链接按实际原模式提交兼容历史；移动按已单独授权的原流程核验源隔离、提交历史及续办清理。跳过已完成/尚未执行项，不开始新文件；遇到运行中、缺完整凭证或其他不适用状态仍停止。普通核对和刷新不会代为调用。React 提供单独勾选/按钮，沿用任务保存的路径，错误只刷新。该入口是完整对象的正向续办，**不是负向取消、回滚或删除暂存**：未完成/未入账/受损对象和无法证明原对象的情况继续保留；源恢复目录已保存的移动应使用 `resume-move`。

对移动任务，普通 `reconcile` 仅返回当前账本，不改名、不清理、不补交移动历史。移动续办必须使用独立动作 `POST /api/v1/organization/jobs/{id}/resume-move`，JSON 为 `{"confirm":true,"confirmSourceRemoval":true}`。它只处理 `prepared/moving/quarantined` 的正向凭证和已提交项的清理待办，不复制目标、不启动 `planned` 项；运行中但无完整凭证、未发布目标、未知源恢复目录及配置变化仍拒绝续办。源改名竞态捕获其他对象时，仅尝试把本次捕获的对象恢复到空源名，不覆盖新文件；恢复失败则保留该对象，不删除。未经账本保存的同名恢复目录不能自动接管。

移动提交事务同时写入“源恢复清理待办”。源清理前重新核对目标私有引用和完整摘要，原源节点若恢复到源名则不清理；只处理原身份/快照/摘要匹配的 `payload/witness`，空目录才可移除。未知对象原样保留，清理失败仍为待办且目标引用不清理。源清理完成后持久保存“目标恢复清理待办”，才清理目标引用；引用仍存在时再次核对已发布目标，空暂存/已移除暂存只续办目录清理或待办提交，不重新处理源。两个阶段的数据库回执失败都可在重启后通过明确授权续办。成功历史只记录已验证的提交，不保证用户随后不会自行删除媒体文件。

React 展示任务账本保存的实际源/目标路径，执行与续办移动均需独立勾选源移除授权和相应执行/恢复确认。缺少路径时不开放授权按钮。选择任务、刷新、请求完成或登录会话变化会清空勾选，错误处理只刷新状态，不自动重试、恢复或切换转移模式。
