## 调度与持久事务

周期必须为空或合法五段 cron；沿用 APScheduler 的星期一为 0、日期与星期同时满足规则，使用原生工作时区。不把它换成 Unix cron 或固定间隔。空 cron 不启用周期。

`onlyonce` 与周期独立。保存时在同一事务关闭原开关并登记最早三秒后的意图；后台每 15 秒检查，已有长任务会顺延，不承诺恰好三秒启动。配置保存本身不联网、不扫描／写入媒体。生产生命周期启动真实 worker 并在取消后等待其退出；handler-only 模式不悄悄执行后台任务，页面明确显示未启动。

新增私有 `GoLibraryScraper` 控制记录及 `GO_LIBRARY_SCRAPE_RUNS` 批次表。授权固定操作者、YAML 快照、选项、时区、根／来源身份及排除范围；配置、选项、根、来源授权或管理员改变会暂停旧调度，不能把配置改回去就恢复旧授权。

调度先在事务保存 scanning 意图、消费本次到期并推进下一个周期，再进行只读扫描。全部根的冻结清单、ready 任务和 queued 批次在同一个 user.db 事务发布；失败不能留下部分 ready 任务。全程不持数据库事务进行目录遍历或网络请求。扫描中断／未知提交不自动重扫；重新启动发现孤立 scanning 意图时暂停，需人工核查授权。

最多选择 16 个不同物理媒体库根，单批总计最多 50,000 个媒体和 64 MiB 私有清单。每个根继续受扫描对象／深度上限约束；超过限制拒绝整个批次，不把截断范围当成功。每周期重新冻结当前清单，因此明确授权的后续新增媒体可在下一轮处理，不扩张已入账任务。配置别名和规范路径下的绝对排除均按组件边界换算；排除某根的祖先会排除整个根，不误匹配 `skip-too`。空库数量随批次回执保留。

蓝光目录后续作为一个完整只读媒体对象接入三模式、一次性／cron 和旧触发，不拆分 STREAM 片段；TV 不猜逐集映射。完整清单、链接元数据恢复、明确扩大审核与验证见 [已有库蓝光整盘刮削](bluray-library-scraper.md)。

插件和旧触发按每个文件或整盘自动识别电影／剧集，允许同一物理配置根包含不同类型，仍逐个核验在线身份及季集。自动分类器对有明确集号、无季号的普通剧集文件沿用旧实现第 1 季规则，并核验该季每一集真实存在；蓝光整盘不沿用此默认，必须有明确且真实存在的季号。独立手动入口的明确季号规则不变。已有 NFO 的 `tmdb`、`Tmdb`、`TMDB` 等大小写写法均能读取，矛盾／畸形 ID 继续阻止执行。

每个调度／发布阶段使用相应跨进程锁。上一批有真实执行锁持有者时等待，不凭状态字符串猜进程已停止；锁可用但有遗留 running、needs_review、writing、uncertain 或 restore_running 时暂停下一轮，保留证据。普通已知图片缺失等 partial 不永久禁用周期：下一次到期是一次新的完整扫描，不重跑同一批。错过的周期合并为至多一轮，不补发停机期间的所有覆盖任务。

## 旧接口与事件

现代和旧插件安装、卸载、配置、状态、聚合列表、记录页均已接入原生实现；旧完整配置提交仍可保留未知项，启用周期／一次性任务须传读取时的 `fingerprint`（旧聚合列表及现代详情提供）、表单 `confirm=true`、`confirmOldExecutorsStopped=true`，强制模式还需 `confirmOverwrite=true`。指纹只可消费一次，不靠重复完整配置重新发起未知结果的运行。旧缓存／原始配置不因兼容读取回显。

`POST /do` 只接管 `cmd="media_path_scrap"`，保持该动作的 `force_all` 意图；其他旧命令明确未迁移，不透明发送给 Python。`POST /api/v1/organization/library-scraper/event` 仅接受 `event="media.scrap.start"`，按 `data.force` 选择 `force_all`／`no_force`，要求已完成原生安装接管的插件。事件独立于周期，仍须逐次明确授权；卸载或重新配置会撤销旧事件任务。

两类触发都采用相同的两阶段协议：

1. `data` 传配置媒体库内的绝对 `path`，以及 `review:true`（事件同时可传 `force`），只读返回范围、样本、`input.requestId` 和 `fingerprint`，不登记任务。
2. 确认时保持路径／force，传 `review:false`、该 `requestId`／`fingerprint`、`confirm:true`、`confirmOldExecutorsStopped:true`；覆盖另需 `confirmOverwrite:true`。重新扫描全部范围一致后才保存并返回实际 ready 任务。
3. 重复观察同一已提交请求只返回原回执，不重复执行；旧客户端仅传路径不会再静默获得强制覆盖权限，须改用上述确认协议或 React 手动入口。

事件的代次核验、任务创建及批次入账同事务；完成／取消任务与事件结果回执同事务。没有泛化任意事件执行器或命令行入口。仓库中未找到此事件的固定发送方（只有事件定义、插件订阅及通用插件命令派发机制），不为消除引用虚造入库事件；需要触发它的外部扩展可用该专用接口。其他消息／事件模块仍需分别迁移。
