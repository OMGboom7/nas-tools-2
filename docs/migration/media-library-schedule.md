# Go 定时媒体库同步

2026-10-16：在 [手动展示快照](media-library-sync.md) 的完整采集与原 `media.db` 原子替换底座上接入真实 Go 后台执行。默认关闭，不因配置里已有 `media.mediasync_interval`、旧 `SyncLibrary` 或已有缓存而自动获得执行权限。没有部署或启用生产任务。

## 使用流程

React「媒体库」中的独立定时同步区：

1. 只读刷新计划/最近 50 次运行，读取并选择当前服务器的媒体库。
2. 明确输入周期（小时，最短 1 分钟、最长 1 年），只读审核。原配置周期只作为页面建议，字符串沿用 Python 的 round-to-even，数字 YAML 沿用原小数小时；无效、负值、非有限值和过小/过大值不会变成可执行周期。
3. 分别确认旧 Python 同步任务已停止、授权周期替换展示登记簿。首次同步在启用后一个周期，不在审核/启用时立即采集内容。
4. 停止需明确确认当前代次；无需等远端读取结束，不删除媒体文件或已有快照。

Go 原生周期保存在 `media.db`，不改旧 YAML 周期或 `SyncLibrary`。这是明确接管而非隐式继承，界面同时展示旧建议和实际授权周期。改旧周期设置也使现有授权失效，须重新审核选择实际周期。旧 UI `start_mediasync` 动作、旧卡片“已存在”标记及进度轮询尚待迁移。

## 授权与实际运行

- 所有新接口仅限 Go-only 管理员。审核绑定服务器配置摘要、管理员身份/密码/API key 摘要、旧周期设置、所选库、实际周期及当前计划代次；不存储原始凭据或会话令牌。
- 审核和激活再次只读核对当前库列表与范围；激活事务验证当前代次，陈旧审核不能恢复已停止/替换的授权。
- 原生生产 `NewWithContext` 启动执行器，每 5 秒检查持久状态；仅创建 handler 的 `New` 不会启动后台任务。状态接口明确返回当前进程是否实际运行执行器，保存了计划不代表运行了任务。
- 首先获取与手动同步共用的跨进程执行锁，之后才检查/认领到期计划并完整采集，单次最长 10 分钟。手动同步、多个 Go 进程之间不会并发发布；锁不靠 TTL 或删除锁文件释放，无法约束仍在运行的旧 Python，必须由操作者先停止旧任务。
- 认领前持久推进下一周期并写入独立运行 ID，不按每个错过周期补跑；重启后未到期不执行，过期多次至多合并一次完整读取，维持原周期相位。
- 获取前和发布前检查配置及管理员授权。失效会持久暂停，恢复原配置不会自动恢复计划；API 的当前配置检查仍存在文件/数据库之间的瞬时竞态，快照另行绑定原配置摘要，不把它当当前下载查重证据。
- 停止/替换授权在 SQLite 事务中撤销旧代次并终结其采集回执。提交快照的**同一个事务**再次检查代次、运行 ID、完整定义、enabled 状态；过期、停止或替换的读取即便随后成功返回也不能发布。
- 快照条目、旧统计、快照代次以及运行 completed 回执同事务提交，回执写入失败不记虚假成功、不清除旧缓存。普通读取失败为 failed，保留旧快照，下一周期重新全量读，不复用部分分页。
- 取消会记录 interrupted；进程崩溃后，由真正取得执行锁的新执行器把未结束的 collecting 记录为 interrupted，不把它当完成，不立即重放原运行；下一到期周期创建新运行、完整读取。没有对媒体服务器的修改或文件操作。
- 停止授权能阻止正在读取的旧结果提交，但不会强行断开另一个进程已经发出的只读 HTTP；该请求在返回/超时后结束。正常关闭会取消自身读取并等待执行器退出。

## 数据与接口

新增表 `GO_MEDIASYNC_SCHEDULE`（单一当前计划）和 `GO_MEDIASYNC_RUNS`（持久运行记录）。原 `MEDIASYNC_ITEMS` / `MEDIASYNC_STATISTICS` / `GO_MEDIASYNC_SNAPSHOTS` 及首次备份继续沿用，不另起空登记簿。运行状态为 collecting / completed / failed / interrupted / stopped / paused / superseded；只有 completed 才有对应原子提交的快照代次。

| 接口 | 作用 |
| --- | --- |
| `GET /api/v1/library/sync/schedule` | 本地计划、最近 50 次运行、配置匹配、执行器状态及旧周期建议；不请求媒体服务器 |
| `POST /api/v1/library/sync/schedule/review` | 校验 libraries / hours / configFingerprint，只读审核，不启用/下种/发布 |
| `POST /api/v1/library/sync/schedule/activate` | 同一范围及审核 fingerprint，独立 confirm / legacyStopped 明确授权 |
| `POST /api/v1/library/sync/schedule/stop` | 当前 revision 及独立 confirm，原子停止 |

前端响应丢失后只读刷新，不自动重复授权或停止。完整采集仍遵守单页/总量/身份/剧集证据边界，不因这是后台任务而绕过分页失败或把缓存作为实时缺失证据。
