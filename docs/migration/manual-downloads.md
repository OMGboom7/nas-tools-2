# 手动下种持久回执与业务通知

## 本批实际接入

Go 的磁力、上传种子、配置站点链接和原生缓存搜索四个 HTTP 入口，接入同一手动提交账本。不是只补一条通知调用：真实 RPC 前持久化原下载器、配置/本次选项摘要、实际 info hash、提交者账户 ID/名称及来源/标题；RPC 正向应答后，在同一个 SQLite 事务中提交任务接收回执、兼容 DOWNLOAD_HISTORY 和 `download_start` 事件。复用已有业务事件发送 worker，不在请求中直接发送消息，也不因发送失败再次下种。

只支持已有 Go 协议能力：qBittorrent、Transmission、Aria2，以及 115 磁力；未迁移下载器不回退 Flask。种子内容按真实编码 info 区域取 hash，磁力 Base32/十六进制归一化。上传/站点/磁力/搜索中同一下载器的同一 hash 共用唯一手动 scope；更换来源、刷新缓存或重启不绕过它，配置或选项不同不静默接管旧 scope。已有待核实的同 hash 还会阻止切换默认下载器后再次提交。

原生搜索中已知正值的最低做种时间/分享率，在完整策略执行迁移前明确拒绝，不能将其当作零或遗漏后下种。未知约束不是已知零；本批没有实现整个 PT 策略，也没有为原始磁力/上传补出其本来不具备的站点约束。未知/旧搜索 ID 的兼容链路及 RSS/订阅各自账本仍需后续统一，不从手动 scope 推断全系统跨来源防重已完成。

## 持久意图与失败边界

`GO_MANUAL_DOWNLOAD_SUBMISSIONS` 保存每次预留和 pending/submitted/rejected 状态；`GO_MANUAL_DOWNLOAD_SCOPES` 持有唯一 task scope，不使用到期租约释放不确定对象。已提交的相同原配置/选项/账户请求只读取原回执，不再次发送 RPC；不是重新确认远程任务还存在。账户绑定包含 ID，不能仅凭删除后重用的用户名接管旧回执。

提交客户端由同一条已核验的下载器行直接构造，不在检查旧摘要后再次读取另一条地址/默认下载器。纯 Go 提交与管理员核实按 hash 共用跨进程操作锁，避免对正在提交的请求并行“恢复”；事务中再次核对配置及 scope 归属。通知/历史回执提交后还核对原配置，进行中的配置切换不能虚记成功，也不会把旧任务操作发送到新地址。已发出的旧请求不能保证被后续配置撤销追回。

只有明确发生在任务发送前的配置/认证/不支持选项错误，才记录 rejected 并释放其 scope，允许用户新的明确请求；旧拒绝尝试继续保留审计。无效配置 JSON 在预留前拒绝。连接失败、应答丢失/错误、任务身份不符、接收后数据库失败保持 pending；不能用重试、重新搜索或“看不到任务”自动解除。收到的 qB/Transmission/115 task ID 必须与实际 hash 一致；Aria2 必须得到有效 GID 后才能记账。记录不存磁力 URI、站点 passkey、Cookie、下载器密码或种子原始字节，兼容历史的 ENCLOSURE 留空；未取得的 TMDB、年份/类型、完成状态不靠标题猜测补齐。

本批不会删除旧历史，也不会主动取消/删种、修改远端标签或清理文件。手动原始磁力/上传仍不擅自应用搜索预设；Aria2 成功应答保存真实下载器/GID 历史，作为后续 only_nastool 的准确归属证据，不拿空显示对象代替。

## React 与管理员明确核实

`GET /api/v1/downloads/submissions?page=1` 为纯 Go 管理员只读入口，每页最多 100 条、页码 1–10000，优先待核实；分页是当前列表，状态变化可能使条目位置变化，不是稳定快照导出。返回字符串下载器 ID、实际 hash/任务 ID、原提交者/来源/时间及状态，不返回配置/选项摘要或路径。读取空队列不创建账本表，不请求下载器。

`POST /api/v1/downloads/submissions/{id}/reconcile` 需管理员和独立确认，锁定后重读原回执，只对原配置的 qBittorrent / Transmission（两种 RPC）读取准确 hash 的全状态存在性。缺席、错误、其他 hash 或配置变化保留 pending；不重发 add、不切换默认下载器、不释放预留。得到正向证据后，原回执、兼容历史、通知事件和 `GO_MANUAL_DOWNLOAD_CONFIRMATIONS` 中核实操作者/证明方式同事务提交。

`verified_present` 仅证明当时原 hash 存在，不证明是本次新建、全部每任务设置已生效、文件下载完成或已入库；对应通知明确写“已核实任务存在”，不能假报一次新的成功 add。已提交回执再次查询/核实只返回历史值，不重复记账或发送消息。Aria2/115 的响应丢失尚无足够身份依据，当前返回未迁移并保持预留，不猜 GID 或释放任务。

React 下载页提供只读分页、逐回执核实与明确确认，换会话/卸载失效旧结果；核实响应丢失只读刷新，不重发核实或下种。普通下载用户仍可按现有权限提交，待核实处置由管理员完成。

## 剩余门槛

跨 RSS/订阅/手动账本的全局真实任务防重、115/Aria2 不确定身份恢复、外部删除后明确重新添加、完整媒体元数据与旧富消息、PT 策略执行，以及真实站点/下载器/NAS/浏览器和无 Python 生产镜像验收仍待完成。scope 永久保留不等于这些能力已实现；旧 Python 尚不能删除。

## 本批验证

模块整体验证和修复后复验通过：Go 全量测试、静态检查、Linux amd64 无 CGO 构建；下载器配置/业务事件与 HTTP 手动提交、下载、完成、监控、同步、整理、订阅、RSS、内置/海胆搜索等相关并发安全回归；前端 85 项测试及构建。模拟 qBittorrent、Transmission 两种 RPC、Aria2 和 115，核对真实 RPC 前持久预留、磁力/上传的重启后防重、跨站点/上传的同 hash 范围、搜索新缓存 ID 不重下、不确定接收及本地历史提交失败后只读恢复、准确 hash 与缺席/异 hash 拒绝、云端未知身份不释放、已知认证拒绝保留审计并允许新的请求、默认/配置变化不绕过 pending、提交/核实共用操作锁、分页只读无建表、权限和独立确认、历史/事件/证明操作者原子提交，以及配置在历史事务内撤销导致整体回滚。初次回归的两处旧站点测试仍期待忽略已知 PT 正值后下种，已改为核验明确拒绝且无下载动作，同时保留无已知正值来源的实际提交验证；并未把 PT 拒绝测试当作策略迁移完成。既有 Transmission 上传测试也改为返回真实 metainfo hash，另有异 hash 明确拒绝用例。全部测试使用临时 SQLite 与模拟接口，未发送真实通知、操作真实下载器/NAS 或部署生产。
