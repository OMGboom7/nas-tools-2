# 入库事件与媒体服务器刷新

2026-10-26：将旧 `LibraryRefresh` 插件的完整新入库事件、明确刷新事件、延迟调度、配置与生命周期接入 Go／React。媒体服务器扫描不是本地 `media.db` 清单同步，也不是文件整理或删除。

## 范围与权限

- 仅纯 Go 当前管理员可操作，原插件 ID、安装名单与 `plugin.LibraryRefresh` 配置保留。未知配置字段保留但不回显。现代插件配置／扩展页和旧配置／安装／卸载／状态／列表／扩展页接入原生实现；本插件及刷新专用路径的错误方法或子动作不能落入 Flask。
- 原 `enable` 不启动新执行器。须重新审核当前配置，分别确认未来事件后台授权、旧重复执行器已实际停止和定向／整库扫描的服务器元数据影响与 I/O 开销。三项确认不存为下次默认值。读取状态、插件页和清单不访问媒体服务器。
- 授权绑定当前管理员认证摘要、所选媒体服务器整条配置、服务端实际身份、插件配置及新的授权代次。修改地址／账户／类型／配置、停用、卸载或重新授权均不能把旧队列转给另一个账户；每项请求前重新检查授权及服务器身份。已经送出的请求不能保证被后续停用撤回。
- 不发送强制全部元数据／图片替换、清空回收站、删除媒体／下载任务等请求。媒体服务器仍按其自身扫描设置运行，不承诺扫描没有元数据变化。

## 原事件与持久队列

本地复制／硬链接／软链接／移动、Rclone／MinIO 及整盘共用原生完整入库的成功事务。只有全部保存条目和移动清理回执成功后，`transfer_finished`、原成功历史和刷新队列才在同一 SQLite 事务提交。普通不识别同步、草稿、部分媒体／附件组及不确定任务不冒充入库完成。刷新队列写入失败时原数据库成功回执一并回滚，已发布文件保留原凭据，不能重传来修补数据库。

只接收当前授权之后的新原生事件，不从旧通知正文、旧 Python 易失队列或历史文件名推断路径，不在启用时补扫旧事件。原任务及全部媒体路径、类型、身份与完整整盘边界冻结到私有任务定义；浏览器不能上传替代路径或服务器地址。

原实现先写 NFO／图片再发刷新事件，因此新队列还冻结原任务定义摘要及实际入库刮削的 ID／来源绑定。自动刷新等待这些元数据任务终结，未决写入不作为已完成元数据采用；原任务永久关闭、定义／依赖被改动或终结回执仍有不确定输出时，旧刷新任务阻止派发。等待只重新核对本机账本，不探测服务器、不重跑刮削；独立的下次检查时间避免等待项阻塞其他任务，不改原延迟到期时间。每个刷新请求意图提交事务中再次核对原绑定。手动选择旧任务也须等原元数据回执稳定，独立整库审核则不借用旧任务授权。

`delay` 沿用旧秒数含义，小数向零取整、负值按 0，最多 2,147,483,647 秒。自动事件的到期时间持久保存，重启不丢失待执行延迟；较早的其他授权任务不被新授权接管。每次新审核的明确刷新事件不延迟。

`NewWithContext` 在纯 Go 模式启动每 10 秒检查的执行器；handler-only `New` 不启动。既有跨进程锁与任务 CAS 串行派发，一轮最多 5 个到期任务。先持久保存完整只读规划，再为每个确切目标存请求意图，随后才发一次请求。`accepted` 只证明 HTTP 正向应答，不证明扫描已完成。网络失败或回执不确定为 `uncertain`；进程中断或本地结果回执丢失保留 `planning`／`running`／`intent`，均不自动抢占或重发。

停止单个任务只阻止后续请求，保留已经接受的逐项回执；不撤销未来新事件授权，也不假称服务器已经撤回扫描。停用或卸载插件阻止原授权的后续派发，但不删除任务、历史或配置。

## 服务器规划

- Emby：按原名称／年份与已知 TMDB 身份完整查询。已有电影保持不刷新；已有电视剧只刷新匹配剧；新媒体按分类及路径边界选择单个子目录或其媒体库，无法唯一映射时明确回退整库。查询失败／清单不完整拒绝规划，不把失败当“未找到”而扩大整库。
- Jellyfin：沿用旧插件的整库扫描行为。
- Plex：支持 JSON／XML 的完整分区与路径，按完整路径边界和最具体根选择媒体目录；同目录去重，整盘保留目录边界。没有匹配或映射歧义时规划完整分区清单，逐分区扫描，不调用有兼容歧义的全局刷新地址，不发送 `force` 或 `emptyTrash`。

服务器条目／分区 ID、目录与完整计数有严格校验，不采用外部返回的任意执行 URL。单任务最多 1,000 个媒体、4,096 个刷新目标，完整分区最多 256 个；HTTP 读取沿用 1 MiB 上限，超限整体拒绝而不执行截断清单。单个私有定义最多 8 MiB，方案最多 16 MiB；真实大库性能仍须验收。

协议依据：[Emby 整库扫描](https://dev.emby.media/reference/RestAPI/LibraryService/postLibraryRefresh.html)、[Emby 单项刷新](https://dev.emby.media/reference/RestAPI/ItemRefreshService/postItemsByIdRefresh.html)、[Jellyfin 扫描控制器](https://github.com/jellyfin/jellyfin/blob/master/Jellyfin.Api/Controllers/LibraryController.cs)、[Plex 服务器 API](https://developer.plex.tv/pms/)。

## 原 Plex 账户模式

除原地址＋令牌外，本模块兼容旧 `username`／`password`／`servername` 发现连接，不要求因此重写现有配置。必须另行确认仅向固定 HTTPS `plex.tv` 登录和发现所选服务器；发现的明文 HTTP 连接默认不使用，若保留该旧能力须再单独确认令牌暴露风险。始终保留证书校验，不跟随登录／发现重定向，不把缺失的服务器令牌替换成账户总令牌，不选择同名歧义服务器。

账户口令与账户／服务器令牌均不进入事件、数据库任务定义或公开回执。每个运行时与授权代次只进行一次账户发现尝试；成功连接和失败结果仅缓存于内存，不为修补刷新回执重新登录或重发刷新。内存最多保留 128 个代次，达到上限拒绝新连接、不驱逐旧结果来重复登录。重启后只有新的待执行任务可以重新建立账户连接，不接管旧发送意图。Plex 已弃用原密码登录；失败不绕过验证、自动更换登录接口或将其冒充新版 PIN 授权。新版登录方式及其他现有媒体读取入口共享账户连接仍属后续整体迁移范围。依据：[旧登录接口与弃用说明](https://forums.plex.tv/t/how-to-request-a-x-plex-token-token-for-your-app/84551)、[Plex 推荐认证流程](https://forums.plex.tv/t/authenticating-with-plex/609370)。

## React 与回执

插件页维护启用／延迟和独立授权，并提供只读队列扩展页。服务页提供完整服务器与目标审核、明确单次提交、最近 30 条回执、较早稳定编号查询与单任务停止。手动事件只接受明确整库，或已有真实完整原生入库事件的准确任务编号；客户端不能提供原媒体内容证明或任意路径。

提交前保留稳定编号，错误清空确认但保留编号，较早记录可用 GET 查回；不会因网络错误重新提交。已提交相同请求仅返回原回执，不重新读取服务器或再次排队。刷新／停止不是文件删除或服务器扫描完成的证明。
