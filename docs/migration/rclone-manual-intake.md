## 启用和兼容

仅在 `NASTOOL_DISABLE_LEGACY=true` 时，通过绝对路径 `NASTOOL_RCLONE_CONFIG` 显式选择已有 Rclone 配置；`NASTOOL_RCLONE_BINARY` 默认是 `rclone`。未配置时不读取宿主机默认账户、不开放远程模式。Go-only 候选镜像安装 Alpine 的 Rclone 包，但没有默认启用账户、远程挂载或自动整理。

沿用旧字面模式 `rclonecopy`／`rclone` 和历史标签 `Rclone复制`／`Rclone移动`，目的端始终是 `NASTOOL:<配置的绝对逻辑根>/<命名后的相对路径>`。不把这个逻辑根当本机路径创建或访问，不要求同名本机目录存在。`NASTOOL` 需在显式配置中存在且能列出目的根；不会创建账户或猜另一个 remote。原 YAML、用户数据库、旧 Python 与生产镜像继续保留。

配置内容复制到本次操作的 0700 私有临时目录、0600 配置快照，子进程不经过 shell，重试次数固定为 1，标准输出、清单和执行时长受限，取消向子进程传播。配置／环境摘要及执行文件身份参与任务指纹与每次操作复核；凭据、配置路径、配置摘要、命令输出和私有转移凭证不出现在公共预览／任务响应中。密码命令、外部 SSH 命令及相应环境覆盖不执行；加密配置无法在执行前检查是否包含辅助命令，本批明确拒绝，需管理员显式提供可检查的独立配置，不自动解密或运行辅助脚本。凭据刷新只发生于操作快照，不回写原账户配置；新授权后需重新预览，不向旧任务静默换账号。

执行文件的持久绑定使用完整 SHA-256，不保存易随容器重建改变的设备／inode 身份；同样内容的新文件可继续旧审核任务，内容变化仍阻止旧任务。仅进程内哈希缓存使用设备、inode、ctime、大小和修改时间，执行／读取导致的 atime 变化不会失效缓存；新进程重新计算摘要。

## 远程约束和独立授权

通用远程存储不能提供本地 inode 身份或跨服务商的原子防覆盖语义。执行／恢复／核对请求必须分别确认：已停止旧执行器及外部写入器、本程序独占该远程命名空间并接受非原子可见性、保留完整恢复副本及元数据暂存并承担容量／读取流量费用。移动另需原源移除及本地源恢复备份清理授权；这些不是原源恢复、远程删除或自动任务授权。

目标预览存在即冲突；首次发布不能接管即使内容一致的旧对象。自身所有远程发布共用跨进程命名空间锁，目标路径按大小写折叠、Unicode NFD、逻辑绝对路径及祖先／后代关系持续预留。改变目标根别名不能绕开旧预留。它们只约束同数据库、已升级的执行器，不能替代实际停止外部写入器。

Rclone 的 `copyto` 本身允许覆盖，`--immutable` 或零退出码都不能独立作为发布成功凭证。本实现发布前再次核对目标不存在，使用 `--immutable --checksum --no-update-modtime`，随后读取全部内容计算 SHA-256。详见 [copyto 文档](https://rclone.org/commands/rclone_copyto/)、[immutable 说明](https://rclone.org/docs/#immutable)。若另一个程序违反独占约定，在“核对不存在→写入”之间抢写，通用远程协议仍没有原子保护；界面明确说明该限制，不能声称获得本地防覆盖等价保证。

## 凭证、发布与故障处置

源文件使用固定的本地目录／文件句柄读取，核对身份、大小、修改时间和完整 SHA-256，至少 30 秒未修改。不是把可交换的源路径交给子进程。

1. `running` 只表示已领取，不能重试上传。`staging` 先保存源清单、完整哈希、随机操作空间和授权，再向 `.nastool-remote/<随机操作>/manifest.json` 与 `files/<序号>` 上传。
2. 逐个读回私有清单和全部私有载荷、检查无额外对象后，保存 `prepared`。缺失或不确定的 `running`／`staging` 不自动接续上传。
3. 保存 `publishing` 意图后，只从完整私有副本复制到最终路径。完整读回目标后才保存目标核验凭证；复制据此提交历史。移动继续沿用本地原源隔离、原身份／完整内容核验、历史和分阶段清理回执，远程原始恢复副本持续保留。
4. 请求失败、取消、进程退出或回执丢失不重放。`resume-publication` 只接受已准备副本／既存发布意图；在明确的独占和内容证据约束下，已存在部分文件须与冻结清单完整 SHA-256 一致，仅复制缺失项，不重传原源。`reconcile` 对复制仅做正向内容核验和记账，不写远程文件；移动普通核对不会处置来源，须另外继续移动。
5. `close-remote` 只将无源隔离待办的任务关闭为 `remote_closed`／`remote_stopped`，保存操作者／原因回执；不造成功历史、不删除对象或释放预留。只在全部未执行时才允许普通取消并释放预留。已有源隔离凭证必须使用原源恢复通道，不能因“停止”隐藏来源去向。
6. 原源恢复独立核验本地原文件／见证或蓝光整盘，不依赖远程在线、原账户配置或旧命名规则；不从目标重复制，不删除或接管远程目标／暂存，既有历史与预留保留。

临时副本与最终对象可能都可见，且每次正向验证需读取完整数据，费用和耗时不能按一次远程复制估算。没有自动清理 `.nastool-*`、过期放行、强制覆盖或失败即重试逻辑。`rcat` 读取标准输入的语义参见 [官方文档](https://rclone.org/commands/rclone_rcat/)。

## 蓝光、NFO／图片和字幕

蓝光按一个整盘对象冻结全部目录、菜单、片段、证书、隐藏文件及其他附属文件，逐文件 SHA-256 发布／恢复，不把 m2ts 片段冒充单独电影。支持实体空目录的后端会创建并核对空目录；对象存储不支持时，空目录只保存在私有清单中，公共摘要和界面如实说明。

整组转移和移动清理完成后才派发入库事件。入库刮削可在同一远程独占授权下创建缺失 NFO／图片，先存独立写入意图、上传私有副本、完整核验后发布，已有对象保留；不确定回执不重放。字幕工作器先核验远程原始载荷并等待刮削回执，再沿用已配置 ChineseSubFinder 的单次提交／路径映射流程；这不证明远程路径在媒体服务器或字幕服务上已挂载，仍需实际部署验收。

远程 FFmpeg 缺图回退尚未开放：现有解码接口要求可寻址的本地只读文件，不把云端逻辑路径当本地文件，也不暗中下载整个视频到本地；单项留下失败回执，NFO／其他图片可继续。
