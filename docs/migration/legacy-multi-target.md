# 旧记录与手动识别：多目标协调（2026-10-21）

本批补齐 [旧记录远程入库](rclone-legacy-intake.md) 留下的默认混合媒体缺口：未指定目的时，电影、剧集和动漫按当前配置及核验身份分别选库。旧重新识别、关联改名和自定义识别复用原本地四模式及 Rclone 两模式；明确指定旧目的仍使用该目的，不借分库扩大到任意路径。

## 规划与原子预留

所有候选根使用同一来源快照、配置、媒体身份和筛选结果。每个媒体与唯一附件只分配一次；未知、冲突、歧义附件、跨预览变化和未覆盖的来源仍拒绝，不能凭其中一个库成功就接受整条记录。明确筛选和父目录扩展继续按原规则独立授权并保留旧未知行状态。

多目标预览显示每个配置根及对应项目，执行需要完整批次审核指纹和停止旧执行器／外部写入器的独立确认；移动、远程独占／非原子可见性及保留恢复副本费用仍分别确认。普通预览不创建任务、不转移文件、不启用后台。

`GO_LEGACY_ORGANIZATION_BATCHES` 是原用户数据库内的新增持久批次表，保存不可变子定义、原来源／旧行及全部子任务 ID。批次、子任务、所有目标预留和旧未知记录的唯一待完成关联在同一 SQLite 事务中创建：一个根冲突即全部回滚，不留下半个新批次或孤立旧行占用。

原 `GO_ORGANIZATION_UNKNOWN_PENDING` 唯一约束保留，不拆成多个可并发接管同一记录的占用。第一个真实子任务作为所有子任务共享的原行关联所有者；每个子任务仍使用自己的已审核单目标、持久阶段、文件内容凭证、源隔离／清理、历史和入库事件，不把其他库伪装成同名路径。

## 完整完成不是单个任务成功

批次先记录执行意图，再执行原子预留的子任务；已执行或响应不确定的批次不由后续提交、刷新或重启整体重跑。每个子任务的写入／发布／移动及关键数据库阶段都核验原批次成员和当前授权状态。

完成某个子任务只保存它的文件和历史回执，不标整条旧未知记录 `Y`，也不释放旧行占用。全部保存项目及移动清理完成后，分别按各自真实本地／远程根重新核验完整目标内容，再合并原来源范围验证；只有全部通过才同事务提交批次完成与唯一旧行兼容回执。新出现的未审核媒体、改变的原行、丢失目标、损坏内容或不完整回执继续保留待核对。

原历史不重写；自定义识别不隐式关联旧行。筛选／扩大造成的 `preserved` 仍不把部分范围标成整条成功。兼容回执失败只能重新完整核对再补数据库回执，不重传、不再写文件历史。

远程整盘移动在持久源清理回执和完整远程目标核验后，仅清理凭证绑定、确认原对象未恢复到原名且内容已为空的本地源隔离目录。不会忽略来源扫描中的未知暂存对象，也不会使用这一步删除云端目标、恢复副本或元数据暂存。

## 中断与明确处置

React 任务区可读取整个批次、全部目标、子任务及当前审核快照。

- “执行”只接受从未启动、全部项目仍为 `planned` 的 `ready` 批次，不能复用它来重跑中断工作。
- “核验”只读取所有目标／来源并尝试补完整批次回执，不复制、不继续发布或移除源。
- “停止”立即撤销后续正向步骤；已经开始的文件系统步骤与数据库不是原子操作，须核对原账本，不能假定停止已回滚。
- “重新授权”须基于新审核、当前原配置／根／账户及停止写入器确认；只重新开放原子任务的独立人工恢复，不自动续跑整个批次。负向处置过的子任务不能重置为未执行。
- “关闭”须先停止整批并重新审核，最多取消从未开始的子任务。已执行而未完成的对象须先使用原任务的凭证放弃、离线原源恢复或远程停止留证。只有所有子任务都可核验为完成或明确终止时，才释放整批原行占用；保留原行状态、已发布文件、既有历史和仍需保留的目标／恢复对象。

单个子任务的取消、放弃、原源恢复或远程停止不能释放兄弟任务的旧行占用；不能在单个子任务上强制解除整批关联。关闭批次不产生整理成功事件。远程原源恢复继续不依赖云端在线，不开放自动云端清理。
