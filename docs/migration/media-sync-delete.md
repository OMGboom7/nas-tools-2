# Emby 同步删除

本模块保留并 Go 化旧 `MediaSyncDel`：原 `/emby` GET、JSON／`data` 表单回调、原插件设置、电影／整剧／季／单集选择、历史与对应去重／同步记录、可选原源文件／NFO／无媒体目录清理，以及原“自定义消息”完成通知。电影精选、下载任务清理及其他消费者仍各自迁移；本模块不会再次删除 Emby 库目标，也不替代 PT 要求。

## 原回调与匹配

处理原 `event_type=media_del`；必须给出明确 `item_isvirtual`。接受旧字符串 True／False 及明确 JSON 布尔值。虚拟媒体忽略；缺少或含糊标志时，接收回执与停用原 `enable`、原生授权同事务，保留未知字段。停用写入无法核实时回调事务失败，不声称已经停用或接收成功。

原字段为 `media_type`、`media_name`、`media_path`、`tmdb_id`，季／单集另需 `season_num`／`episode_num`。保留原编号补零和具体单集字符串匹配。电影／单集必须匹配原目标文件名；整剧完整匹配同媒体，季号按完整数字匹配，避免 S02 误及 S020。电影与 TV／动漫类型分别匹配，纠正旧仅凭相同 TMDB 数字跨类型选择的问题；不因整剧超过 100 条而只处理前一部分。

`exclude_path` 保留逗号分隔的原 Emby 路径，按完整路径组件排除，避免 `/media/a` 误排 `/media/another`。支持规范本机和 Windows 回调路径。回调路径只用于排除及版本名称比较，不能指定实际删除根、网络地址或源路径；源范围由完整原历史和另行批准的本机源目录确定。

接收器仍核对当前服务器类型、真实来源网段、原密钥与独立接收授权。旧接收身份不能被新消费者授权补领；明确同一事件编号去重。没有提供原事件编号时，接收器为每次请求创建新接收，不把无编号重传宣传为可识别的同一个事件。已完成历史不会由相同回调再次处理；新产生的历史属于新的实际范围，须继续满足当前完整规则和授权。

## 完整删除与恢复

安装、重装、保存配置和旧表单修改均保持原生执行停止，旧 `enable` 不自动授予副作用。只读审核绑定管理员、应用配置、原 Emby 身份和逐个选择的源目录身份，有效十分钟；明文 Emby 读取先单独确认。启用前再次核对原服务，分别确认未来历史删除、去重重置、关联旧写入权关闭、所选源范围／唯一副本／展开目录风险、旧执行器停止及所选通知。

默认历史模式不删除文件。源模式复用现有完整媒体删除协调器：先冻结全部原行、未知列／NULL／整数／BLOB 和去重关系，以及完整文件内容／身份／所有者，检查 PT 与原源位置，再提交原回调与独立删除计划的关联。普通手动接口仍保持原 100 条上限，回调整剧内部支持完整最多 20,000 条、受原总内容／对象预算约束；超限明确阻止，不分割后静默处理子集。

逐文件操作使用原内容凭证、捕获／删除意图和明确结果。后台只取新 pending，不续跑已经保存或进入执行的旧计划。完整原范围核实后，历史／去重删除、最终协调器回执、同步删除回执及可选通知在同一个事务提交；处理中停用、权限／配置／根身份变化会阻止后续工作。部分物理删除不能由数据库回滚撤回，仍保留原文件事实和未完成回执。

React 可按页和完整稳定编号查回。已关联计划可只读核对整个原范围，再逐项独立确认后执行一次明确继续；此恢复使用当前管理员的单次授权，和未来后台授权分开。响应不明后只读查回，不重复操作。明确忽略需原因，同时关闭原未结束协调器与当前后台，保留旧结果、捕获对象和剩余占用；不归还已经删除的对象。已有本机捕获对象的防覆盖返还仍由整理页“历史／媒体删除”按原完整编号独立审核。

普通媒体删除入口可只读查看、停止或独立返还捕获对象；关联同步删除的“继续”须回到同步删除管理区，避免借普通入口绕过原通知及完整范围的独立确认。

## 通知与边界

只有完整处理后生成 `plugin_message`，按旧 `custom_message` 开关冻结渠道。通知图片由已配置 TMDB 查询产生：单集使用原集图片，其余使用原媒体背景，失败使用 Emby 公共图标；不跟随回调携带的图片或服务器 URL。发送沿用独立持久通知意图，不确定响应及重启不重发通知，更不重做删除。

源文件删除事件保留给其他原生消费者／外发，但不借此启动尚未迁移的 TorrentRemover、MediaSyncDel 以外插件或解除做种义务。电影精选 MovieLike 继续是下一独立模块。真实 Emby／NAS、存量升级和候选镜像仍需最终整体验收，不能据临时夹具删除 Python。
