# 原生媒体详情、季集与播放入口

2026-10-16：Go 直接读取媒体详情、演职人员、季集及相关推荐，React 提供完整详情页面；探索、资源搜索和订阅卡片均可进入，不再依赖旧 Jinja 详情页面或 Flask 请求。保留现有配置、原 user.db 订阅记录和 media.db 展示快照，不新建空业务数据替代旧数据。

## 用户流程与真实来源

- 电影与电视剧详情展示标题/原名、年份、简介、评分、海报/背景、类型、时长及已提供的制作/发行资料。未提供的时长保留 null，不按 0 推断；成本/收入保留上游原始数值，不估算或换算。
- 演职人员直接读取对应 movie/tv credits。TV credits 按原 Python 所用接口提供**最近一季名单**，不是跨所有季的 aggregate_credits；页面明确标注。人员链接为 TMDB 公开页面；演员和工作人员完整保留至有界响应限制，不额外加载演员搜索/作品页。
- 支持数字 TMDB ID、DB: 豆瓣 ID；TV 还支持 BG: Bangumi ID，复用既有 Go 身份解析，不按标题猜一个 ID。数字身份与上游详情 ID 不匹配即失败。DB 来源保留豆瓣链接，普通 TMDB 来源不编造豆瓣对应关系。
- TV 按季号展示季信息，包括第 0 季/特殊篇；切换季后按实际返回集号展示集详情，不把第 0 集视作未指定。上游季号和集号必须明确匹配；若返回 show_id 则须与所选剧匹配，重复集号/ID或错误身份均失败。没有 show_id 的响应仍依赖所配置 TMDB HTTPS 端点与正确季号，不声称有额外父剧证据。
- 季集每页最多 100 项，上游季列表最多 1000 季、单季最多 10000 集，每次上游响应最多 2 MiB、请求最长 15 秒。超出边界或错误信封不被当作“无季/无集”。明确的空集数组可展示为尚无集信息。可用缓存另查；缺页或失败不改登记簿。
- 展示标记复用 [展示缓存](media-display-progress.md) 的当前配置绑定、精确类型/身份与实际季/集查询，始终只供展示。多批缓存读若代次/范围变化，整批退回未知；不会拼成同一快照，也不会以“快照未记录”断言服务器缺失。
- 当前订阅从原 user.db 读取，TV 保留各条记录原 SEASON，某季已订阅不因此禁用其他季。订阅按钮仍要求“订阅管理”权限、用户明确确认和真实季选择，提交至原 Go `/api/v1/subscriptions`，不另建提交器，不从缓存推断缺失后自动订阅。现有精确订阅对有效总集数、季号等限制不变，不能为通过页面而降级为模糊订阅。
- 用户点击后才查询当前播放入口：重新取得 TMDB 身份，实时查询当前配置的媒体服务器，使用现有 Inventory 的标题/年份/可用提供方 ID 匹配规则，再生成当前服务器 UI URL。快照有记录、实时无对象或实时查询失败时，不用旧缓存 ID 编造播放链接。生成前后配置不一致返回冲突；结果只代表此次查询时刻，不保证随后媒体不会变更。
- 播放 URL 支持 Emby、Jellyfin 和 Plex、服务器路径前缀及 play_host；只允许普通 HTTP(S) UI 链接，不携带媒体服务器 API key/token、不自动播放、不返回受保护媒体流。用户另行点击链接并使用媒体服务器自身登录。非法主机凭据/查询片段或非法 item ID 被拒绝。

## API 与兼容入口

所有元数据 API 都是登录后只读请求。本批回归发现旧 HTTP 订阅写入口只验证登录、未验证“订阅管理”角色，现已在统一 HTTP 边界补齐现代订阅写路由和旧 add/delete/redo/search 等写路由的当前账户权限检查；撤销权限后的后续写请求即使持有旧令牌也会被拒绝，内部已授权 worker 不借此获得新的权限。每项失败返回受控错误，不代理 Flask，不在错误中回显上游凭据。

| 路由 | 行为 |
| --- | --- |
| `GET /api/v1/media/details/{movie|tv}/{id}` | 原生完整详情、演职人员、季、原订阅及展示快照；DB/BG 身份会解析成 canonical TMDB ID |
| `GET /api/v1/media/details/tv/{id}/seasons/{season}?page=1` | 已解析 TMDB TV 身份的指定季/集、真实集号与有界分页 |
| `GET /api/v1/media/details/{movie|tv}/{id}/related/{similar|recommendations}?page=1` | 相似媒体/同类推荐，正确保留 TV 类型与当前页，附加只读缓存标记 |
| `GET /api/v1/media/details/{movie|tv}/{id}/playback` | 明确点击后实时核实并生成安全 UI 入口，不修改播放或服务器状态 |
| `POST /api/v1/media/detail` | 兼容旧 form type / tmdbid；保留旧基础字段、fact 字典、前 6 位 crews、actors/profile 和季字段，增加明确缓存/订阅未知标记 |
| `POST /api/v1/media/similar`、`/api/v1/media/recommendations` | 兼容旧 form type / tmdbid / page，业务读取直接在 Go 执行 |
| `GET/POST /media_detail?type=TV&id=...` | 仅将合法旧详情链接 303 重定向到相对 React 详情路径，不公开元数据、不请求上游；React 页面另行要求登录 |

旧详情结果的 item_url 不再由陈旧缓存 ID 自动拼接，现代页面使用独立实时播放入口。这是明确的证据边界，不宣称旧页面会自动获得当前播放证据。旧 WebAction/Jinja 代码尚未最终删除；演员搜索/作品页、字幕、旧 start/SSE 及插件详情使用方等独立业务不包含在本模块。

## React 状态与错误

支持 `/media/movie/{id}` 与 `/media/tv/{id}` 深链，DB/BG 源选择器安全编码；旧链接规范化 ID 后跳转。导航、会话变化及切换季/分页会取消旧只读请求，旧结果不能覆盖新页面。只有明确确认才发起订阅；订阅响应不确定时提示只读刷新/查看记录，不自动再提交。播放 URL 还会在前端核对身份、liveVerified 及 HTTP(S) 安全性。

演职人员单项失败时保留已验证的其余详情并显示警告；季集或相关媒体失败单独呈现，不伪造空成功。缓存不可用不阻止查看 TMDB 内容，订阅记录不可核实时明确提示；新流程不改变实时下载查重、PT 约束或后台任务授权。
