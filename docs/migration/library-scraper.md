# 已有媒体库手动刮削

2026-10-20：在原生入库刮削之外，接入已有媒体库的只读扫描、一次人工审核执行、三种模式、逐文件回执和单个元数据恢复。沿用 `UserScraperConf` 的生成选项、TMDB/Fanart 图片、中文演职员与固定只读视频句柄的 FFmpeg 缺图回退；手动任务不依赖 `media.nfo_poster` 开关。

此手动批次不包含 `LibraryScraper` 插件全部功能。后续已接入 cron、onlyonce、安装／卸载及事件／旧 Ajax 触发，具体接管协议和验证边界见 [媒体库刮削插件](library-scraper-plugin.md)；旧 Python 暂不删除。

后续已有库蓝光支持已接通三模式、四种本地入库布局、整盘冻结、明确扩大审核、TV 季元数据与链接对象备份／恢复，见 [蓝光整盘媒体库刮削](bluray-library-scraper.md)。下文保留最初普通媒体文件批次的验证记录，不代表蓝光仍一律未迁移。

## 审核与执行范围

仅管理员、纯 Go 模式可用。React 整理页新增独立“已有媒体库手动刮削”，不在浏览器传入任意绝对路径。可选择配置中的电影、电视剧或动漫库，以及库内相对目录／一个媒体文件；排除项按完整路径边界匹配，不用表达式或不安全字符串前缀。剧集沿用 `剧/季/集` 布局，共享剧元数据在视频目录的上一级，始终受选定媒体库根限制；预览和页面明确说明共享范围。

扫描最多 50,000 个媒体文件、1,000,000 个访问对象、64 层目录和 128 个排除项。超过限制拒绝整次审核，不把截断扫描当全量成功；超过 1,000 个媒体的扫描有单独回归。忽略隐藏目录、私有备份、NAS 回收／索引目录；不跟随目录符号链接。媒体软链接只允许直接指向当前配置的媒体库、下载或同步来源中的普通文件；链式、越界、无效或不可读链接作为 blocked 行固定在工作清单。

审核指纹绑定配置全快照、刮削选项、根及来源的真实路径与身份、相对范围、排除规则、所有媒体节点版本和请求代次。提交时重扫并比较全部文件，页面只展示前 200 个样本；保存后只处理冻结清单，不重扫扩大到后来新增的文件。执行期间再次检查当前来源授权，撤销下载／同步来源不能继续读取原授权的软链接目标。

每份新审核生成独立请求代次；同一代次丢失响应后可查到同一个任务，不重复提交，新审核才能表达一次新的运行意图。页面对失败请求不自动重发，要求只读刷新。

## 三种模式

| 模式 | 已有 NFO | 已有图片 | 身份来源 |
| --- | --- | --- | --- |
| `no_force` | 保留；电影已有 `movie.nfo` 也不生成重复文件 NFO | 保留，不下载／解码已有图 | 优先 `movie.nfo`、同名 NFO／`tvshow.nfo` 的明确 TMDB ID，否则按名称识别 |
| `force_nfo` | 替换所选 NFO，原文件保留备份 | 保留 | 忽略旧 NFO ID，按名称重新识别并核验在线详情 |
| `force_all` | 替换所选 NFO，原文件保留备份 | 替换所选图片，原文件保留备份 | 同上 |

缺失的所选元数据均可创建。没有选中项目、元数据缺失、错误图片或身份冲突明确返回 blocked/partial，不冒充完成。已有文件的 preserved 仅指“不改动”，不承诺其内容正确。

NFO 只接受预期 `movie`／`tvshow` XML 根下的直接 `tmdbid` 或 `uniqueid type="tmdb"`；拒绝 DTD、外部实体、嵌套 ID、矛盾 ID、非规范数字、错误根和截断 XML。损坏或不安全的现有 NFO 阻止该文件，不静默换身份写入。电影不会把默认／IMDb ID 误当 TMDB ID，演员内部 ID 也不参与媒体识别。

## 发布、备份和互斥

媒体只是单独记录的只读来源，不伪造“已完成入库任务”，不移动／删除视频，不新增转移历史或字幕入库事件。文件读取固定描述符，前后检查媒体及来源版本；所有输出都经过原有 NFO／图片文件名和目录白名单。

每份输出先建立本进程用户所有的 0700 私有目录 `.nastool-library-*` 和独立载荷，在写入字节前提交身份／摘要／目标和 writing 意图。新文件以防覆盖方式发布；覆盖使用 Linux `RENAME_EXCHANGE` 或 macOS `RENAME_SWAP` 交换节点，不截断已有文件，也不修改其其他硬链接。被交换出的原文件留在私有目录中。系统／挂载不支持原子操作时拒绝，不回退覆盖式重命名。

所有手动刮削和恢复共用数据库目录内的跨进程发布锁。未确定结果的目标另有持久占用，绑定真实父目录身份和保守归一化文件名，不能通过重叠媒体库根、路径别名或大小写绕过。大小写敏感文件系统中的少数不同名对象可能因此被保守阻止。共享的剧／季输出在同一任务中只生成一次；后续文件须核验相同媒体身份和已发布凭证，不能把两个不同身份的同目录海报互相覆盖。

文件交换后同步目录并核对目标新节点、内容摘要及原文件备份。中断或回执不确定保留证据和占用，不自动重新下载、解码或执行写入。目录／空载荷创建与首次数据库入账并非一个原子操作，崩溃可能留下未入账对象；不按名字接管或清除未知暂存。

## 回执、取消和恢复

新增 `GO_LIBRARY_SCRAPE_JOBS`、`ITEMS`、`OUTPUTS` 和 `CLAIMS` 表（均带 `GO_LIBRARY_SCRAPE_` 前缀），只读查询不创建这些表。任务／输出意图和状态使用事务及回读核验；失效意图不发布，丢失完成回执保留原 writing。响应隐藏原始配置、源／备份凭证、私有目录名和摘要。

纯 Go 生产 worker 每 15 秒检查 ready；handler-only 嵌入方式不自动启动 worker。任务和每个媒体都在开始前持久化 running。崩溃遗留的 running、partial、blocked、needs_review 或 cancelled 不自动续跑。停止请求不等网络操作完成即可保存 cancelled，后续发布检查停止状态；已生成的文件与备份保留。不确定占用不随取消而释放。

媒体回执和输出分别每页 100 条，任务列表最多 50 条、未完成优先。恢复前先停止 ready/running 任务，然后只读核对某一输出，另行确认旧执行器确已停止：

- `reconcile`：只验证目标、暂存／备份身份、目录和内容，补记 created/replaced/not_published，不写文件、不重跑任务。无法确证时保留占用。已入账但未发布的暂存也不自动清除。
- `restore`：只对有原文件备份的输出，在当前目标仍是该任务生成内容时，先持久化 restore_running／占用，再交换回原文件。替换文件继续留在私有备份中；后来编辑的文件、陌生对象或错误备份均拒绝覆盖。交换成功但回执丢失时，明确再次恢复可核实“原文件已在位”并补交同一恢复回执，不会再交换一次。

备份占用磁盘，没有自动过期／批量清理入口；不要凭目录名称批量删除。根目录已从配置移除或证据损坏时不自动恢复，需要人工核查并保留现场。恢复是元数据的单文件操作，不回滚入库、不删除媒体、不重新识别和联网。

## 验证与剩余工作

临时文件、SQLite 和模拟 HTTP 覆盖三模式、旧 NFO 身份选择／强制忽略、共享剧季输出、固定只读缩略图、授权及陈旧审核、越界软链接、根／来源变化、晚到文件、交换备份与硬链接、意图／完成回执失败、占用别名、取消／重启不重放、只读核对和恢复回执丢失。

前端覆盖只读请求、分页、独立覆盖／停止旧执行器／取消／恢复授权、错误或跨任务响应拒绝，以及丢失响应不重试。

集中结果：后端全量测试通过（HTTP 84.569 秒、整理模块 5.216 秒），`go vet ./...` 和 Linux amd64 静态构建通过。相关整理／NFO／入库／手动刮削竞态测试通过，HTTP 31.647 秒；前端 142 项测试全部通过，TypeScript 检查及生产构建通过。主包约 551 kB，既有超 500 kB 提示未阻止构建。

本批未操作真实 NAS、真实账户或生产目录。Docker 服务在此前检查中不可用，Go-only 镜像实际构建、启动与健康检查仍未验收；原有前端主包超过 500 kB 的构建提示继续存在。插件调度与旧入口、蓝光／远程和其余业务仍须迁移，360 个 Python 源文件继续保留，整体迁移仍粗估 50–60%，不能据此宣布 Python 已退出。
