# 已有媒体库蓝光整盘刮削（2026-10-20）

在 [整盘入库](bluray-intake.md) 和 [媒体库刮削插件](library-scraper-plugin.md) 之后，已有库的蓝光目录现作为一个只读媒体对象进入原生手动、cron、仅运行一次、旧 Ajax 和专用事件任务。支持复制、硬链接、逐文件软链接及移动形成的本地目录，不把 `BDMV/STREAM` 的片段当作多部影片，也不通过虚造已完成入库任务取得写入权限。

## 整盘清单与范围

布局须包含 `BDMV/index.bdmv`、真实 `BDMV/STREAM` 目录和至少一个 `.m2ts`；编号的 `Disc1`／`Disk2`／`BD1`／`CD1` 等卷可合并审核。目录布局只证明可处理，不证明光盘二进制有效、可播放或下载完整。缺少布局或不安全来源不会退回逐片段刮削。

每个对象固定整盘根和父目录身份、关键子目录及每个非元数据叶子的节点版本。软链接还固定链接自身、原指向，以及当前已配置来源或媒体库内的普通输入文件版本。目录链接、链式／越界链接、特殊节点、未完成后缀和内部私有暂存名不能成为媒体来源；不跟随路径中的目录链接或系统别名来扩大授权。原生入库生成的软链接使用已规范化的配置根。

读取媒体库清单只核对节点版本，不为一次元数据任务重新读完全部影片计算 SHA，也不改变原媒体字节、链接指向、目录结构、权限或修改时间。真正入库的逐文件 SHA 凭证不被这份库内清单冒充或替代。

选择整盘根可直接审核；选择内部文件或目录时，必须另传 `allowDiscExpansion:true` 才能扩大到整盘，React 提供独立复选框并展示新范围。改变库或选择路径会清除该同意。即使允许扩大，也须以包含完整清单的新指纹再次确认任务；新增文件、链接重指向或目录替换会使旧审核失效。排除规则命中整盘祖先或任一内部节点时跳过整盘，不生成残缺工作项。

配置根本身可以是整盘，电影元数据只能写在根内；不能借此向根外的节目目录写文件。配置根若直接指向 `BDMV`／`BDMV/STREAM` 片段目录则拒绝。每盘最多 20,000 个访问节点、64 层和 16 MiB 私有清单；单个任务以及定时全部根合计最多 50,000 个媒体对象、64 MiB 清单，超限不截断为成功。公开预览／分页回执只含文件数、子目录数、扩展标志和摘要，不回显逐节点凭证、输入根或私有备份路径。

## 三种模式与元数据位置

继续使用现有 `UserScraperConf`、身份核验和生成器。电影使用完整目录名作为文件名主干（不按点号截断），NFO／图片只写在整盘根。`no_force` 优先读取该目录内 `movie.nfo` 或同名 NFO 的明确 TMDB ID，已有元数据保留；`force_nfo` 忽略旧 NFO ID、仅重写所选 NFO；`force_all` 重写所选 NFO 和图片。缺失项目可按选项创建，错误或冲突不冒充完成。

TV／动漫必须有明确、在线核实存在的季号；不能凭蓝光片段文件名猜第几集或默认第一季。可生成节目及季 NFO／图片，但不解码任意片段、不生成伪逐集 NFO／缩略图。选项要求逐集项目而无法建立映射时明确记录 partial；没有可靠季号则阻止写入。

整盘根的白名单 NFO／图片和私有元数据备份不属于冻结的蓝光载荷，因此本任务新增元数据、保留的备份或下一周期重刮不会使自身载荷凭证失效。其他文件和子目录继续冻结；名为 `poster.png` 的目录不会被当作可变图片忽略。未知私有对象只跳过、不接管、不清理。

## 软链接元数据、覆盖和恢复

仅补缺失时读取 NFO 链接，仍要求其直接指向已配置、已固定的普通文件；读取前后检查链接、输入文件和整盘版本。越界或不安全 NFO 不用于身份识别。已有图片的 preserved 仅表示保留，不承诺验证过内容。

强制模式遇到整盘元数据链接时，交换的是链接对象，不跟随链接截断来源；旧链接原文和身份存入私有输出凭证。原文件或链接留在 0700 私有备份中。硬链接元数据同样通过交换单个目录项替换，不改其其他链接共享的原字节。

继续使用 writing 意图、原子交换／防覆盖发布、父目录和私有节点身份、摘要及持久目标占用。只读核对不重新发布；单文件恢复须独立审核与确认，只在当前目标仍是本任务的新文件且备份仍是原对象时交换回去。恢复原链接不读取或修改其目标，也不授予读取越界目标的权限。恢复回执丢失可明确核实已恢复状态，不再交换一次。后来改动、额外对象和不确定凭证保留待核查，不自动清除。

## 后台与兼容入口

手动、插件 cron／onlyonce 和 `/do` 的 `media_path_scrap`、`media.scrap.start` 专用事件共用上述扫描／冻结清单和任务执行。旧触发选择内部路径时也须传相同的 `allowDiscExpansion` 并保持到确认提交；旧客户端仅传路径不会静默获得整盘强制覆盖权限。

每次周期重新冻结新清单；已保存的任务不会扩大到后来新增载荷。配置／来源撤权、取消、中断、丢失意图或结果回执均沿用原有保留证据、不自动重跑规则。独立库内刮削不新增 `TRANSFER_HISTORY`、字幕事件、整理任务或入库历史。

## 验证与剩余范围

临时真实目录、SQLite、模拟元数据／图片服务覆盖四种入库布局与三模式组合、整盘／多卷／配置根、明确扩大及排除、只读载荷变化、NFO 软链接、备份与恢复、私有大清单、一次性／cron 再次运行、旧 Ajax／事件、来源撤权、取消、中断和重启不重放。前端验证扩展权限原样传递、跨范围／错误摘要拒绝，以及公开任务回执；没有操作真实 NAS、账户或生产目录。

集中验证通过：后端全量测试（HTTP 111.936 秒、整理内核 20.816 秒）、整理／字幕／刮削内核竞态检查（整理 30.015 秒）、相关接口竞态检查（HTTP 107.208 秒）、`go vet ./...` 和 Linux amd64 无 CGO 静态构建。前端 154 项测试、TypeScript 检查和生产构建通过；主包约 556.39 kB，既有超过 500 kB 的构建警告仍在。

Docker daemon 当前不可用，Go-only 镜像的实际构建、启动及健康检查仍未验收；真实 NAS／浏览器、大盘性能、远程整理、未知无凭证对象人工处置及其他保留业务仍在完整目标内。退出检查仍为 360 个 Python 源文件、8 处 Go legacy 调用计数（含 helper）、74 处 proxy/runtime 引用和 45 处容器 Python 引用。整体迁移仍粗估 50–60%，不能把本模块完成当作 Python 完全退出。
