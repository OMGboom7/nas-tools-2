# 剩余功能：迁移与删除决策

核查日期：2026-10-07。业务代码基线：`4a567d5`。本清单是后续实施决策，不是功能已经完成或删除的声明。

## 决策原则

- 保留完成“发现资源 → 订阅 → 下载 → 整理入库 → 通知”的核心闭环，迁移到 Go；不能用删除整理、同步等核心业务来冒充完成迁移。
- 先实现并验收替代能力，再删除旧 Python 实现；不同时保留两个能够下种、移动文件或删种的后台执行器。
- 可选功能逐项确认。没有真实使用情况、安装配置和用户选择的证据，不自动删除功能、安装记录、账户、历史或媒体文件。
- 删除 Python 的实现不等于删除业务功能。旧页面、插件加载机制、运行时自更新脚本属于技术实现；通知、同步、刮削、备份等属于用户能力，分别决策。
- 没有 React 入口、测试返回 501、目录里存在插件名称，都不能分别证明“不需要功能”“迁移完成”或“插件已经迁移”。

## 功能清单与建议

| 模块 / 功能 | 当前证据与缺口 | 建议 | 删除影响 / 验收条件 |
| --- | --- | --- | --- |
| 认证、配置、数据库升级 | Go 认证、原生配置存储和数据库备份已存在；仍需覆盖完整升级与恢复流程 | 保留并收尾 | 必须兼容已有账户、未知配置字段和存量数据库，不要求重新配置 |
| 元数据、名称解析、站点与搜索 | Go 已有 TMDB、库存、词表、索引器与过滤执行；完整命名和真实站点兼容仍有缺口 | 保留并迁移缺口 | 媒体身份、集号、文件路径不能靠猜测；旧搜索缓存迁移/失效策略须明确 |
| 精确订阅、自定义 RSS、下载提交 | Go 已有搜索/扫描 worker、持久预留、提交事务和 qB/Transmission 手动正向核实 | 保留并收尾 | 旧无证据待核实记录、后台核实、完整事件链未完成；不得自动释放不确定提交 |
| 模糊订阅、洗版、跨季 | 保存部分配置不等于执行支持；原生规划对模糊/洗版仍明确拒绝 | 保留建议；是否精简需确认 | 删除会改变现有订阅行为；须展示受影响订阅，不能默默按精确订阅执行 |
| PT 最低做种、分享率与 HR 策略 | Go 已解析部分指标，但订阅执行仍拒绝正值最低做种策略；HR 等详情规则存在未支持分支 | 保留并迁移，高优先级 | 这些是下载/删种的安全约束，不应作为普通“可选优化”直接移除；不支持时继续拒绝执行 |
| 手动整理、重命名、未识别文件处理 | `app/filetransfer.py` 仍负责实际文件转移；Go 的 `transfer_history.go` 只接管历史读取/统计 | 保留并迁移，下一核心模块 | 删除会失去下载后的入库闭环；需核验复制/移动/硬链接/软链接、字幕、蓝光目录、冲突与失败恢复 |
| 目录同步与文件监控 | `app/sync.py` 仍有文件事件、目录配置、队列与转移逻辑；旧 scheduler 调用转移队列 | 保留并迁移，依赖整理引擎 | 配置读写不是同步执行；需防止源/目标循环、半写文件、重复事件与并发覆盖 |
| 下载完成监控和自动整理 | 下载任务读取/控制已 Go；服务配置仍保留 transfer/路径映射等字段，不代表自动整理已实现 | 保留并迁移，依赖整理引擎 | 需读取实际完成状态、核对来源、尊重 only_nastool/路径映射并持久防重；不能把“下载器收到”当作“文件完成” |
| 媒体库同步、播放记录与缓存 | Go 已有媒体服务器读接口和库存适配器；旧 scheduler 仍调度媒体库同步 | 保留并迁移必要部分 | 读取服务器接口不能证明本地缓存同步已迁移；须明确缓存失效、完整/增量同步与取消 |
| 消息通道、业务通知、事件系统 | Go 已有多数通道、测试与自定义发送；旧 `message.py` 仍有下载/整理/订阅等业务消息，旧插件事件管理器仍在 | 保留并迁移 | 需要业务提交后的可靠事件与发送策略；消息失败不得回滚已接收下载，也不能因重试重新下种 |
| Webhook 自定义 JSON / Jinja、列表消息 | 普通 Webhook 已 Go；非空 json_tpl 仍被拒绝，旧实现还含 json_list_tpl 与列表变量 | 可选，待确认后迁移或取消模板能力 | 不应为全部用户引入完整模板引擎而未确认需求；保留时须支持使用中的模板，并限制文件加载、循环、输出和泄密。取消时保留普通 Webhook，报告受影响配置 |
| qBittorrent、Transmission、Aria2、115 | 已有 Go 客户端，能力覆盖不相同；115/Aria2 待核实恢复和真实服务联调仍有缺口 | 保留并补齐实际使用的能力 | 不将活动列表、控制、添加与核实统称为“全部完成”；切换默认下载器不应错误核实旧提交 |
| PikPak 等尚未原生支持的云下载器 | 下载器连接测试仍有旧接口分支；不能由 qB/Transmission 的测试证明云下载器可用 | 可选，待确认 | 删除会失去对应账户的下载能力；若不用，移除选择入口和调用链但保留/导出配置，不默默切换到本地下载器 |
| 刷流与自动删种 | `app/brushtask.py` 和相关插件仍执行 RSS、任务限制和删除策略，旧 REST 仍有 brushtask/torrentremover 领域 | 可选，待确认；保留则独立迁移 | 涉及真实任务、文件和 PT 信誉；即使决定取消，也只停用服务与入口，不为清理迁移主动删除下载器任务或文件 |

| React 未覆盖的业务与设置页面 | 当前 App 有搜索、下载、探索、订阅、站点、服务、通知和插件页面；整理/同步等闭环入口仍需补齐 | 为保留的业务补 React 页面 | 原生 REST 可用不代表用户流程可用；验收权限、编辑、进度、错误与刷新后状态，再删除对应旧页面 |
| Python/Jinja 旧界面、Flask 代理、Python 插件加载器 | 当前生产仍有旧实现；剩余显式旧接口调用 13 处 | 替代完成后删除技术实现 | 不是提前删除未迁移业务；逐项证明无调用、无后台执行、无存量数据依赖 |
| 容器、s6、Python 启动和运行时自更新 | 生产 Docker/s6 仍含 Python；已有 go-only 候选，不等于生产切换验收 | 最终替换并删除旧链路 | 生产健康检查、存量挂载、权限、停止/启动和回滚完成后，移除 pip/requirements/run.py/Python 服务；运行时拉取旧 Python 的更新脚本应取消或改为发布镜像升级 |
| 动态登录壁纸、辅助缓存维护等旧定时任务 | 旧 scheduler 仍有壁纸刷新、元数据保存/清理等任务；业务用途不相同 | 壁纸刷新可列为精简候选；核心缓存维护按实际需求重做 | 不机械复制整个 Python scheduler；每项任务列出保存对象、触发器和调用者，再决定删除或迁移 |

## 下一步顺序

1. 先取得可选功能的保留范围；未收到选择时，默认保留，不删除。Webhook 模板只完成调研，未添加 Go 依赖、未改消息逻辑。
2. 下一核心实施批次优先整理引擎：先建立只读文件扫描与整理预览、媒体身份核验、目标路径/冲突报告及对应 React 入口，再实现有持久防重和错误恢复的实际文件操作。预览只是安全的第一步，不能代替整理执行完成标准。
3. 基于同一整理引擎迁移手动整理、未识别记录处理、目录监控队列、下载完成监控；保留现有目录及历史数据，补复制/移动/链接等模式，不通过另起空数据库绕过升级。
4. 接入业务事件与通知，再补媒体库同步、必要插件及用户选择保留的云下载器/刷流/模板能力。PT 安全约束是上线前门槛，不能为了开放整理或下载而略过。
5. 每个保留模块完成 Go API、后台执行、React 流程和兼容数据验收；每个取消模块完成影响清单、用户确认、入口/调度/调用链移除与配置导出策略。
6. 最后实际构建并运行无 Python 生产镜像，完成存量升级、关键流程和回滚验收，再删除旧 Python 文件、依赖、Flask 代理与启动服务，执行退出强制门禁。

## 进度与证据

当前退出检查：360 个 Python 文件、13 处 Go 显式旧接口调用、75 处旧代理/运行时引用、45 处容器 Python 引用。检查程序使用原来的统计口径，数字不是业务迁移完成率。

整体仍粗估约 50–60%，不因本次清单编写提高完成率。整理/同步、业务事件与完整生产切换是明显的大块缺口；可选功能是否保留会改变剩余工作量，在选择前不承诺精确比例或时间。即使取消一些功能，也必须明确产品范围已变化，不能算作那些功能已迁移。

核查依据：`backend/internal/httpserver/server.go`（Go 路由/启动）、`subscription_search_plan.go`/`subscription_search_run.go`（执行拒绝条件）、`transfer_history.go`（只读历史）、`notification_delivery.go`（模板缺口）、`downloader_test_api.go`（云下载器兜底）、`plugin_metadata_config.go`/`plugin_catalog.go`/`plugins.go`（原生插件边界）、`frontend/src/App.tsx`（现有页面），以及 `web/apiv1.py`、`app/filetransfer.py`、`app/sync.py`、`app/scheduler.py`、`app/message/message.py`、`app/message/client/webhook.py`、`app/plugins/event_manager.py`、`app/brushtask.py` 和旧插件目录。具体安全与最终退出要求继续以 [Python 退出计划](python-exit.md) 为准。
