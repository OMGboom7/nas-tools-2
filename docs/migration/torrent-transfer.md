# 自动转移做种（TorrentTransfer）实施状态

目标为保留原 TorrentTransfer 的下载器选择、排除标签／目录、路径转换、源种子文件与 qBittorrent fastresume Tracker 补充、暂停添加、校验、可选启动、保留文件的源任务移除、原转种历史、一次／周期和通知，并接入 Go 持久回执与 React。

2026-11-06 第一阶段已新增独立核心，尚未接入生产调用者：

- `torrentmeta.PrepareTransfer` 复用现有完整文件清单解析，只修复外层缺失的 Tracker 字段，优先沿用种子自己的 announce-list，再读取匹配原 info 的 fastresume；原始 info 字节不重新编码。未知外层字段原样保留，已存在的 announce 不用另一个 resume 改写。公共无 Tracker 种子保留 DHT 行为，私有种子缺少原 Tracker 证据时不猜测接收方。
- `torrenttransfer` 读取原设置并保留未知 JSON 与大整数，源／目标编号不经浮点数。保留原排除语义（qB 标签包含匹配、Transmission 完整标签、目录前缀）；目录映射按完整组件；远端目录格式支持 POSIX、盘符和 UNC，阻止越界与文字前缀相撞。
- 元数据目录使用只读根句柄，绑定规范路径及文件系统身份；只读内容与源任务完整哈希匹配的 `.torrent`。可显式使用原协议给出的种子文件名，但不能借此读取其他文件类型。读取前后复核目录、文件类型、身份、长度、时间和内容摘要；拒绝源文件符号链接、根目录替换和原别名重定向。
- Tracker URI 和原始种子内容只留在私有内存字段，不进入普通 JSON 进度。没有写回原种子、创建替代种子文件或操作媒体文件。

已编写覆盖 info 字节与哈希、v1／v2／混合元数据、私有字段不进入进度、已有 Tracker、错误 resume、公网 DHT、精确编号、旧目录前缀／两类标签过滤、只读与复核、路径逃逸／符号链接／根替换／取消的回归夹具。遵照用户要求，行为用例待整个模块调用链完成后集中运行；本阶段仅进行编译和静态检查，不能据此声称这些行为用例通过。

后续仍需接入源／目标协议、下载器版本和 v2 任务标识核验、暂停添加、校验／启动、源任务保留文件移除、跨周期动作账本、PT 与范围保护、原历史／通知，以及 React 审核、停止和未知结果查询。可解析 v2 元数据不表示任意目标下载器支持 v2；缩短的 v2 任务标识也不能未经协议核对就当作完整哈希。

本阶段没有启用新后台、发送种子或启动／移除任务，原 Python 插件仍保留。完整计划见 [实施计划](../superpowers/plans/2026-11-06-torrent-transfer.md)。

## 第二阶段：协议适配层

2026-11-09 已编写 qB／Transmission 的独立暂停添加、任务快照、校验和启动方法；尚未接入生产调用者或后台。仅进行编译与静态检查，新增及第一阶段行为夹具仍待整模块接通后集中运行。

- qB 读取应用、API 和实际 libtorrent 版本，按版本选择暂停字段及原目录布局；旧无文件索引 API 使用完整未筛选数组位置，新 API 缺失索引则拒绝。完整 v1／v2 哈希单独保存；libtorrent 2 的纯 v2 和混合任务使用经协议核对的截短控制编号，随后仍要求 properties 的完整身份。依据 [qB 5 添加／properties 源码](https://github.com/qbittorrent/qBittorrent/blob/release-5.0.0/src/webui/api/torrentscontroller.cpp)、[qB 编号转换](https://github.com/qbittorrent/qBittorrent/blob/release-5.0.0/src/base/bittorrent/infohash.cpp) 和 [libtorrent get_best](https://github.com/arvidn/libtorrent/blob/v2.0.11/include/libtorrent/info_hash.hpp)。
- Transmission 保留旧 RPC 与 JSON-RPC 协商，只在明确的 CSRF 409 后重发；核对回执编号，区分新添加／重复，错误或未知响应不自动再发。目标需要原标签能力（RPC 16+），当前 SHA1 身份协议不发送纯 v2；混合种子沿用原 v1 身份。依据 [官方 RPC](https://github.com/transmission/transmission/blob/main/docs/rpc-spec.md)。
- 快照绑定任务创建时间、完整身份、目录、原始 qB 标签／TR 标签和逐文件清单／完成量。qB 用两次相同任务读取夹住 properties／文件读取。校验中可读取，但不作为全部完整；聚合进度为 100% 不能代替每个实际文件的证据。私有种子启动前另行核对既有 PT 做种限制，不在启动调用中自动改限制。
- 元数据读取可使用协议提供的原种子文件名，仅取审核根内的文件；resume 沿用同一原 basename。libtorrent 2 缺失协议的全零 resume 哈希不作为身份，至少一个实际可用协议必须匹配。混合种子只有一个真实文件时，也核对原 v1 文件目录，不能仅凭文件数丢弃原根目录。

添加回执不是任务归属许可，校验调用成功也不是校验周期已经结束。后续持久执行器仍须分别记录意图、冻结实际新增任务、观察本次校验状态，处理丢失应答／重启、外部并发写入、独立启动与源任务移除授权；不能凭一张完整快照直接消费旧未知动作。源任务删除仍未接入。真实下载器版本、v2／混合文件布局、浏览器和候选镜像均尚未验收。

2026-11-25 已加入独立 SQLite 动作记录。每个接收端、任务控制编号、创建时间和动作只允许一个调用者取得发送资格。暂停添加使用创建时间零，校验、启动和移除源任务绑定实际创建时间。动作发送前提交原回执编号和计划摘要，重复调度可取回原记录。已有未知结果保持占用；协议应答只记录动作结果。重启防重夹具已编写，留待模块集中测试。执行器尚需接入该记录、保存完整计划及处理只读核对。

目标任务阶段已接入暂停添加的原回执。绑定时需要调用者核对任务归属，冻结下载器任务、创建时间、目录、标签和文件清单；后续按原授权和内容摘要取回。执行器分次观察校验中、暂停且所有有效文件完成，之后按独立启动许可及当前 Tracker 状态决定是否发送启动。重复查询读取原动作回执。上述逻辑与协议适配层已编译并通过相关静态检查；行为夹具留待模块接通后集中运行。生产调用者仍需提供归属证据、调度这些观察并处理未观察到校验周期的情况。源任务移除、历史、通知及 React 控制尚待接入。

源任务扫描已复用两个 Go 下载器的已完成任务列表，并逐项重读任务和种子文件。Transmission 沿用原插件的做种／等待做种条件，qB 保留已完成的暂停任务。排除标签和路径在读种子文件之前应用，目录映射区分 POSIX 根和 UNC 共享。复核会重新检查当前配置、下载器、任务创建时间、逐文件完成情况、原种子及元数据目录身份。后台调用者和集中行为验收仍待接入。

已将源任务复核与两个下载器的暂停提交连接到同一 Go 调用。每份审核计划按回执保存授权摘要、源任务、文件身份、目标端点摘要、目标控制编号和内容摘要。恢复时从原目录重读内容。协议即将发送时再次读取授权、配置、源任务与目标编号，再申请唯一发送资格。调度与 HTTP 尚需提供真实授权解析和生命周期入口；本阶段只完成编译与静态检查，行为夹具待整模块接通后运行。

已加入按原回执继续绑定目标和校验／启动的 Go 入口。首次绑定需要调用者核实任务归属；启动另查原范围、当前自动启动选项及该目标实例的启动许可。主管理员可通过 GET /api/v1/torrent-transfer/records/{id} 只读查询已保存计划的目标阶段和每个动作的回执状态。查询不创建账本，也不访问下载器。实际生产写入和调度仍待接通，已有行为夹具按整模块集中验收。

React 下载任务页已接入主管理员的回执查询。输入原编号可查看目标绑定／校验阶段、各动作的应答状态和更新时间。切换编号或离开页面会取消正在进行的查询。生产写入、调度以及 React 对执行动作的审核仍需接通；页面行为和接口夹具留待整模块集中验收。

目标任务首次确认归属时，Go 在绑定目标的同一 SQLite 事务中写入旧 PLUGIN_HISTORY 表。沿用源下载器编号与源任务哈希组成的键，目标下载器编号按整数精确写入，目标任务采用其实际协议编号。此时源任务仍保留，delete_source 记录为 false。遇到存量同键关系会保留原记录并回滚本次绑定。每份回执记录关联行号，供后续经核实的源任务移除更新；旧记录已被联动删除消费时，正常恢复不会重新插入。源移除后的状态更新和实际旧数据升级验收尚待完成。

源任务移除已接入独立 Go 执行方法。要求当前原配置启用源移除、目标为本次已核实的完整任务、独立授权及源任务实例一致。启用自动启动时还要求原启动已应答且目标处于做种状态。实际源适配器复用 PT 检查、任务锁、下载器配置保护及保留文件的协议调用。仅当本次动作已应答且从源下载器精确查询到任务不存在时，才把该回执关联的旧历史更新为已移除。歧义应答保留原动作，不自动重发。生产授权、后台调度、独立核对未知结果和集中验收仍待接通。

Go 独立模式的插件管理现可安装、卸载和编辑自动转移做种的原有 13 个设置。React 通用编辑器通过原生插件接口列出可用下载器、加载配置版本并保存修改。旧配置中的未知字段和整数精度继续保留，卸载保存安装名单变更并保留原配置。后台周期／一次调度尚未接通，运行状态保持未运行。插件配置回归夹具留待完整模块后执行。

主管理员可在 Go 独立模式的下载页生成转种审核计划。接口根据安装状态、原插件设置和两个启用下载器解析实际客户端，逐项读源任务／元数据、目标协议编号和目标任务是否存在，将候选按计划摘要持久保存。页面区分候选、已存在和核对失败，可按原编号查看回执。审核只读下载器；后续执行仍须把写入许可与调度接入生产入口。

下载任务页已提供单项暂停添加。主管理员确认任务、目标下载器和目录后，Go 按已保存的审核编号重读配置、源任务和元数据，在目标任务锁内通过原生协议提交。已占用的添加返回原回执及其应答状态，已存在的目标任务显示为重复。此操作仅覆盖添加阶段。生产校验／启动／源移除授权、后台调度和集中验收仍待完成。

React 回执页现可读取目标任务名称、控制编号、目录、创建时间与状态。主管理员审核并确认归属后，Go 按本次回执和实时快照绑定目标与历史。继续校验与启动分别进入独立的操作接口，启动还要求原设置允许自动启动、已观察校验完成及原任务实例匹配。真实生产调度和源移除的用户入口仍待接入，行为验收留到整模块完成后进行。

回执页现接入独立的源任务移除与已应答结果核实。操作前显示已审核的源下载器、原任务编号和目录；管理员确认保留文件后，原生执行器重新核对源实例、完整目标和 PT 要求。已应答的原动作可再次查询源任务是否消失并更新旧历史，结果未知的原动作仍留待核对。此批未连接真实下载器，行为用例留到整模块集中验收。

回执中的源移除动作在进程中断或应答丢失后也可单独核实。核实方法只接受已有的同一计划／源实例／目标实例的动作，在原下载器精确报告源编号不存在且目标仍匹配时，将首次观察时间和旧历史在同一事务保存。页面同时显示当时的协议应答与后来观察到的缺席时间。没有原移除动作、任务仍存在、目标已替换或协议读取失败，均不产生缺席证据。

主管理员可查看、启用或停止转种调度。启用时保存管理员、源／目标配置范围、时区和独立调度编号。单次开关与三秒后的触发时间同步写入；周期复用现有五段 cron 算法。Go 服务的后台轮询把到期触发和下一次时间在同一事务中保存，进程重启或并发轮询仍保留原待执行批次。配置变更／卸载撤销旧调度。本阶段的待执行批次尚需连接下载器执行与通知，不计作自动转种已完成。

到期批次已接入源扫描、计划冻结及目标暂停添加。后台在发送首项前持久保存整批回执清单，每项保存处理位置；重启按原清单和动作账本继续。下载器请求前复查调度编号、管理员及配置，停止或撤销后不能以旧批次继续发送。最近批次显示添加应答、已有、失败和待核实数量；GET /api/v1/torrent-transfer/batches/{id} 可查询该批次的原回执。后续目标绑定／校验、可选启动／源移除与结果通知仍需接入自动批次，已有手动入口保留。

启用原通知设置后，非空批次在完成暂停提交阶段时向现有业务通知队列写入一条汇总，包含原批次编号、已应答、已有、失败与待核实数。通知事件和调度完成状态共享事务及稳定的批次编号；仅向已启用自定义消息的渠道排队，按原投递回执处理。React 可按消息中的批次编号查询任务回执。本阶段通知反映提交结果；自动绑定、校验及后续执行仍待接入。
