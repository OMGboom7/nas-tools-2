# 模糊 RSS 订阅

2026-10-26：纯 Go 模式接通模糊 RSS 的逐规则授权、多媒体完整批次、下载器提交、明确恢复及 React 审核。精确订阅的洗版和完整跨季规划不是本模块，Python 退出条件仍未满足。

## 已核对的旧语义

- 旧搜索和元数据刷新任务跳过 fuzzy_match；模糊规则是 RSS 的关键词／正则、可选年份和电视剧季号匹配，不应拿规则名称去查一个固定 TMDB ID。
- 匹配文本是处理后资源名、识别名称及年份；忽略大小写的正则和原样字面包含互为命中条件。无效正则不降级为字面规则，S00／空季号为模糊季范围。质量、分辨率、制作组、包含／排除、站点范围和详情／PT 约束仍生效。
- 不执行精确订阅的媒体库查重或缺失集数交集。一条规则可命中多个媒体，按名称／年份／季／集分组择优，不是只下载第一个电影。资源优先级、站点／做种排序和实际原下载设置须保留。
- 旧 RSS 先完成本批下载，再收尾订阅；普通模糊规则不是永久关键词监控。与洗版同时启用时仍走质量优先级更新，含明确单集的电视剧不冒充整季洗版完成。旧 batch_download 的模糊电视剧分支没有建立 need_tvs，实际会漏掉电视剧下载；新执行须在独立明确授权后支持完整种子，不能继承这个无意的空分支，也不伪称旧代码已有可靠的模糊 TV 执行。

## 整体实施约束

1. 保留原 RSS_MOVIES／RSS_TVS 数据及未知列；新增独立、默认关闭的逐规则授权。授权绑定当前管理员、完整原行、站点／下载器／下载设置／词表／过滤组／识别配置和详情规则目录；编辑、删除、重新创建同编号或重新授权不能接管旧批次。
2. 本机只读授权审核不访问站点或下载器。RSS 目标审核需要单独同意外部只读访问；展示全部最终候选、择优及整种子范围，不向浏览器返回下载 URL、Cookie 或账户凭据。没有 TMDB ID 或密钥仍允许基于解析结果匹配，不将模糊规则强制当作精确订阅。
3. 稳定请求编号在保存前保留。重复保存只返回原批次；一个规则只能有一个未关闭批次。新 pending 批次可由 worker 领取，running／intent／uncertain 不按重启或超时抢占。旧 RSS 周期不直接授予新模糊执行权限。
4. 每项请求意图与既有跨 RSS／订阅的原生提交占用同事务；复用真实下载器设置、PT 接管和正向核实，不改变原未知义务保护。批次保存完整不可变范围，逐项回执和下载事件同事务。全部已接受后才按本轮语义完成／保留原订阅；不在第一项成功后提前删除来源。
5. 原始源行、相关缺失集账本及每次提交尝试保留私有审计，NULL／BLOB／整数／实数不靠字符串替代。成功收尾、历史、源行变化、授权推进／撤销及批次回执同事务。停止只阻止后续请求，已在下载器中的任务不撤回、不删文件。
6. 响应不确定只允许对原账户／hash／原占用的正向只读核实；不因未找到而释放或重下。核实回执后也不自动继续，须新审核及明确确认。仅明确证明尚未调用添加接口的拒绝可在新确认下重试，旧尝试保留；未知意图永不回退 pending。
7. React 接通逐规则授权、完整候选审核、保存、按稳定编号查询、停止及核实／后续续办；页面重载与错误不自动重发。旧立即搜索不被偷换成批量模糊下种。
8. 模块整体实现后再集中验证匹配／多媒体择优／电影与电视剧／洗版组合、事务失败、配置变化、重复请求、未知回执／停止／重启、权限及混合模式无 Python 回退；再运行相关竞态、前端、静态构建与适当范围的整体回归，并提交推送。

## 原生入口与持久流程

- `GET /api/v1/fuzzy-subscriptions` 与逐规则 `GET /{MOV|TV}/{id}` 只读本地授权范围、下载目标及最近 30 条批次；已知较早编号通过 `GET /jobs/{id}` 查回。没有运行记录时不创建新控制表，不访问站点或下载器。
- 逐规则 `POST /authorize|revoke` 绑定本次本地范围审核。原来数据库的 FUZZY_MATCH、旧 RSS 周期或 Python 开关都不构成新的 Go 执行授权。新增、编辑、删除及恢复规则撤销原授权；相同数值 ID 或完全相同字段的复用也不能继承旧授权。
- `POST /preview` 单独同意外部只读读取，`POST /save` 使用完整审核指纹、稳定请求编号及三项独立确认。候选保存全部私有 URL／resolver；这些字段不走公共搜索资源的隐藏 JSON 投影，也不输出到浏览器。任何 URL 改变都改变审核指纹。
- 普通 RSS 扫描仅为有效授权规则建立 pending 批次，不在扫描请求内直接下种。纯 Go 生产实例每 10 秒领取最多 5 条新 pending；handler-only 不启动 worker，可明确执行原待办。running／intent／uncertain 不由重启、超时或新授权自动重抢。
- `POST /jobs/{id}/stop` 停止后续请求并暂停仍精确匹配的原规则授权；原下载器已接收的任务不可保证撤回，迟到回执仍保留。停止不会删除文件、下载器任务、媒体或旧回执。
- 原下载器及准确 hash 的 `POST /verify` 只采用正向接收证据。当前支持 qB／Transmission，不把其他下载器的未知结果伪装为可恢复。原账户／配置变化或未找到均保持占用；核实成功也不自动续办。`POST /review`、`POST /resume` 只在全量剩余目标已证明未提交／明确拒绝后，以新的独立确认继续；已接受项不重发。
- 全部已接受后，原行／TV 辅助账本、RSS_HISTORY、源行收尾、授权撤销或洗版优先级推进、rss_finished 事件与最终回执同事务。下载事件在每一项真实接收记账事务中提交，首项成功不提前关闭整批。
- `POST /jobs/{id}/restore` 按原行创建规则副本，保持全部已知／未知列、整数精度、REAL、NULL 和 BLOB，不覆盖当前规则。恢复请求编号在发送前保留，同编号只返回原恢复回执，原历史／批次保留，执行授权关闭。旧历史“重新订阅”对精确关联的模糊历史也恢复原正则，而非用正则去猜 TMDB；历史 ID 复用须核对全行摘要。

React 订阅卡片的“模糊 RSS 授权与回执”与精确立即搜索分开；逐规则未来授权和当前批次各有独立的三项确认状态，操作后全部清空。保存、恢复在请求前显示稳定编号；会话、规则切换及错误不接纳旧响应，也不自动重发。查回终态后更新来源列表并清空过期授权视图，不把已收尾规则继续显示为有效执行范围。
