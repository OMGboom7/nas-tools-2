# 下载任务联动删除（TorrentRemover）实施状态

完整目标为将原插件的源文件删除事件、下载历史、转种／同下载器辅种关系、配置生命周期和实际任务移除迁入 Go，配套 React 授权、停止、执行记录及未知结果核对。任务移除必须保留所有文件，并继续遵守现有 PT／做种保护。

2026-11-06 已完成第一阶段的独立核心包 `backend/internal/torrentremover/`：

- 读取原 `DOWNLOAD_HISTORY` 与 `PLUGIN_HISTORY`，冻结精确的下载器编号、任务编号、原记录行及未知 JSON；不经浮点数解析大编号，不按标题直接删除。
- 延续原转种后保留／移除源任务的关系，以及原插件只处理同下载器辅种记录的边界；组件级相对路径匹配排除越界和部分名称相撞。
- 为未来的新源文件删除事实定义范围快照、独立回执及逐任务状态。旧启用开关不会自行启动新执行器；已接收事件有稳定编号，远端写入前须保存意图。
- 定义领取、范围复核、父任务确认、未知结果、进程恢复及原历史条件更新。中断和未知意图不能回到可发送状态；关联历史仅在任务已确认移除后按完整旧快照处理，保留其他下载器及未知字段。

本阶段尚未接入业务事件事务、下载器客户端、生产 worker、插件页面或 React，也没有启用任何远端删除。此包的数据库方法只会在显式调用时生效；当前生产请求链路保持既有状态。原 Python 插件仍在，不能据此宣布模块完成或删除 Python。

已写入核心回归夹具，覆盖精确大编号、转种／同下载器辅种、稳定事件编号、未知结果与重启、范围撤销、条件历史更新和路径匹配。遵循用户要求，行为测试待整个模块调用链接通后集中运行；本阶段仅做 Go 编译和静态检查，不将未运行用例写作通过。
