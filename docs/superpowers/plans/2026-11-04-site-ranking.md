# 站点等级迁移实施计划

> 使用 Superpowers 实施计划和集中验收流程。在已有 React／Go 迁移分支完成整批后测试、提交、推送。

**目标** 将站点等级进度和旧统计页面的读取操作接入 Go 与 React。

**设计** 读取现有站点目录的 `user_ranking_info` 和已保存的站点统计快照，在 Go 内计算进度。React 的等级明细、旧 `/do` 排行和统计导出查询共用计算。用当前统计范围和站点地址限定查询，按地址优先匹配规则，保留旧名称匹配作为回退。

**依据** `app/sites/site_ranking.py`、`web/action.py`、`web/templates/site/statistics.html`、`web/backend/user.sites.bin` 和现有 Go 统计模块。

- [x] 在目录读取中保留等级规则。在 `sitestats` 迁移等级标准化、普通与特殊等级、保号、顺序和晋升条件，包括无映射、最高级和未配置。按目录顺序显示条件，使用本地时区计算注册时长。
- [x] 在 `httpserver` 用当前站点编号和保存的快照提供只读等级 API，接管 `/do` 的等级、统计列表、历史、活动和做种五个读取操作。API Key 统计入口复用同一投影。按地址计算历史增量，保持统计写入需要主管理员及确认。
- [x] 在 React 统计页显示当前与下一等级、保号、总体进度及各条件。旧 `/statistics` 地址向登录用户展示只读统计和明细，站点管理保留原刷新入口。使用可验证的 HTTP／HTTPS 规则链接。
- [x] 整批完成后集中验证。覆盖内置规则、旧数据库等级文本、同名站点、未知映射、旧查询与权限、前端生产构建及本机隔离页面。已核对退出指标。
